# 演示行动变化目标定义

## R — 原文 (Reading)

> "促使对方从A状态向B状态发生改变。"
>
> — 高杉尚孝，第一章

## I — 方法论骨架 (Interpretation)

演示不是播放材料，而是促成听众状态变化。  
先定义听众现在的 A 状态，再定义演示后希望达到的 B 状态，最后写清楚希望对方采取的下一步行动。  
只有行动目标清楚，故事、页面、开场、案例和问答才知道服务什么。  
如果只是"介绍一下我们公司"或"讲讲数据"，演示就容易变成信息展示。  
这个 skill 在制作 PPT 前使用，也可用于改写已有 PPT 的开场和收尾。

## A1 — 书中的应用 (Past Application)

### 案例 1: 定森坏演示目标不清
- **问题**: 演示者只讲材料和细节，没有说明主题、时间、行动请求和后续安排。
- **方法论的使用**: 作者用 Bad Example 暴露"听众不知道自己要做什么"的问题。
- **结论**: 演示缺少 A/B 状态和行动请求，就失去推动力。
- **结果**: Good Example 改为先声明主题、时间、希望采取的行动和成功案例。

### 案例 2: 技术营业人员说错对象语言
- **问题**: 营业人员面对潜在客户先讲机种定位和价格差。
- **方法论的使用**: 作者指出内容应服务买方和消费者收益，而不是演示者手里的材料。
- **结论**: 先定义听众变化，才能决定该讲技术、收益还是行动安排。
- **结果**: 演示方向从技术展示转向听众问题。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 汇报或提案开场不知道如何定义目的。
2. 路演、销售、项目请示已经有 PPT，但听众下一步不清楚。
3. 领导或客户听完可能只说"知道了"，没有行动。
4. 用户想从"展示资料"转为"推动决策"。

### 语言信号

- "我这个汇报到底想让对方做什么?"
- "PPT已经有了，开场怎么判断?"
- "投资人/老板听完要采取什么行动?"
- "A state to B state / presentation objective"

### 与相邻 skill 的区分

- `conclusion-first-pyramid-report` 处理结论先行的报告结构；本 skill 处理演示前的听众变化目标。
- `pyramid-slide-one-point-check` 检查单页是否一条论点；本 skill 检查整场演示是否有行动目标。
- `th-problem-type-story-routing` 在行动目标明确后选择故事类型。

## E — 可执行步骤 (Execution)

1. **写 A 状态**
   - 描述听众现在知道什么、相信什么、担心什么、尚未行动的原因。
   - 完成标准: A 状态必须是听众状态，不是演示者材料目录。

2. **写 B 状态和行动**
   - 写出演示后希望听众理解、相信、决定、批准、购买、安排或试点什么。
   - 判停条件: 若行动不能被具体观察，先重写；若只是开放探索，不使用本 skill。
   - 完成标准: B 状态 + 下一步行动各一句。

3. **改开场和收尾**
   - 开场声明目的和议程，收尾请求明确行动、负责人和时间。
   - 完成标准: 听众不用猜"所以你要我做什么"。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 研究、教学、共创、心理支持或事实探索场景，不应过早锁定行动。
- 证据不足却要强推决策时，先补事实和风险披露。
- 说服目标涉及隐瞒风险、制造紧迫感或操控听众时，停止。

### 作者在书中警告的失败模式

- 演示者从"我有什么材料"出发，讲完后听众不知道要改变什么或做什么。

### 作者的盲点 / 时代局限

- 原书偏传统商务演示，对异步文档、在线会议和预读材料需要适配。
- "促使行动"若缺少伦理边界，可能被误用为操控式说服。

### 容易混淆的邻近方法论

- 结论先行告诉听众答案；行动变化定义告诉你为什么要做这场演示。
- 单页检查看每页；本 skill 看整场演示前后的状态变化。
