# SIT 约束变形创新验证门

## R — 原文 (Reading)

> 系统创新思维的"五个策略"：减法、除法、乘法、任务统筹、属性依存。
>
> — 《系统创新思维培训PPT》Slide 5-6

> 创新其实恰恰源于对思想的制约，而非放任。限定一个框架，然后在框架内寻找答案。
>
> — 《系统创新思维培训PPT》Slide 6

## I — 方法论骨架 (Interpretation)

SIT 把创新从"等灵感"改成"对对象做结构手术"。
它先限定一个具体对象，例如产品、服务、流程或内容资产，再列出组成部分、功能、角色、触点和属性。
接着用五种动作生成新形态：删除一个组成部分，拆分并重组，复制一个组成部分，给已有元素分配新任务，让一个属性随另一个条件变化。
这套方法的反直觉之处是"形式为先，功能次之"：先制造一个不寻常的新形态，再倒推它可能服务谁、解决什么问题、形成什么定位。
但新形态不是创新成功。
正式进入行动前，必须经过验证门：用户价值、成本、技术、合规、隐私、伦理、可逆实验和停止线。
所以这个 skill 的产物不是灵感清单，而是 3-5 个结构变形候选，加上每个候选的验证计划。

## A1 — 书中的应用 (Past Application)

### 案例 1: 洗衣液减法转成衣物清新剂

- **问题**: 删除洗衣液中的去污活性成分后，原功能看似被破坏。
- **方法论的使用**: PPT 用减法策略列出组成部分，删除基础成分，再从新形态反推用途。
- **结论**: 新形态不再按"能否洗干净"评价，而被重新定位为衣物清新剂。
- **结果**: PPT 转述称该品类给宝洁带来巨大收益；因来源链条不完整，正式使用时只能当启发案例。

### 案例 2: 酒店用任务统筹替代昂贵人脸识别

- **问题**: 酒店希望门童识别二次入住的重要客人，但人脸识别方案成本高。
- **方法论的使用**: PPT 用任务统筹策略重组网上订房、前台入住、重要客人标记和门童识别等流程，让已有环节承担新任务。
- **结论**: 不一定新增昂贵技术，先看现有角色、信息和触点能否重新分工。
- **结果**: 案例生成低成本识别老客流程；PPT 未提供真实实施数据。

### 案例 3: 温度变色杯盖做属性依存

- **问题**: 用户不知道咖啡是否烫口。
- **方法论的使用**: 把杯盖颜色和咖啡温度建立依存关系，温度变化时颜色变化。
- **结论**: 静态属性可以变成用户可感知的状态信号。
- **结果**: 用户观察杯盖颜色即可判断烫伤风险。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户要为产品、服务、流程、知识库、课程、内容栏目、工具或商业模式找新卖点。
2. 团队只会开脑暴会，却没有结构操作、候选形态和验证计划。
3. 用户被旧功能框架卡住，觉得"删掉这个就没用了"。
4. 用户想低成本创新，不确定是否必须采购新技术、增加人手或做大改版。
5. 已经有一个产品/服务对象，但不知道该从组件、功能、任务还是属性入手改造。

### 语言信号

- "这个产品没新卖点了"
- "不要泛泛脑暴，给我系统创新方法"
- "用 SIT / 减法 / 除法 / 乘法想方案"
- "能不能不加资源也做出新体验"
- "form-first / constraint innovation / systematic inventive thinking"
- "把流程重新组合一下"

### 与相邻 skill 的区分

- 与 `creative-workshop-diverge-cluster-prioritize` 的区别: 该 skill 负责会议发散、归类、筛选和实验排序；本 skill 负责对一个具体对象做结构变形，生成新的产品/服务/流程形态。
- 与 `market-feedback-growth-loop` 的关系: 本 skill 生成候选和验证计划；市场反馈 skill 用真实用户或市场反馈检验候选是否有效。
- 与 `primary-source-fact-grounding` 的关系: 当候选依赖行业案例、竞品数据、成本或监管判断时，先做原始材料接地，不能只信 PPT 转述案例。

## E — 可执行步骤 (Execution)

1. **限定对象和边界**
   - 操作: 明确要创新的对象、目标用户、现有用途、不可突破约束、资源窗口和高风险边界。
   - 完成标准: 对象足够具体，可以列出组成部分、功能、任务和属性。
   - 判停条件: 如果问题只是"想点活动创意"，转 `creative-workshop-diverge-cluster-prioritize`；如果已经要决策投放或上线，先补用户和市场证据。

2. **拆出对象清单**
   - 操作: 列出组件、功能、流程节点、角色、触点、外部元素和可变化属性。
   - 完成标准: 至少形成四列：组件/功能/任务/属性；每列不少于 3 项，若确实不足需说明原因。

3. **做五种结构手术**
   - 操作: 依次生成候选：删掉一个基础组件；拆分并重组一个功能或物理部分；复制一个组件并赋予差异；让内部或外部元素承担新任务；让一个属性随条件变化。
   - 完成标准: 每种策略至少产出 1 个候选，总计 3-10 个候选。
   - 判停条件: 如果候选第一眼显得荒唐，不立即删除，先进入下一步倒推功能；若触碰安全、伦理、隐私或合规红线，立即淘汰。

4. **倒推功能和定位**
   - 操作: 对每个候选回答：它可能给谁带来什么新价值、降低什么成本、减少什么摩擦、增加什么体验或产生什么信号。
   - 完成标准: 每个保留候选都有目标用户、使用场景、价值假设和与原方案的差异。

5. **进入验证门**
   - 操作: 检查用户价值、成本、技术可行性、运营复杂度、合规隐私伦理、可逆实验和停止线。
   - 完成标准: 每个候选必须有最小验证动作、成功指标、失败指标、负责人和时间盒。
   - 判停条件: 无法设计低风险验证的候选，不进入实施；高风险专业领域先找专业审查。

6. **排序并输出实验清单**
   - 操作: 按价值潜力、验证成本、风险和可逆性排序。
   - 完成标准: 只选择 1-3 个候选进入实验，其余归档为素材或淘汰。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户需要的是普通会议脑暴、便签归类和优先级筛选，应使用 `creative-workshop-diverge-cluster-prioritize`。
- 已经有真实用户证据和上线决策问题，不能用 SIT 想象替代取证。
- 医疗、金融、安全、儿童、隐私、法律合规或重大生产系统，不能直接用结构变形给执行方案。
- 用户想复制 PPT 成功案例来证明方案一定有效。

### 作者在资料中警告的失败模式

- 等待灵感，把创新神秘化。
- 放任式发散，没有框架、对象和结构操作。
- 删除组件后仍用旧功能评价新形态，提前否定候选。
- 新形式生成后不追问优势、定位和可行性。
- 默认采购昂贵技术，不先重组既有任务。
- 复制组件后因初始形态怪异而提前停止。

### 来源局限

- 来源是作者未标注的培训 PPT，案例多为成功转述，缺少一手证据、失败案例和适用范围。
- "形式为先"容易被误用为无视用户需求；正式使用必须把它限制在候选生成阶段。
- PPT 对成本、合规、隐私、伦理和真实实验讲得不足，本 skill 把验证门作为硬步骤补上。

### 复盘方式

- 实验后记录每个候选的用户反馈、成本、技术阻碍、风险和下一步判断。
- 复盘哪些结构手术产生了有效候选，哪些只是新奇但无价值。
- 把失败候选归档为"失败模式"，下次同类创新先检查。
