# 求真复盘学习闭环

## R — 原文 (Reading)

> 复盘的步骤：1. 回顾目标；2. 评估结果；3. 分析原因；4. 总结规律。
>
> — 《复盘分享培训方法论汇总》Slide 9

> 不是自己骗自己，证明自己对；流于形式，走过场；追究责任，开批判会。而是重在实事求是。
>
> — 《复盘分享培训方法论汇总》Slide 7

## I — 方法论骨架 (Interpretation)

复盘不是把经历讲一遍，也不是把责任人找出来。
它是一种行动后的学习协议：先回到当初目标，再把实际结果摆出来，然后解释差距原因，最后把下一次可复用的规律、规则和动作沉淀下来。
这个方法最重要的入口不是模板，而是防变形。
如果复盘服务于自我证明、走过场、追责、推责或简单结论，事实会被筛选，原因会被扭曲，团队学不到东西。
所以一次好复盘要同时保护两件事：事实足够真实，行动足够具体。
它允许谈责任，但责任必须建立在目标、结果、证据、权限、资源、流程和角色边界之上。
最后产物不是会议纪要，而是下一次行动的规则、负责人、检查点和需要升级的组织问题。

## A1 — 书中的应用 (Past Application)

### 案例 1: 双十二驻店活动复盘

- **问题**: 驻店活动结束后，团队需要判断目标是否达成，以及哪些因素影响了订单和付款路径。
- **方法论的使用**: PPT 先列目标，再对比下午和全天实际单数，并进入热销时间、广告牌位置、付款提醒、下载引导等原因分析。
- **结论**: 复盘不是只说"完成了"，而是把目标、结果、偏差和原因连成下一次可用的经验。
- **结果**: 案例沉淀出热销时段、广告牌摆放、付款提醒和无支付宝用户引导等后续行动规则。

### 案例 2: 目标现状对照

- **问题**: 行动结束后容易凭印象说好坏，缺少共同事实。
- **方法论的使用**: PPT 引述用"当初定的目标"和"现在做的情况"对比，追问哪些地方没有按预定出现以及为什么。
- **结论**: 先确认差距，再解释差距，能避免复盘变成情绪判断。
- **结果**: 团队得到一个最小复盘链条：原目标、实际情况、偏差、原因、下一次规律。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 项目、活动、发布、课程、营销、销售、团队协作或创业尝试刚结束，需要沉淀经验。
2. 复盘会正在变成表功会、检讨会、追责会、甩锅会或模板填空。
3. 团队对结果有争议，但没有先对齐原目标、实际结果和事实证据。
4. 用户想把一次行动的经验转成下次可执行规则、检查点或组织改进项。
5. 管理者需要设计一个让成员敢说事实、又不会逃避责任的复盘流程。

### 与相邻 skill 的区分

- 与 `mistake-to-learning-review` 的区别: 该 skill 处理个人犯错、失败、亏损后的学习转化；本 skill 处理团队或项目行动后的共同事实、角色责任、心理安全和下一次规则。
- 与 `firefighting-to-standard-improvement-loop` 的区别: 该 skill 处理稳定流程反复出同类问题并固化 SOP；本 skill 先让一次行动被诚实理解，不默认问题已属于稳定流程。
- 与 `communication-understanding-execution-loop` 的关系: 复盘会议中若出现事实、感受、请求和行动验收混乱，可组合使用沟通闭环来澄清表达和承诺。

## E — 可执行步骤 (Execution)

1. **设定复盘护栏**
   - 操作: 在开场写明本次复盘不用于自证、甩锅、追责表演或模板交差；本轮目标是还原事实、解释原因、形成下一次动作。
   - 完成标准: 参与者知道可以谈责任，但必须用事实、权限、资源、流程和角色边界说话。
   - 判停条件: 若涉及事故、安全、违法、劳动争议或正式问责，先转专业调查程序，本 skill 只辅助整理事实。

2. **回顾原目标**
   - 操作: 列出行动前的目标、指标、假设、成功标准、关键约束和当时已知风险。
   - 完成标准: 能回答"当初要达成什么，为什么认为能达成"。
   - 判停条件: 如果原目标不存在或事后才补写，标注为"目标缺失"，不要伪造目标。

3. **评估实际结果**
   - 操作: 记录结果数据、关键事实、未完成项、超预期项、时间线和证据来源。
   - 完成标准: 目标和结果可以逐项对照，事实与解释分开。

4. **分析原因**
   - 操作: 对每个差距写原因，至少区分个人动作、流程机制、资源权限、目标假设、外部条件和信息缺口。
   - 完成标准: 每条原因都能对应事实证据或明确标为假设。
   - 判停条件: 若原因列表全是外部因素，补问"我们可控部分是什么"；若全是个人归因，补查流程、资源、权限和激励。

5. **总结规律和边界**
   - 操作: 把经验写成"在什么条件下，下次应该/不应该做什么"。
   - 完成标准: 至少产出 1-3 条可复用规则，每条都有适用条件和不适用条件。

6. **转成行动和检查点**
   - 操作: 为每条规则指定负责人、下一次触发点、检查时间、验收方式和是否需要流程/培训/资源升级。
   - 完成标准: 复盘结束后有行动清单、决策记录和未解决问题清单。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 正在处理重大事故、安全事件、法律合规调查、劳动争议、财务责任或正式纪律处分。
- 问题是稳定流程反复复发，需要用 `firefighting-to-standard-improvement-loop` 做数据、主因、对策和 SOP 固化。
- 用户只是个人一次失败或羞耻感复盘，应优先用 `mistake-to-learning-review`。
- 团队没有基本发言安全，参与者说事实会遭报复；先建立保护和升级机制。

### 作者在资料中警告的失败模式

- 自我证明式复盘: 只挑支持自己的事实。
- 走过场式复盘: 模板完整但没有原因和行动。
- 追责批判会: 先找人背锅，导致信息被隐藏。
- 外因推卸式复盘: 原因全是不可控因素。
- 刻舟求剑式结论: 把一次经验机械固化成通用规则。

### 来源局限

- 来源是作者未标注的培训 PPT，案例多为教学转述，不是一手项目报告。
- 资料强调"求内"，正式使用时必须防止把组织流程、资源、权限和激励问题个人化。
- PPT 对心理安全、劳动合规和正式事故调查程序讲得不足，高风险场景必须升级。

### 复盘方式

- 检查会后 7-30 天行动清单是否执行，而不是只看会议纪要。
- 下一次类似行动前，回看本次规律是否真的被用上。
- 若同一问题反复出现，把它转入 `firefighting-to-standard-improvement-loop` 做流程改进。
