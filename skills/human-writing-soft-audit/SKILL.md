# Human Writing 保真软审校

把本 Skill 当作初稿后的编辑检查层，不当作第二个写手。保留目标写稿 Skill 的 Writing DNA、节奏、标点、短句、重复方式和题材气质。

## 不变量

1. 事实材料和来源边界优先于一切表达优化。
2. 原写稿 Skill 始终是唯一正文所有者。
3. 默认使用 `audit-only`，只返回问题卡；把修改要求退回同一个写稿 Skill。
4. 不用审校补充用户未提供的事实、采访、亲历、引语、数据或场景。
5. 不替代 `dayibin-content-review`、医学/法律/政策核验或人工发布门禁。
6. 不把所有作者修成同一种“自然中文”。目标 DNA 与题材需要高于通用偏好。

## 模式

- `audit-only`：默认。审查标题和正文，返回结构化问题卡，不输出整篇改写稿。
- `apply`：仅当用户明确要求，或编排器已经加载原写稿 Skill 并声明由它继续拥有正文时使用。按问题卡做最小改动，仍按同一个写稿 Skill 的 DNA 输出。
- `diagnose`：只解释事实、结构或自然度问题，不改稿。

## 输入合同

开始前确认：

- 原写稿 Skill 的精确名称；
- 原 Skill 的 Writing DNA 和必须保留的原味指纹；
- 初稿及目标渠道、读者、动作和长度；
- 已确认事实、带来源说法、推断、未知与禁止补写内容；
- 本次策略等级。读取 `references/writing-skill-inventory.json`；不在台账中的 Skill 默认为 `on-demand`。

缺少事实台账时，先从现有材料整理，不把稿件中的所有句子反向当成已确认事实。

## 审校顺序

### 1. 过来源门

区分已确认事实、带来源主张、明确推断和未知。发现事实缺口时写入问题卡，禁止用更流畅的句子掩盖缺口。`source-gated` 路线没有通过来源门时直接停止，不进入表达优化。

### 2. 查材料支撑

找出至少五项支撑稿件的具体事实、行动、数字、引语、约束或后果。现有材料不足五项时如实标注，不为凑数发明第六项。

检查是否把搜索、用户材料或公开报道写成作者自己的亲历、采访、朋友关系或现场观察。

### 3. 查段落推进

逐段回答“这一段新增了什么”：事实、动作、例子、区分、问题、反方观点或后果。只复述上一段的，建议合并、删除或补上真实功能。

若删掉约三分之一仍不影响事实、论证和目标节奏，建议压缩；不得为了短而删除必要证据、人物温度、铺垫或目标作者的节奏。

### 4. 查假细节与流程泄漏

标出无材料支撑的装饰场景、精确动作、对话、心理、亲历和因果。标出 Skill 名、模型、素材处理、路由、审稿分数、写作步骤或“根据你提供的材料”等生产过程泄漏。

### 5. 查结尾

材料和判断完成时停止。不要强加通用总结、励志升华或模型式路线图。事实不能收束时保留张力和未知。

### 6. 做保真回归

列出本轮必须保留的 3–5 个目标 DNA 指纹。任何建议若会让风格变弱、人物温度消失、题材气质错位或标题变得模板化，降级为 `skip`。

## 明确关闭的硬禁令

- 冒号不禁用。
- 破折号和其他横线不禁用。
- `不是 A，而是 B` 及同类对比结构不禁用。
- `闭环`、`方法论`、`底层逻辑` 等词不能只按字符串删除。
- 目标 DNA 中有功能的短段、重复、直白、标点和修辞习惯必须保留。

## audit-only 输出

只返回以下问题卡，不输出整篇新正文：

```text
【审校策略】default-on / guarded-on / suggested / on-demand / default-off / source-gated
【结论】通过 / 同主笔小修 / 同主笔重写 / 补材料后再写 / 跳过软审校
【必须保留】3—5 个目标 DNA 指纹
【事实问题】最多 5 条；写原句、问题、允许的修法
【推进问题】最多 5 条；写段落位置、重复功能、建议动作
【自然度问题】只列有证据的问题，不按禁词表机械判定
【同主笔修改单】按优先级给原写稿 Skill，最多 8 条
【停止条件】何时不得继续优化
```

没有明确问题时返回“通过”，不要为了证明调用有价值而强行改稿。

## apply 边界

只有满足全部条件才执行：

1. 已加载原写稿 Skill；
2. 已列必须保留的目标 DNA；
3. 事实台账足够；
4. 用户或编排器明确允许修改；
5. 修改后仍交最终审稿。

只改问题卡命中的位置。返回标题和正文，并另附不进入正文的简短改动说明。若无法同时守住事实和风格，停止并退回问题卡。

## 编排接入

在多 Skill 工作流中执行：

```text
唯一写稿 Skill 出初稿
→ 本 Skill audit-only
→ 同一个写稿 Skill 最多回炉一次
→ dayibin-content-review
```

不得让本 Skill 与原写稿 Skill 轮流重写。读取 `references/integration-policy.md` 了解分级理由；读取 `references/writing-skill-inventory.json` 做机器可校验的覆盖检查。

## 验收

- 没有新增事实、亲历、采访或来源强度。
- 每条改动能追溯到问题卡。
- 原写稿 Skill 仍是唯一正文所有者。
- 目标 DNA 指纹没有减少。
- 正文不出现审校和生产过程。
- 最终发布闸门仍然存在。

## 来源边界

软规则参考 `KKKKhazix/human-writing` 1.0.0（commit `22d20b6726`）中的材料与段落推进思想；没有执行其仓库代码，也没有采用其绝对标点、句式或词语禁令。采用等级来自本机 2026-08-05 的 12 组修正盲测，未覆盖的写稿 Skill 保守按需。
