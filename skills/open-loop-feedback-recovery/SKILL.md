# 开环决策反馈恢复

## R — 原文 (Reading)

> “他们没有收到不断迭代、更新的反馈，他们似乎也并不关心结果怎样。”
>
> — 沃尔特·艾萨克森，第47章“开环警告”

## I — 方法论骨架 (Interpretation)

开环不是简单意见不足，而是决策者已经切断了能改变行动的反馈：坏结果被归因于敌人，反对者失去发言权，承诺不断扩大。恢复闭环要先暂停新增风险，再把事实、受影响者、可信反方和结果指标带回决策。决策者必须事先声明什么证据会让自己修改、停止或回退，并给予外部角色实际叫停权。

## A1 — 书中的应用 (Past Application)

### 案例 1：纯视觉路线重新开放

- **问题**：马斯克长期反对表现不佳的雷达，团队担心新方案也会被一概拒绝。
- **方法论的使用**：工程师用不同能力的新型雷达和实验方案提供可验证证据。
- **结论**：反对的对象应是糟糕证据和方案，而不是某个技术标签。
- **结果**：马斯克同意在高端车型秘密试验新系统。

### 案例 2：萨克拉门托搬迁

- **问题**：基础设施工程师试图解释隐藏依赖和搬迁风险。
- **方法论的使用失败**：他们的说明被打断，物理搬迁速度被当作全部结果。
- **结论**：陌生领域中拒绝逆耳信息，会把高行动力变成系统性盲点。
- **结果**：7 万次硬编码引用损坏，马斯克后来承认关闭数据中心是错误。

## A2 — 触发场景 (Future Trigger)

1. 项目连续失败，负责人却不断追加资金或期限，不愿讨论停止。
2. 团队只汇报领导者想听的信息，异议者沉默或离开。
3. 个人在公开表达、投资或并购上情绪化加码。
4. 所有负面证据都被解释成敌对集团、用户无知或执行不够努力。

### 语言信号

- “他已经听不进任何意见了。”
- “结果越差，反而越加码。”
- “什么证据能让我们承认判断错了？”
- “This decision loop is closed to feedback.”

### 与相邻 Skill 的区分

- 与 `multi-view-truth-filter` 的区别：后者用于形成判断前寻找反证；本 Skill 用于判断已经封闭并持续加码后的恢复。
- 与 `thought-observer-pause` 的区别：后者处理个人念头到动作的短暂停顿；本 Skill还处理组织权力、指标和外部叫停权。
- 与 `bounded-rapid-failure-protocol` 的区别：若团队不愿被试验结果改变，应先恢复开环再试验。

## E — 可执行步骤 (Execution)

1. **识别开环证据**
   - 列出被忽略的结果、被排除的角色、不断扩大的承诺和无法证伪的解释。
   - 完成标准：至少有两类证据表明反馈无法改变决策，而非普通分歧。

2. **暂停扩大暴露**
   - 暂停新增资金、全量上线、公开承诺、裁员或不可逆动作。
   - 完成标准：在审查完成前，风险规模不再增加。
   - 停止条件：如存在即时人身或安全风险，转入应急和专业处置。

3. **重建事实板**
   - 分开记录事实、解释、预测和价值判断。
   - 加入原始指标、实际操作者、受影响者和至少一名可信反方。
   - 完成标准：每个关键结论都有证据来源和不确定性。

4. **声明改变阈值**
   - 每位决策者写下什么证据会使其继续、修改、暂停或终止。
   - 完成标准：阈值在新结果出现前固定，不允许事后移动门柱。

5. **赋予外部叫停权**
   - 指定独立审阅者、董事、风险负责人或技术负责人，在阈值触发时可以暂停。
   - 完成标准：叫停权是实际权限，不只是顾问意见。

6. **用小规模行动重新闭环**
   - 选择可逆试验或有限承诺，按结果阈值执行继续或停止。
   - 完成标准：至少一项决策因反馈发生真实改变。

## 复盘方式

- 检查坏结果是否仍被自动归因于外部敌人。
- 记录哪些反方意见最终改变了动作，以及提出者是否受到惩罚。
- 若阈值连续两次被触发却没有执行，判定叫停机制无效，升级到更高治理层。
- 公开表达场景记录“冲动发生时间—等待时间—核验结果—最终是否发布”。

## B — 边界 (Boundary)

- 不把正常不同意见或果断决策都诊断为开环。
- 不用于精神健康危机诊断；若有自伤、伤人、严重失控风险，应联系专业与紧急支持。
- 反方不是人数投票，证据质量仍需评估。
- 第90—91章表明阴谋叙事能吸收所有反证；无法说明何种证据会改变判断时，应停止扩大承诺。
- 恢复反馈不能成为无休止讨论，必须在预设阈值后采取行动。
