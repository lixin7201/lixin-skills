# 讲解—教练责任分层

## R — 原文 (Reading)

> 微课+大社群
>
> — 李笑来，第8章 问问自己真的适合卖课吗

---

## I — 方法论骨架 (Interpretation)

知识传递与行为改变是两种不同工作。讲解层负责概念准确、结构清楚、示例和理解检验；教练层负责目标、练习、反馈、障碍处理和持续执行。

两层可以由同一产品提供，也可以分开，但必须有不同验收：听懂不等于做到，做到也不能只靠增加内容。先明确用户购买的是哪一层，再决定人员、工具、节奏、规模和价格。

“微课+大社群”只是书中实例，不是普遍方案；小组、一对一、自动反馈或同伴练习都可能更合适。

## A1 — 书中的应用 (Past Application)

### 案例：开源定投书并持续维护践行群

- **问题**：作者先把定投方法写成开放内容，再通过长期社群维护把一次性内容转为持续实践环境。
- **方法论的使用**：作者把该经历用于检查内容开源、社群践行闭环，而不是只展示结果。
- **结论**：案例能说明方法如何进入真实行动，但不能从一个成功样本推出普遍因果。
- **结果**：形成书籍、课程与社群结合的持续服务模式；收益与成员效果为作者自报，需独立核验。

## E — 可执行步骤 (Execution)

1. **定义结果与层级**
   - 动作：写出用户要理解什么、要做到什么，以及只购买讲解层还是包含教练层。
   - 完成标准：两类结果分开且不承诺不可控终局。

2. **设计讲解层**
   - 动作：配置核心概念、示例、练习和复述/测验，删去无助理解的内容。
   - 完成标准：学员能正确复述并完成最小知识检验。

3. **设计教练层**
   - 动作：配置目标、实践任务、反馈频率、障碍升级、同伴/教练角色和退出规则。
   - 完成标准：每个实践周期有行为证据、反馈责任和未完成处理。

4. **校准规模与承诺**
   - 动作：根据反馈密度、风险和单位成本选择一对一、小组、社群或自动化，并公开不包含内容。
   - 完成标准：服务容量、响应时限、价格、退款和边界透明。

### 整体验收与停止

- **完成标准**：讲解与教练的结果、责任、验收、容量、边界和退出均被分开定义。
- **停止条件**：结果需持证专业人员、反馈容量不足、承诺不可控或成员安全隐私无法保障时停止销售或缩小服务。
- **复盘方式**：每期分别统计理解通过率、实践完成率、反馈延迟和退出原因，不能只看观看数或群人数。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不把大社群当唯一或必需实现
- 不以教练名义越过医疗心理法律资质和个人自主权

### 作者在书中警告的失败模式

- 用更多课程内容掩盖实践支持缺失，或用无限陪伴承诺掩盖责任、容量和退出边界。

### 作者的盲点 / 时代局限

- 书中 BOX 社群效果主要为作者自报，缺少对照和长期退出数据；规模优势需真实验证。
