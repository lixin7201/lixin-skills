# 核心因果锚点

| 场景 | 最先命名的变量 | 常见错位 | 可迁移判断 |
|---|---|---|---|
| 想赚钱但没方向 | 具体事情与用户价值 | 把“赚钱”当技能或动作 | 先选能交付价值的事情，再补所需能力 |
| 产品增长停滞 | 用户最终需求与使用摩擦 | 只优化已有功能 | 换维度，让交付更靠近用户结果 |
| 用户调研 | 真实行为、样本异质性、回答成本 | 把点赞和礼貌支持当需求 | 看搜索、付费、使用、提问、流失等行为 |
| 案例学习 | 已验证结构与相似性 | 收藏案例或迷信创新 | 拆 what/why/how，进入需求/流量/营销/变现清单 |
| 执行力 | 下一步清晰度；动力与阻力 | 先找工具、意志力或自责 | 模仿成熟拆解，缩小到能立刻开始的动作 |
| 学习 | 归纳、演绎和连接 | 听懂、囤课、只记“是什么” | 找现实对应，再迁移到自己的对象 |
| 完美主义 | 发散与收敛失衡 | 继续研究等于继续进步 | 设收敛条件，进入实践 |
| 写作/内容 | 用户问题、价值感知、传播承载 | 只表达自己想说的 | 从读者场景和需求组织素材 |
| 商业模式 | 需求—产品—流量—营销—变现闭环 | 迷信单点流量或技巧 | 找断点，检查承接与复购 |
| 个人成长 | 刻意练习与长期复利 | 把高手能力归因于天赋 | 建清单、重复训练、形成自动联想 |

## 防止被通用顾问腔替换

- “多坚持”不能替代“下一步是否清楚”。
- “做好产品”不能替代“功能是否靠近用户最终结果”。
- “多做调研”不能替代“真实行为与样本结构”。
- “多学习”不能替代“归纳—演绎—迁移”。
- “创新”不能替代“先模仿已验证结构，再做情境匹配”。
- “建立系统”必须落到需求、产品、流量、营销、变现和反馈链。
