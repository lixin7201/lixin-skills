# 私域适用性与触达边界审计

## R — 原文 (Reading)

> 私域流量是指企业可以直接控制并且无需支付额外费用就可以反复触达的用户群体。
>
> — 《分章节P3-06 私域运营》Slide 9, lines 68-70

> 每个企业的实际情况不同，因此在实际操作中还需要根据自身特点进行适当的调整。
>
> — 《分章节P3-06 私域运营》Slide 15, lines 325-326

## I — 方法论骨架 (Interpretation)

私域不是“把人拉进群后反复卖”的捷径，而是一种长期关系运营。真正的问题是：这类用户是否愿意被持续触达，企业是否能持续提供价值，触达是否获得同意，服务能力是否跟得上。

这个 skill 先判断行业和业务适配，再检查用户同意、价值承接、标签授权、频率控制、退出机制、平台政策和服务承受力。只有这些硬门通过，才进入链路设计。

它特别强调边界：用户可以被经营关系，但不能被当成无限触达资产。

## A1 — 书中的应用 (Past Application)

### 案例 1: 公域流量向私域转化

- **问题**: 企业希望把社交媒体、搜索、电商等公域流量导入自己的渠道。
- **方法论的使用**: PPT 将品牌价值认同、内容口碑、活动裂变、线索运营和价值沉淀放入转化链路。
- **结论**: 转私域前必须先有价值和信任承接。
- **结果**: 私域不是单纯拉人，而是关系和内容的沉淀。

### 案例 2: 抖音私域闭环适配

- **问题**: 品牌想从抖音导流做私域转化。
- **方法论的使用**: PPT 列出低客单、线上化高、高复购、短决策等行业条件。
- **结论**: 不同行业不应照搬同一闭环。
- **结果**: 高客单、长决策、低复购业务要改为信任培养和咨询承接。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 想把抖音、小红书、视频号、电商、公域投放用户导入企微、社群、公众号或会员体系。
2. 想判断高客单咨询、知识付费、门店、电商、SaaS 是否适合私域。
3. 社群、企微或会员触达带来投诉、退群、低转化或服务压力。
4. 想设计标签、SOP、RFM、ONE ID 或自动化触达前，需要先检查授权和边界。

### 语言信号

- “适不适合做私域？”
- “怎么从公域转企微/社群？”

- 与 `customer-journey-touchpoint-diagnosis` 的区别: 先用旅程 skill 找用户在哪个阶段需要承接；再用本 skill 判断能否反复触达。

## E — 可执行步骤 (Execution)

1. **判断行业适配**
   - 完成标准: 明确客单价、线上化程度、复购频次、决策成本、信任周期和服务复杂度。

2. **确认用户同意与价值交换**
   - 完成标准: 写清用户为什么愿意进入私域、会得到什么价值、如何退订或退出。
   - 判停条件: 没有明确同意、退订路径或价值承诺时，不设计触达动作。

3. **检查承接能力**
   - 完成标准: 列出内容供给、客服响应、交付能力、线索管理和投诉处理能力。

4. **设计触达边界**
   - 完成标准: 明确频率、触达类型、标签使用范围、敏感数据禁区和平台规则核验项。

5. **搭建最小链路**
   - 完成标准: 输出一个从来源、入域、培育、转化、复购/推荐到退出的最小链路。

6. **复盘信任指标**
   - 完成标准: 除转化外，跟踪退订、投诉、响应、复购、推荐和用户反馈。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只是想找平台规则的最新操作步骤，应先做当前政策核验。
- 用户没有持续价值供给，只想高频推销。
- 涉及未授权采集、过度画像、骚扰式触达或规避平台规则。

### 作者在书中警告的失败模式

- 把“可反复触达”理解为“可以无限打扰”。
- 不看行业条件，照搬抖音私域闭环。
- 标签和 ONE ID 只追精细化，不检查授权和最小必要。

### 作者的盲点 / 时代局限

- PPT 未充分展开隐私保护、平台政策变化和用户退出权；正式使用时这些是硬边界。

### 容易混淆的邻近方法论

- 私域不是 CRM 系统采购问题；工具只有在价值、同意和承接能力成立后才有意义。
- 社群活跃不是最终目标，信任和复购才是关键结果。
