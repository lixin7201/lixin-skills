# 创意工作坊发散-归类-筛选闭环

## R — 原文 (Reading)

> 书面头脑风暴法，让参与者以接力的方式，轮流书面填写创意表格，以求短时间内产出大量的创意。
>
> — 《分章节P1-03 创意和想象力》Slide 9, lines 67-103

> 以“可行性”和“效果”为评估指标的矩阵之中。
>
> — 《分章节P1-03 创意和想象力》Slide 21, lines 476-485

## I — 方法论骨架 (Interpretation)

创意工作坊不能只靠“大家随便说”。这个 skill 把创意生产拆成四段：先静默发散，避免权威和即时批评压缩想法；再用 KJ 法归类，找到模式；再用 SCAMPER 或曼陀罗补缺口；最后用利弊表、支付矩阵或决策矩阵筛选。

它的关键是阶段分离。发散阶段追求数量和多样性，收敛阶段才讨论成本、风险、可行性和效果。过早评价会杀死创意，永不评价会留下噪音。

最终产物不是漂亮便签墙，而是少数可实验的优先创意、验证指标和停止线。

## A1 — 书中的应用 (Past Application)

### 案例 1: 改进销售体系的书面头脑风暴

- **问题**: 团队需要短时间产生大量销售体系改进点。
- **方法论的使用**: 参与者围绕主题接力书写，遵守自由发挥、严禁批判、欢迎补充和重数量原则。
- **结论**: 静默书面形式可以降低即时评价和职位影响。
- **结果**: 创意池先被扩大，再进入归类和筛选。

### 案例 2: 餐馆销售额创意支付矩阵

- **问题**: 餐馆有多种提升销售额创意，不知道先做哪个。
- **方法论的使用**: 将官网自媒体、限期优惠、会员制度、新菜品、装修等放入可行性和效果矩阵。
- **结论**: 高效果高可行的创意优先进入实验。
- **结果**: 筛选从偏好争论变成指标比较。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 团队要为新产品、课程卖点、营销活动、内容栏目、流程改进或创业方向想方案。
2. 会议中老板或强势成员过早否定，导致点子变少。
3. 创意很多但散乱，无法归类、补缺口或决定先做哪个。
4. 用户想把 SCAMPER、KJ、曼陀罗、利弊表和矩阵串成完整流程。

### 语言信号

- “帮我设计一场头脑风暴”
- “点子很多但不知道怎么筛”
- “用 SCAMPER / KJ / 曼陀罗做创意”
- “creative workshop / diverge / cluster / prioritize”

### 与相邻 skill 的区分

- 与 `problem-analysis-tool-router` 的区别: 路由器判断问题是否适合创意工作坊；本 skill 负责具体工作坊。
- 与 `market-feedback-growth-loop` 的区别: 本 skill 产出候选创意；市场反馈 skill 验证创意是否真实有效。

## E — 可执行步骤 (Execution)

1. **设定主题和约束**
   - 完成标准: 写出一个清晰主题、目标用户/对象、时间盒、决策人和不可突破约束。
   - 判停条件: 没有主题、决策人或评价指标时，先停止并补定义。

2. **静默发散**
   - 完成标准: 每人独立写创意，禁止批评和自我否定，完整记录。

3. **KJ 归类**
   - 完成标准: 把相近创意合并成小组/中组/大组，并给每组命名。

4. **二次发散补缺口**
   - 完成标准: 用 SCAMPER 七问或曼陀罗八方向补出缺少的角度。

5. **利弊和矩阵筛选**
   - 完成标准: 对候选创意写成本、风险、可行性、效果或替代指标；矩阵只作排序辅助。

6. **转成实验**
   - 完成标准: 选 1-3 个创意，定义验证动作、指标、负责人、时间盒和停止线。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 已有真实用户证据要求决策，不能用会议想象替代实验。
- 主题过大、无决策权或没有资源窗口。
- 团队只想证明既定方案正确，不愿保留反对意见。

### 作者在书中警告的失败模式

- 发散时即时评论或批判。
- 创意列举偏正面，忽略负面因素。
- 决策矩阵只看总分，忽视关键单项风险。

### 作者的盲点 / 时代局限

- PPT 主要讲工具组合，对用户实验和反事实验证讲得不足；正式使用必须把优先创意转成小实验。

### 容易混淆的邻近方法论

- 头脑风暴不是决策，矩阵也不是证据；二者后面都要接验证。
- SCAMPER 是补创意角度，不是商业可行性证明。
