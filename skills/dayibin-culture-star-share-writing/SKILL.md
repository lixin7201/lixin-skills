# 大宜宾企业文化之星知识星球分享稿写作 Skill

## Overview

用于根据用户提供的“一个月工作内容”，写出大宜宾知识星球企业文化分享稿。稿件必须以 `#使命×价值观×文化  {主题}` 开头，结合大宜宾使命、价值观和具体工作现场，写得像真人复盘，情感真挚，没有 AI 感。

这类稿子的核心不是“解释文化口号”，而是：

> 本月真实场景 → 具体问题/冲突 → 我做了什么 → 结果/反馈 → 我哪里变了 → 这条企业文化在这件事里是什么意思。

## When to Use

使用本 skill，当用户说：
- “帮我写知识星球分享”
- “这个月企业文化稿怎么写”
- “结合我一个月工作内容和感悟写分享”
- “写 #使命×价值观×文化 开头的稿子”
- “企业文化之星分享稿”
- “不要 AI 感，要真诚”

不要用于：
- 对外公众号正式新闻稿；
- 大宜宾 APP 热点稿；
- 纯月报/述职 PPT；
- 涉及客户/会员隐私且用户未授权脱敏处理的完整案例公开发布。

## Company Culture Themes

常见标题格式：

```markdown
#使命×价值观×文化  工作现场有神灵
```

可选主题：
- 不忘初心
- 工作现场有神灵
- 学习创新
- 追求完美卓越
- 尊重他人
- 用心对人对事

不同主题的落点：

| 主题 | 不要写成 | 应该落到 |
|---|---|---|
| 不忘初心 | “我热爱公司” | 具体困难中仍不放弃；今日事今日毕；长期主义；归属感；流程坚持 |
| 工作现场有神灵 | “现场很重要” | 发现问题不逃避；立即解决；诚实正直；勇于承担；现场复盘 |
| 学习创新 | “我要学习新东西” | 拆解优秀案例；本地化改造；用 AI/新工具但保留判断；建立新方法 |
| 追求完美卓越 | “我很认真” | 反复修改、检查、重拍、重剪；自己先满意；不交差 |
| 尊重他人 | “对客户礼貌” | 站在客户/用户/同事立场，但守原则，不无底线迁就 |
| 用心对人对事 | “我很用心” | 凡事有交代、事事有回音；多走一步；不看菜下饭；超出预期 |

## Workflow

### Step 1：先收用户输入

用户最理想的输入格式见 `templates/monthly-work-input.md`。但不要强迫用户填表；他只要丢一段工作流水，也可以直接处理。

先提取：
- 本月主题：如果用户已说主题，照用；如果没说，从工作内容判断最匹配主题。
- 主案例：最有冲突、成长、结果的一件事。
- 辅助案例：补充证明价值观的另一件小事。
- 证据：项目名、人名、数据、反馈、修改次数、客户/同事参与、真实情绪。

### Step 2：决定要不要追问

用户偏好“先做了”，不要一上来问一堆问题。

不追问，直接写的条件：
- 有 1-3 件具体工作；
- 至少有一个结果/反馈/困难；
- 能判断主题或用户已给主题。

最多追问 3 个问题的条件：
1. 完全没有主题，也无法从工作判断；
2. 工作内容全是流水账，没有主案例；
3. 没有任何可写结果、反馈或真实感受。

可追问句式：

```text
我先不问太多，只补 3 个关键点：
1）这个月企业文化主题是哪一个？
2）你最想重点写哪件事？
3）有没有可写的数据/反馈/被指出的问题？没有也可以写过程。
```

### Step 3：主动浏览电脑/知识库补证据

当用户只说“这个月做了交行活动、几个稿子、AI 写作”这类粗略内容时，主动搜索本地证据，不要编。

优先搜索路径：

1. 历史知识星球样本：
   - `/Users/REPLACE_ME/Documents/大宜宾/大宜宾知识库整理/知识星球分享/手动抓`
2. 当前知识库：
   - `/Users/REPLACE_ME/.openclaw/workspace/knowledge/02-公司知识库`
3. 可能的运营资料路径：
   - `/Users/REPLACE_ME/Documents/大宜宾/大宜宾知识库整理/运营部/`
4. 关键词：
   - 项目名/客户名：如“交行”“理财节”“爱心送考”“王家”“山姆”“彩凤凰”“绿源”“市场监管局”
   - 人名/花名：二毛、加菲、小美、小康、小田、甘甘等
   - 文件类型词：方案、脚本、复盘、总结、排期、数据、会议纪要、反馈

证据原则：
- 找到就写具体。
- 找不到就不要编。
- 不确定数据不要写死，可写“目前看到的反馈是……”或留待用户确认。
- 红娘/相亲/客户服务案例必须脱敏。

### Step 4：整理证据卡

出稿前先在草稿中整理：

```text
本月主题：
用户岗位/视角：
主案例：
辅助案例：

主案例证据：
- 背景：
- 难点/冲突：
- 我当时的真实状态：
- 我做了哪些动作：
- 谁给了提醒/帮助：
- 结果/数据/反馈：
- 我复盘出的教训：

价值观落点：
- 这件事对应哪条文化？
- 它不是一句口号，而是什么具体行为？
- 下次我会怎么做？
```

### Step 5：选择结构

#### A. 单主线深挖型

适合有一个强项目。优先使用。

```text
开头真实状态
→ 项目背景
→ 遇到困难
→ 具体动作
→ 结果反馈
→ 复盘企业文化
→ 未来行动
```

#### B. 两点分论型

适合材料较多，且主题可以拆成两个落点。

```text
开头
1、{个人化理解}
   案例 + 动作 + 结果 + 反思
2、{个人化理解}
   案例 + 动作 + 结果 + 反思
结尾
```

#### C. 成长时间线型

适合新人、转岗、被批评后成长、入职周年。

```text
刚开始我……
这个月发生了……
当时我……
后来大家指出……
我开始调整……
现在我理解……
接下来我希望……
```

#### D. 后台流程型

适合数据、运营、行政、销售运营等“看不见”的岗位。

```text
别人看不见的工作
→ 曾经吃过亏/发现问题
→ 为什么流程重要
→ 我如何坚持执行
→ 这背后的企业文化
```

## Opening Patterns

优先用真实、口语、现场感开头：

- 如果用一句话总结这个月，那就是——{真实状态}。
- 说实话，这个月的 {项目}，是我最近做得最 {痛苦/紧张/有成就感} 的一件事。
- 这个月的企业文化刚好是 {主题}，而 {事件} 让我对它有了很实在的理解。
- 以前我以为 {旧认知}，直到这个月真正做了 {事件}，才发现 {新认知}。
- 对我来说，{主题} 不是一句挂在墙上的话，而是 {具体行为}。

避免：
- “在当今快速发展的时代……”
- “企业文化是企业发展的灵魂……”
- “作为一名新时代员工……”
- “通过本月工作，我深刻认识到……”
- “我将以更加饱满的热情投入工作……”

## Draft Template

```markdown
#使命×价值观×文化  {主题}

如果用一句话总结这个月，那就是——{真实状态}。

{用 1-2 段交代本月最重要的工作现场，不要解释文化定义。}

一开始我以为 {旧认知/简单想法}。真正做起来才发现，{困难/冲突}。当时我最明显的感受是 {真实情绪}。

但这件事不能就这么悬着，所以我开始 {动作1}，同时 {动作2}，后来又 {动作3}。这个过程中，{同事/客户/领导} 也给了我 {帮助/反馈/提醒}。

最后 {结果/数据/反馈}。

现在回头看，这件事让我明白，{企业文化主题} 不是 {空泛解释}，而是 {具体工作习惯/具体选择}。

{辅助案例：用较短篇幅说明这个价值观不是偶然，而是本月反复出现的工作状态。}

接下来如果再遇到类似情况，我会 {具体行动}。{收束到个人成长/团队协作/公司文化，不喊空口号。}
```

## Voice Rules

写得像大宜宾真实员工：
- 可以有“说实话”“现在回头看”“那会儿真的有点崩”“心里一紧”“不是没想过敷衍过去”这类真人表达。
- 可以写二毛、加菲、小康、小美、小绵羊等花名，但不要乱造人物参与。
- 可以写情绪，但不要卖惨。
- 可以写成绩，但不要只夸自己。
- 语言要顺，不要太书面；但也不要过度网络化。

## Privacy / Safety

红娘、相亲、客户服务类稿件必须：
- 不写客户全名；
- 不写可识别身份组合；
- 不写过度私密细节；
- 保留冲突但做脱敏；
- 不编成交、锦旗、金额、客户原话。

## Anti-AI Checklist

出稿后逐项检查：

- [ ] 是否以 `#使命×价值观×文化  {主题}` 开头？
- [ ] 是否围绕一个主案例，而不是流水账？
- [ ] 是否有至少 3 个具体证据：项目名、人物、时间、动作、数据、反馈、修改次数等？
- [ ] 是否写出了困难、冲突或不足？
- [ ] 是否写了“我具体做了什么”，不是只写“我很努力”？
- [ ] 是否有真实情绪或个人变化？
- [ ] 是否把企业文化落到具体行为？
- [ ] 是否避免“在当今时代”“深刻认识到”等 AI 腔？
- [ ] 是否没有编造数据和评价？
- [ ] 是否注意客户/会员隐私？
- [ ] 结尾是否是具体行动，而不是空喊口号？

## Best Practice

最终交付给用户时，通常给：
1. **正式稿**：可直接复制发知识星球。
2. **可选标题/主题备选**：如果主题不确定，给 2-3 个。
3. **我用到的证据**：简短列出，方便用户确认有没有不准。
4. **需要用户确认的点**：只列不确定数据/事实，不要把所有问题都丢回去。
