# SCRTV 价值方案表达

## R — 原文 (Reading)

> 情境、冲突、原因、策略、价值（呼吁）。
>
> — 《结构化思维工具》Slide 8, lines 45-57

> 标准SCRTV公式——向领导提交方案、报告等。
>
> — 《结构化思维工具》Slide 10, lines 69-71

## I — 方法论骨架 (Interpretation)

SCRTV 是一个从背景到行动的表达链。它先给听众必要情境，再指出现实和目标之间的冲突，接着解释冲突为什么发生，然后提出策略，最后说明策略能创造什么价值或需要对方采取什么行动。

它适合写一段“让人愿意继续听”的方案开场、提案摘要、营销表达或演讲呼吁。它不是为了煽动，而是为了避免听众只听到方案却不知道为什么现在要做。

一个合格的 SCRTV 表达必须经得起反向审计：冲突是真的，原因能解释冲突，策略回应原因，价值不是空口承诺。

## A1 — 书中的应用 (Past Application)

### 案例 1: 说服领导购买 CRM 系统

- **问题**: 需要向领导表达购买 CRM 系统的方案价值。
- **方法论的使用**: PPT 用 TV 变量公式压缩表达：策略是使用 CRM 系统，价值是利润提升 30%，并给出后续资料发送动作。
- **结论**: 即使压缩到 TV，也要保留“策略创造价值”的链条。
- **结果**: 方案不只说“买系统”，而是把行动和业务收益连起来。

### 案例 2: 滴滴宣传话术

- **问题**: 共享打车软件需要宣传话术。
- **方法论的使用**: 用情境、冲突、策略、价值组织用户出行不便和 App 解决方案。
- **结论**: 话术要从用户场景出发，而不是只罗列功能。
- **结果**: 用户更容易理解为什么这个工具与自己有关。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 要写一段方案摘要、提案开场、销售话术、募资简介或演讲呼吁。
2. 已有策略，但听众可能不知道为什么要听、为什么要现在做。
3. 表达里功能很多、卖点很多，却缺少“冲突-原因-价值”链。
4. 需要把复杂想法压缩成一段 30-90 秒可说清的话。

### 语言信号

- “帮我写一段方案开场”
- “这个提案怎么讲价值？”
- “把卖点讲得更有说服力”
- “value proposition / proposal brief / SCRTV”

### 与相邻 skill 的区分

- 与 `claim-reason-fact-reception-audit` 的区别: 本 skill 组织自己的输出；对方的输入是否可信由审计 skill 处理。
- 与 `conclusion-first-pyramid-report` 的区别: 本 skill 写一段价值链表达；金字塔 skill 组织整份报告。

## E — 可执行步骤 (Execution)

1. **写情境 S**
   - 完成标准: 一句话说明当前背景、对象和已知现实，不加入夸张判断。

2. **写冲突 C**
   - 完成标准: 指出现实与目标、常规、期望或用户需求之间的真实落差。
   - 判停条件: 如果冲突只是制造焦虑且无证据，停止并补事实。

3. **写原因 R**
   - 完成标准: 解释冲突产生的关键机制，不把症状误写成原因。

4. **写策略 T**
   - 完成标准: 给出可以执行的方案、动作或选择，并明确对象。

5. **写价值 V**
   - 完成标准: 说明策略带来的收益、影响或呼吁；价值承诺必须有证据、前提或范围。

6. **做风险披露**
   - 完成标准: 标出 1-3 个成本、限制、替代方案或未证实前提。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 事实、数据或客户证据尚未核验时，不要直接写价值承诺。
- 用户要搭建整份报告结构时，应转金字塔/报告类 skill。
- 用户要求隐瞒风险、夸大收益或操控受众时，应拒绝并改为透明表达。

### 作者在书中警告的失败模式

- 只做功能堆砌，没有说明冲突和价值。
- 把价值写成口号，缺少策略和原因支撑。

### 作者的盲点 / 时代局限

- PPT 强调说服效率，但对伦理披露、证据强度和受众拒绝权讲得不足；正式使用必须补充风险和前提。

### 容易混淆的邻近方法论

- SCQA 更适合开篇引出问题；SCRTV 更强调策略和价值呼吁。
- FABE 更偏产品卖点；SCRTV 更偏方案链路。
