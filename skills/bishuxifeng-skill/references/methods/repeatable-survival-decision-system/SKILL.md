# 可生存的重复决策系统

## R — 原文（Reading）

> 如果押输了，我该怎么办，而不是我认为怎么能押对。为此才诞生了交易系统。
>
> — 碧树西风，BXSF-107 · 2025-12-07

> 风险管理的本质就是次数理论
>
> — 碧树西风，BXSF-009 · 2022-03-16

## I — 方法论骨架（Interpretation）

1. 把决策质量从‘这一次有没有猜中’改成‘这套系统能否长期存活并持续修正’。
2. 方向只是一个变量；进入条件、暴露规模、流动性、退出条件和模型适用域共同决定能否兑现判断。
3. 单次损失必须小到不会永久出局，只有这样，次数才会带来数据、经验和概率优势。
4. 系统不是固定秘籍。规则应预先写明，但当适用条件被证据推翻时，要整体升级而不是临场随情绪漂移。

## A1 — 语料中的应用（Past Application）

### 案例 1：把市场当系统调试

- **问题**：作者自述从小额异常成交入手，不追求一次暴利，而用真实订单暴露问题、修正规则。
- **方法论的使用**：先做可承受的小策略，再逐步扩大到跨平台与技术增效。
- **结果与证据边界**：作者称第三年开始稳定盈利；收益与归因均为自述，不能当外部验证。
### 案例 2：六十个月盈利后的模型失效

- **问题**：连续盈利让作者误以为规律总可掌握，随后两个月不可解释的小亏损打破信念。
- **方法论的使用**：把异常当成模型边界信号，而不是立即加码追回。
- **结果与证据边界**：财务表现后来恢复，但认知转向承认模型只在有限环境中有效。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 准备把大量资金、时间或职业信用押在一个判断上
2. 连续成功后想加杠杆
3. 一次失败后想临时改规则
4. 需要把试错变成可复盘的重复系统

### 语言信号

- “这次机会太大，要不要全押”
- “我判断肯定对，仓位应该怎么上”
- “这次输了，要不要把规则反过来”
- “押错了我该怎么办”

## E — 可执行步骤（Execution）

1. **定义重复单元**
   - 完成标准：写出一次决策的输入、动作、结果窗口和可重复次数；若无法重复，标记为一次性决策。
   - 判停/转向：若不可重复且损失不可逆，停止使用本 skill，转人工审慎决策。
2. **画出出局线**
   - 完成标准：列出最大可承受损失、现金/时间跑道、关键人和流动性约束。
   - 判停/转向：任一合理压力情景会永久出局，则缩小暴露或不参与。
3. **写规则卡**
   - 完成标准：明确进入、仓位、加码、退出、复盘和模型失效条件，不留‘到时看感觉’字段。
   - 判停/转向：规则不足以约束最坏行为时，不进入下一步。
4. **做最小实测**
   - 完成标准：用不会伤筋动骨的规模获得至少一轮真实反馈，并记录预期与实际差异。
   - 判停/转向：不得用一次赢证明系统成立。
5. **按证据升级**
   - 完成标准：区分执行错误、随机波动和模型失配；只有适用域被推翻才整体换规则。
   - 判停/转向：若只能解释结果、不能说明事前条件，结论保持未知。

## B — 边界（Boundary）

### 不要在以下情况使用

- 违法、欺骗、医疗安全等不能靠多试几次来容错的行为
- 用户只要查价格、数据或定义
- 损失由无知情第三方承担的试错

### 作者在语料中警告的失败模式

- 只判断方向，不管理仓位与风险
- 因一局输赢临时改规则
- 连续顺利后热手加杠杆
- 把固定技巧当永久秘籍

### 作者盲点与证据局限

- 作者大量证据来自个人交易自述，缺少独立账目核验
- 金融隐喻不能自动迁移到人际、健康或公共伦理问题

### 统一安全边界

- 这是从公开文章中提炼的方法，不代表作者本人对新问题的真实意见。
- 不复制作者亲历，不冒充作者，不把自述案例当作独立核验事实。
- 涉及时效事实、法律、医疗或财务高风险问题时，先获取当前可靠资料并明确不确定性。
