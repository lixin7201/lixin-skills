# “由东”瓶颈与单位时间配置

## R — 原文（Reading）

> 高效的秘诀是什么？很简单，做事不由东，累死也无功。
>
> — 碧树西风，BXSF-108 · 2025-12-21

> 什么卡你，做什么，而不是什么简单，做什么。
>
> — 碧树西风，BXSF-115 · 2026-04-23

## I — 方法论骨架（Interpretation）

1. 忙碌不等于推进。先问当前结果真正由哪个变量、角色或约束控制，作者把这个支点称为‘由东’。
2. 优先级不是挑最简单、最熟悉或最有成就感的任务，而是解除当前唯一关键瓶颈。
3. 再把个人时间视为有机会成本的资源，比较亲做、委托、购买工具、删除和合法复用。
4. 瓶颈会随阶段改变；每解除一个约束，都要重新识别下一阶段的‘由东’。

## A1 — 语料中的应用（Past Application）

### 案例 1：从乙方琐事换到甲方服务决策者

- **问题**：作者自述被低价值答疑占满时间，随后更换服务对象和位置。
- **方法论的使用**：不是加速处理旧任务，而是改变决定职业结果的支点。
- **结果与证据边界**：后续升迁为作者自述。
### 案例 2：时间不足时改用历年真题

- **问题**：作者自述考研准备时间不足，没有从完整知识体系重学。
- **方法论的使用**：把过线作为当前结果，直接研究规则样本和评分要求。
- **结果与证据边界**：考取结果存在，但具体贡献无法拆分。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 任务很多但关键结果没变化
2. 在亲做和付费委托之间选择
3. 团队不知道先做哪个项目
4. 低价值事务占满稀缺时间

### 语言信号

- “我每天很忙，为什么还是没进展”
- “这些事情到底先做哪个”
- “这件事该自己学还是花钱”
- “什么才是真正卡住我的”

### 与相邻 skill 的区分

- 与 `choice-basis-three-question-audit` 的区别：先确认当前真正要什么，再识别控制结果的瓶颈。
- 与 `rules-player-to-game-designer` 的区别：当瓶颈来自流程或评价函数时，组合规则设计 skill。

## E — 可执行步骤（Execution）

1. **定义唯一结果**
   - 完成标准：写出当前阶段一个可衡量的最高优先结果和截止时间。
   - 判停/转向：同时追多个互斥结果时必须先排序。
2. **找控制支点**
   - 完成标准：列出导致结果变化的必要变量，并找当前最短板。
   - 判停/转向：只写‘努力不够’不算支点。
3. **给任务归因**
   - 完成标准：标注每个任务对瓶颈的直接作用、间接作用或无作用。
   - 判停/转向：无作用任务进入删除候选。
4. **计算单位时间**
   - 完成标准：比较亲做的机会成本与委托、工具、延期和删除的总成本。
   - 判停/转向：非商业关系不得只用钱衡量。
5. **执行并重识别**
   - 完成标准：集中资源解除首要瓶颈，达到阈值后重新跑一遍。
   - 判停/转向：瓶颈未动却持续优化旁支时停止。

### 边界路由规则

- 目标方向尚未形成时，仍由本 skill 触发第 1 步的前置诊断：要求定义唯一结果、受益对象、成功标准与期限；在这些条件未明确前停住，不伪造瓶颈，也不继续效率优化。

## B — 边界（Boundary）

### 不要在以下情况使用

- 用公司时间、设备或数据做未授权私事
- 把亲情、健康和尊严全部货币化
- 目标方向本身未审计时不得进入瓶颈排序，但应先完成结果定义

### 作者在语料中警告的失败模式

- 战术疲惫掩盖战略懒惰
- 训练方式与最终角色背离
- 意识到了却没有动作
- 洞察问题却不交付价值

### 作者盲点与证据局限

- 单位时间估值容易忽略照护、恢复和关系价值
- 个人效率无法替代组织资源不足或结构性不公

### 统一安全边界

- 这是从公开文章中提炼的方法，不代表作者本人对新问题的真实意见。
- 不复制作者亲历，不冒充作者，不把自述案例当作独立核验事实。
- 涉及时效事实、法律、医疗或财务高风险问题时，先获取当前可靠资料并明确不确定性。
