# 资料即产品 3W 连环画

## R — 原文 (Reading)

> "汇报的资料就是我们的产品。"
>
> — 户塚隆将，第五章

## I — 方法论骨架 (Interpretation)

资料不是把信息交差，而是一个读者要使用的产品。  
先用 3W 定义 Who、Why、What: 给谁看、为什么看、需要看什么。  
再把资料排成连环画式路径，让读者从背景、判断、证据到下一步自然读下去。  
最后用机械校对保护专业信任。  
它处理资料生产的读者路径和产品质量，不替代金字塔逻辑检查。

## A1 — 书中的应用 (Past Application)

### 案例 1: 前辈提醒资料就是产品
- **问题**: 咨询资料容易被当成内部文件。
- **方法论的使用**: 前辈提醒作者，汇报资料就是给客户的产品，不能从头到尾松懈。
- **结论**: 资料价值由客户理解和决策效果决定。
- **结果**: 作者把资料制作从格式工作转为产品交付。

### 案例 2: 细节错误被退回
- **问题**: 作者重做资料后仍因助词、格式等小错被退回。
- **方法论的使用**: 上司在空白处标注"注意细节"，强化最后校对。
- **结论**: 机械错误会破坏专业可信度。
- **结果**: 最后 5 分钟校对成为资料产品质量门。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 要给客户、上级或跨部门交资料，但不确定结构。
2. 周报、方案、PPT、会议材料内容很多，只是在堆信息。
3. 想让读者看完能理解、判断和行动。
4. 需要把资料从"我做了什么"改成"读者能用什么"。
5. 资料需要披露风险、限制或不确定性，但担心打断顺读路径。

### 语言信号

- "这份资料像堆信息"
- "客户周报怎么组织?"
- "Who/Why/What 怎么写?"
- "风险披露怎么放，能不能删?"
- "document as product / storyboard"

### 与相邻 skill 的区分

- `pyramid-slide-one-point-check` 检查单页是否一条完整论点；本 skill 检查整份资料的读者、目的、流程和质量。
- `conclusion-first-pyramid-report` 处理结论先行结构；本 skill 处理资料作为交付产品的生产流程。
- `presentation-action-change-brief` 处理现场演示希望听众发生的变化；本 skill 处理资料本身可读可用。

## E — 可执行步骤 (Execution)

1. **写 3W**
   - Who: 读者和决策者；Why: 读者为什么现在看；What: 读完要知道/决定/做什么。
   - 完成标准: 3W 能写在资料第一页备注或任务卡上。

2. **排连环画**
   - 按读者理解路径排列: 背景 -> 关键判断 -> 证据 -> 风险/选项 -> 下一步。
   - 判停条件: 若某页无法说明服务哪个读者动作，删掉或移入附录；若某段属于关键风险、限制或合规披露，不删除，只改位置和表达。
   - 完成标准: 每页都有主功能，并能顺读成一条线。

3. **做产品质检**
   - 检查数字、日期、单位、错字、格式、链接、附件和权限。
   - 完成标准: 最后 5 分钟机械校对完成，关键错误为 0。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 只检查一页 PPT 标题和图表关系时，优先单页金字塔 Skill。
- 资料目的还没有确定、听众行动目标不清时，先做演示行动目标定义。
- 涉及法律、财务、医疗、投资披露时，本 skill 只能做读者路径和披露边界检查，不能替代专业审查，且不能为了顺读删掉关键风险。

### 作者在书中警告的失败模式

- 把资料做成格式、颜色和信息堆叠，忽略读者是谁、为什么看、要看什么。

### 作者的盲点 / 时代局限

- 原书以传统商务资料为主，对异步协作文档、数据仪表盘和移动端材料需适配。
- 产品化资料不能演变成过度包装或隐藏不确定性。

### 容易混淆的邻近方法论

- 金字塔检查逻辑；3W 连环画检查读者路径。
- 资料产品化关注交付物质量，不等于演示现场说服。
