# 路由评估样例

这些样例用于验证路由边界，不是固定答案。输出可选择表中任一允许组合，但必须解释主角度，且只有一个写稿人。

| 场景 | 预期主稿型 | 允许的代表组合 | 必须避免 |
|---|---|---|---|
| 宜宾经济半年报，数据完整，无采访 | 城市发展或产业经济 | 芒格→大艳；张一鸣→刘润；张一鸣→36氪 | `renwu-skill`、人物采访、虚构市民场景 |
| 某路段下周封闭绕行 | 民生通知 | none→小美 | 强行调用名人、写成长评论 |
| 老学校拆除，有老照片和校友资料 | 城市记忆 | none→加菲；乔布斯→加菲 | 编造共同记忆、虚构校友原话 |
| 返乡创业者，有完整采访和时间线 | 人物/创业 | PG→甘甘；PG→《人物》；张一鸣→36氪 | 同时让三位写正文 |
| 新能源企业签约但尚未投产 | 产业经济 | 张一鸣→大艳；芒格→刘润；张一鸣→36氪 | 把签约写成投产或就业已兑现 |

| 本地荣誉只有一张模糊海报 | 本地荣誉但弱素材 | route-only / 补采清单 | 硬写完整发布稿、虚构奖项含金量 |

## 验收断言

1. “人物 skill”空白时不得回退 `renwu-skill`。
2. 信息通知允许人物为 `none`。
3. 任何组合必须只有一个正文写稿 Skill。
4. 外部写稿 Skill 被选中后，`wechat-writing-skill` 不再重写。
5. 素材不足时输出补采或降级，不靠名人观点填满长稿。
6. 正文不得暴露 Skill 名、路由过程、人物委员会或审稿分数。

## 软审校断言

1. `liurun-skill` 默认使用 `default-on`；审校问题必须退回刘润 Skill，不由审校 Skill 重写。
2. `renwu-skill` 使用 `guarded-on`；必须把人物温度、场景细节和关系推进列为保留项。
3. `li-xiaolai-skill` 使用 `suggested`；允许用户跳过。
4. `kazike-skill` 使用 `default-off`；只有假亲测、事实边界或结构问题命中时才启用。
5. `kepu-zhongguo-skill` 使用 `source-gated`；来源缺口未关闭时不得进入表达优化。
6. `app-skill` 只进入共享台账，不由本公众号 orchestrator 自动选为写稿人。
