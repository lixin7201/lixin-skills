# 生态位与价值链位置审计

## R — 原文（Reading）

> 生态系统里面有不同的生态位，每个生态位的门槛是不一样的。
>
> — 碧树西风，BXSF-045 · 2023-06-05

> 他自己的生态位，就不是利润增长点，他就没有前途，因为他的生态位是不断被技术发展蚕食的。
>
> — 碧树西风，BXSF-120 · 2026-07-02

## I — 方法论骨架（Interpretation）

1. 行业增长不等于价值链上的每个位置都增长。先问具体岗位或产品从哪里获得利润、议价权和资源。
2. 生态位由上下游关系、进入门槛、替代者和规则共同定义，不只是一个好听的行业标签。
3. 个人优势要放到能兑现的位置；拥有资源与能为具体目标调动资源是两回事。
4. 若当前位置持续被技术和制度蚕食，应迁移位置，而不是只在原位置加速执行。

## A1 — 语料中的应用（Past Application）

### 案例 1：IBM 工程师判断生态位迁移

- **问题**：作者转述一位工程师从社会分工结构判断司机等生态位会转移而非消失。
- **方法论的使用**：关注需求功能和位置迁移，不押具体产品名称。
- **结果与证据边界**：后续吻合是作者评价，缺少独立收益验证。
### 案例 2：技术全栈却走不到管理目标

- **问题**：作者用同事逐层练技术的计划说明训练与目标位置错配。
- **方法论的使用**：管理位置需要承担结果、组织资源和靠近决策，不会由执行技能自动兑换。
- **结果与证据边界**：原文未给出当事人最终结果。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 行业热门但个人回报差
2. 岗位面临自动化
3. 比较乙方/甲方或上下游位置
4. 决定把稀缺能力放在哪个场景

### 语言信号

- “这个行业这么重要，为什么工资还低”
- “AI 会不会替代我的岗位”
- “我要不要从乙方去甲方”
- “我的优势到底放在哪里值钱”

### 与相邻 skill 的区分

- 与 `ability-demand-leverage-path` 的区别：本 skill 定位价值链位置；后者检查能力、需求和杠杆是否闭环。
- 与 `cycle-endgame-optionality-map` 的区别：当前位置还要放入更大的技术、行业与职业周期复核。

## E — 可执行步骤（Execution）

1. **画价值链**
   - 完成标准：列出谁创造、分配、定价、购买和承担风险。
   - 判停/转向：只写行业名称不算完成。
2. **定位当前位置**
   - 完成标准：说明自己的交付、服务对象、议价权、资源调用权和被替代方式。
   - 判停/转向：无法解释价值如何兑现时标记为弱位置。
3. **查利润与门槛**
   - 完成标准：找出利润增长点、进入门槛、规则控制者和门槛迁移方向。
   - 判停/转向：用当前数据核验，不能沿用旧时代标签。
4. **比较相对优势**
   - 完成标准：把能力、关系、资产等相对稀缺项放入不同位置，比较可兑现程度。
   - 判停/转向：优势没有真实需求时不计入。
5. **设计迁移**
   - 完成标准：选择能提高议价、资源调用或问题定义权的邻近位置，并给出最小验证。
   - 判停/转向：迁移成本会令家庭或现金流出局时先建跑道。

## B — 边界（Boundary）

### 不要在以下情况使用

- 用职业和阶层标签判断人的尊严
- 没有时效数据却给出具体行业结论
- 把所有合作简化成弱肉强食

### 作者在语料中警告的失败模式

- 把短期发薪误认岗位稳定
- 复制旧成功路径不追溯供需
- 只看行业而不看所在位置
- 洞察不能转成可交换价值

### 作者盲点与证据局限

- 生态隐喻容易过度竞争化并弱化公共制度与合作价值
- 作者对部分行业位置的判断是时效性观点，不是永恒规律

### 统一安全边界

- 这是从公开文章中提炼的方法，不代表作者本人对新问题的真实意见。
- 不复制作者亲历，不冒充作者，不把自述案例当作独立核验事实。
- 涉及时效事实、法律、医疗或财务高风险问题时，先获取当前可靠资料并明确不确定性。
