# 能力—需求—杠杆路径诊断

## R — 原文（Reading）

> 赚钱这件事，拆开看，和能力，需求，杠杆三个要素相关
>
> — 碧树西风，BXSF-115 · 2026-04-23

> 当你能力有，需求也有的时候，才轮到杠杆的事儿。
>
> — 碧树西风，BXSF-115 · 2026-04-23

## I — 方法论骨架（Interpretation）

1. 回报问题先拆成三个变量：能否稳定交付、是否存在真实需求、是否有放大机制。
2. 能力或需求为零时，杠杆只会放大零收益、亏损或声量幻觉。
3. 再区分回报来自环境窗口的 Beta，还是来自个人稀缺性的 Alpha；两条路需要不同训练周期和退出纪律。
4. 第一步必须是自身资源够得着的真实支点，用小交付验证，而不是复制强者的成熟位置。

## A1 — 语料中的应用（Past Application）

### 案例 1：有正预期但没有规模价值的原型

- **问题**：作者自述用小资金策略证明可行，却很快算出容量太小。
- **方法论的使用**：把可行性、需求容量和杠杆分开，不把能做等同值得做大。
- **结果与证据边界**：金额、算法与收益均未外部核验。
### 案例 2：技术训练与管理目标错位

- **问题**：作者转述同事计划练满全部技术再成为总监。
- **方法论的使用**：能力必须与目标需求一致，执行深度不能自动变成组织杠杆。
- **结果与证据边界**：当事人最终结果未知。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 想做副业或产品但不知道先学还是先卖
2. 有技能却没人付费
3. 想招人、融资或做平台放大
4. 需要区分追风口与建长期优势

### 语言信号

- “我会这个，怎么才能变现”
- “先做产品还是先找客户”
- “是不是加大投放就能做起来”
- “我要赚 Alpha 还是 Beta 的钱”

### 与相邻 skill 的区分

- 与 `ecological-niche-value-chain-audit` 的区别：路径诊断前先确认需求和利润究竟落在哪个位置。
- 与 `explore-exploit-transition-ladder` 的区别：路径候选成立后，用探索钉子取得真实需求与增长证据。

## E — 可执行步骤（Execution）

1. **定义最小能力**
   - 完成标准：写出可独立交付、可验收的最小结果及过去证据。
   - 判停/转向：只能描述知识、不能交付结果时，能力未验证。
2. **验证真实需求**
   - 完成标准：找到具体付费者、痛点、替代方案和愿意付出的成本。
   - 判停/转向：只靠点赞、访谈礼貌或个人热情时不算需求。
3. **判断回报类型**
   - 完成标准：说明收益主要来自窗口/择时 Beta，还是长期稀缺能力 Alpha。
   - 判停/转向：无法区分时先用小实验，不做长期重投入。
4. **选择够得着的支点**
   - 完成标准：用现有资金、身份、关系和可承受损失设计第一单/第一个原型。
   - 判停/转向：起点依赖尚不存在的资源时重做。
5. **通过杠杆门**
   - 完成标准：只有能力和需求都验证后，才比较平台、资金、团队、代码和内容杠杆。
   - 判停/转向：杠杆扩大投诉或亏损时立即停止。

### 边界路由规则

- 非商业、公益或开源项目也可触发本 skill，但要把‘需求’改写为受益者、真实使用和公共价值，把‘回报’改写为使命效果或持续性；不得强加赚钱指标，未有放大需要时跳过杠杆步骤。

## B — 边界（Boundary）

### 不要在以下情况使用

- 承诺具体财富结果
- 把兴趣或社会热点直接当需求
- 能力和需求未验证就融资、雇人或高投放

### 作者在语料中警告的失败模式

- 自我评估在自负与自卑间摆动
- 把一次赚钱等同长期有钱
- 复制标签不追溯供需条件
- 洞察不转成价值

### 作者盲点与证据局限

- 作者强调市场交换，可能低估公共价值、照护和非商业目标
- Alpha/Beta 类比来自投资，迁移到职业时只能作路径分类

### 统一安全边界

- 这是从公开文章中提炼的方法，不代表作者本人对新问题的真实意见。
- 不复制作者亲历，不冒充作者，不把自述案例当作独立核验事实。
- 涉及时效事实、法律、医疗或财务高风险问题时，先获取当前可靠资料并明确不确定性。
