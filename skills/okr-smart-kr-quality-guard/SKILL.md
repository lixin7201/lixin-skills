# OKR/SMART 目标与 KR 质量护栏

## R — 原文 (Reading)

> "目标要明确方向并且鼓舞人心。"
>
> — 《OKR工作管理法培训PPT》，提取文本行 226-228

> "也许你制定的KR是好意，但是却产生了反结果。"
>
> — 《OKR工作管理法培训PPT》，提取文本行 244

> "目标不明确就没有办法评判、衡量与执行！"
>
> — 《SMART目标管理培训PPT》，提取文本行 101-102

## I — 方法论骨架 (Interpretation)

一个目标不是因为写了数字就变好，也不是因为口号漂亮就值得执行。
O 需要指出重要方向、鼓舞团队、设定期限、聚焦并由独立团队负责。
KR 需要高远、可衡量、能查看进展，并且推动正确行为。
SMART 提供底层语言护栏：具体、可衡量、相关、可达成、期限清楚。
但 OKR 与 SMART 有张力：探索型目标需要挑战性，稳定型目标更需要可达成。
最危险的是单一指标诱发坏行为，比如为了通话时长而挂断客户电话。
这个 Skill 的作用是把目标从口号/任务/坏指标，改成可验证、能推进真实价值、带反向激励护栏的 O/KR。

## A1 — 资料中的应用 (Past Application)

### 案例 1: 客服 6 分钟 KR 的反向激励

- **问题**: 公司给客服制定"六分钟内处理好客户问题"的 KR。
- **方法论的使用**: PPT 指出该 KR 看似可衡量，却会让客服在接近 6 分钟时主动挂断电话重新计时。
- **结论**: KR 必须推动正确行为，不能只追求一个好看的数字。
- **结果**: 资料建议增加客户满意度等辅助 KR，降低负面影响。

### 案例 2: 模糊卫生目标无法执行

- **问题**: "按时检查卫生，保持公司清洁"看似合理，却没有说明检查范围、频率和清洁标准。
- **方法论的使用**: SMART 要求用具体语言和明确数据作为衡量依据。
- **结论**: 目标不明确就无法评判、衡量和执行。
- **结果**: 模糊目标需要重写为具体对象、标准、频率、负责人和验收方式。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户已经有 O/KR 草案，需要判断是否像目标、是否像 KR、是否能推动正确行为。
2. 目标只有"提升、加强、优化、打造"等词，没有具体对象、期限和衡量口径。
3. KR 是行动清单，例如"开会 3 次、发文 10 篇"，但没有结果指标。
4. 指标很清楚，却可能诱发刷量、挂断、压低质量、牺牲长期信任等坏行为。
5. 团队在 SMART 的可达成和 OKR 的挑战性之间摇摆，需要按稳定型/探索型目标分流。

### 语言信号

- "帮我改写这个 OKR"
- "这个 KR 好不好"
- "目标太虚/太泛/像口号"
- "这个指标会不会带来副作用"
- "SMART goal / bad metric / metric guardrail / key result quality"

### 与相邻 skill 的区分

- 与 `okr-fit-preflight` 的区别: 先判断是否适合用 OKR；本 skill 只在决定使用目标/OKR 后检查质量。
- 与 `written-clarity-action-planner` 的区别: 行动计划写任务和时间块；本 skill 不把行动当 KR，而是检查目标和结果证据。
- 与 `reasoned-threshold-action` 的区别: 阈值行动用于决定坚持到什么证据才调整；本 skill 可与其组合，为 KR 设进度阈值和停止条件。

## E — 可执行步骤 (Execution)

1. **确认前提和目标类型**
   - 判断目标是否已经通过 OKR 适用性预检；标注稳定型、探索型或混合型。
   - 完成标准: 能说明为什么用 OKR/目标管理，而不是 KPI、PDCA 或普通计划。
   - 判停条件: 如果用户还没判断是否该导入 OKR，先转 `okr-fit-preflight`。

2. **拆分 O、KR、行动**
   - 把草案中的方向性目标、结果指标、行动任务分开。
   - 完成标准: O 回答方向，KR 回答结果证据，行动回答怎么做。

3. **检查 O 的质量**
   - 检查是否方向明确、重要、有期限、聚焦、鼓舞、由清晰团队负责。
   - 完成标准: O 不超过 1 个主要方向，能让团队判断什么事该做、什么事该放下。

4. **检查 KR 的质量**
   - 检查 KR 是否高远/可达成匹配目标类型、可衡量、可追踪进展、可影响而非纯外部结果。
   - 完成标准: 每个 KR 有指标定义、周期、基线、目标值、数据来源和更新频率。

5. **做反向激励审计**
   - 对每个 KR 问: 为了达成它，团队可能做出什么坏行为。
   - 完成标准: 至少列出 2 个副作用，并为高风险副作用设置辅助 KR 或质量护栏。

6. **按 SMART 补齐清晰度**
   - 补具体对象、衡量标准、相关性、资源约束、完成期限和验收人。
   - 完成标准: 考核者与执行者能用同一把尺子判断完成与否。

7. **输出改写版本和复盘方式**
   - 输出原问题、改写 O、改写 KR、行动不写入 KR 的提醒、坏行为护栏、周期复盘问题。
   - 完成标准: 用户能直接拿去评审，并知道何时调整目标或停止指标。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户还没决定是否应该使用 OKR，先做 `okr-fit-preflight`。
- 用户只是要把一个任务写清楚，而不是评审目标和结果指标。
- 用户要求用单一数字绑定奖惩，且拒绝质量护栏时，不应继续包装成 OKR。
- 目标涉及法律、医疗、安全、财务重大责任时，本 skill 不替代专业风控。

### 资料中警告的失败模式

- 目标模棱两可，相关成员无法准确理解。
- 衡量口径含糊，如"基本达成"，导致完成标准不可判定。
- 目标与岗位、部门或公司整体运营无关，达成也没有意义。
- 指标好意但产生反结果，例如客服为满足 6 分钟通话 KR 主动挂断电话。
- 目标过窄或过宽，脱离资源特长和可实现性。

### 来源局限

- 两份来源均为培训 PPT，未标注作者；应作为目标质量工具而非权威绩效制度。
- SMART 与 OKR 对"可达成/挑战性"存在张力，不能强行合并，必须按目标类型处理。

### 复盘方式

- 周期中复查 KR 是否仍代表真实价值，而不是只代表容易刷的数字。
- 检查是否出现副作用信号；出现后优先修 KR 或添加护栏。
- 周期末分别复盘 O 是否聚焦、KR 是否可证据化、行动是否误写成 KR。
