# 目标管理副作用审计

## R — 原文 (Reading)

> 没有绝对客观、公正的奖惩。往往强调短期目标而忽略长期发展。关注自身目标而忽略整体，助长本位主义。
>
> — 《工作计划目标管理培训》Slide 18

> 要通过对目标完成情况的检查和奖惩，来确保目标的实现。
>
> — 《工作计划目标管理培训》Slide 17

> 目标实施的环境、条件、资源等发生了变化，那么，要根据实际情况对目标进行调整和反馈。
>
> — 《工作计划目标管理培训》Slide 26

## I — 方法论骨架 (Interpretation)

目标管理能让组织对齐方向、分解责任、检查结果，但它也会改变人的行为。
只要目标和奖惩绑定，人们就会优化被看见、被记录、被奖励的部分。
这不一定是坏事，但如果目标设置过窄、周期过短、奖惩口径不公或局部目标缺少整体护栏，制度会诱发短期化、本位主义和指标游戏。
所以目标管理不是写完目标就结束，而要在入口处审计副作用。
审计的重点不是反对目标，而是判断目标制度会把人推向什么行为。
好的结果不是“取消所有指标”，而是在保留方向感的同时补上质量护栏、长期指标、协作约束、资源边界、试点反馈和调整机制。

## A1 — 书中的应用 (Past Application)

### 案例 1: 家庭奖励约定暴露奖惩机制

- **问题**: PPT 用父亲承诺旅行奖励激励女儿考班级第一，说明日常生活中也会使用目标管理。
- **方法论的使用**: 先给出清晰结果，再通过奖赏强化行动动机。
- **结论**: 奖惩能让目标被关注，但也提示正式组织中必须审计奖惩是否公平、目标是否可控、是否牺牲长期发展。
- **结果**: 文本没有交代考试结果，因此该例只能说明激励机制存在，不能证明奖惩一定有效或公正。

### 案例 2: 目标管理好处和缺憾并列

- **问题**: 资料既列出目标管理能提高效率、监督控制和评价员工，又主动列出目标难定、奖惩不公、短期化和本位主义。
- **方法论的使用**: 把目标管理当成双刃剑：设计目标制度时同步检查好处与副作用。
- **结论**: 目标制度越清晰，越要防止被清晰的指标牵引到错误行为。
- **结果**: 形成一个正式审计入口：目标是否难以合理制定、商定成本是否过高、奖惩是否会被当成绝对公正、短期目标是否吞噬长期发展、局部目标是否伤害整体。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 团队准备把某个目标、KPI、排名、奖金、绩效考核或承诺强绑定到奖惩。
2. 短期指标提升了，但客户体验、产品质量、协作关系、长期能力或员工行为变差。
3. 每个部门都达标，但整体交付变慢、用户价值变差或跨部门推诿增加。
4. 员工质疑目标不公平、不可控、资源差异大，或者目标协商长期消耗执行时间。
5. 创业团队、内容团队、销售团队或客服团队想设目标，但担心用错指标把行为带偏。

### 语言信号

- "这个 KPI 会不会有副作用"
- "目标完成了但质量下降"
- "按数量排名发奖金出了问题"
- "每个部门都达标，整体反而变差"
- "目标管理短期化、本位主义、奖惩不公"
- "incentive risk / KPI gaming / short-termism / silo optimization"

### 与相邻 skill 的区分

- 与 `pre-smart-goal-worthiness-audit` 的关系: 先用它判断目标是否值得承诺；若目标进入制度、奖惩或多人协作，再用本 Skill 审计行为副作用。
- 与 `kgi-kpi-causal-tree-validity-check` 的区别: 该 Skill 检查 KGI/KPI 因果关系和指标有效性；本 Skill 检查目标制度会不会诱发扭曲行为。
- 与 `okr-smart-kr-quality-guard` 的区别: 该 Skill 检查目标和 KR 的文字质量、坏指标和衡量口径；本 Skill 检查参与、奖惩、公平、短期化和本位主义。
- 与 `firefighting-to-standard-improvement-loop` 的区别: 该 Skill 处理稳定流程反复出问题后的 PDCA/SOP；本 Skill 处理目标制度本身造成的新问题。

## E — 可执行步骤 (Execution)

1. **界定目标制度**
   - 操作: 写下目标、指标、周期、适用对象、奖惩方式、数据来源、考核口径和最终决策人。
   - 完成标准: 能说清这个目标会影响谁、奖励谁、惩罚谁、要求谁改变行为。
   - 停止条件: 若只是单个个人目标且不涉及奖惩或多人协作，优先使用目标预检或行动规划类 Skill。

2. **检查目标制定前提**
   - 操作: 判断目标是否可合理制定、参与者是否理解和认可、权责资源是否匹配、目标是否可观察。
   - 完成标准: 每个前提都有证据、待确认项或风险标记。
   - 判停条件: 如果目标无法合理定义或资源权责严重不匹配，先回到 `pre-smart-goal-worthiness-audit` 修目标。

3. **审计五类副作用**
   - 操作: 逐项检查制定难度、协商成本、奖惩公正幻觉、短期化、本位主义。
   - 完成标准: 每类副作用都有“低/中/高”风险判断、触发证据和预警信号。
   - 判停条件: 如果任一高风险副作用已经出现且会伤害客户、安全、合规或组织信任，暂停奖惩绑定，先试点或补护栏。

4. **补整体价值和质量护栏**
   - 操作: 为数量目标补质量指标，为个人目标补协作约束，为短期目标补长期能力或客户价值指标。
   - 完成标准: 每个目标至少有一个防止局部优化的护栏，且护栏可以被检查。

5. **设计反馈和调整机制**
   - 操作: 设定试点周期、复查时间、数据复核人、申诉/解释入口、资源变化后的目标调整规则。
   - 完成标准: 目标制度不是一次性硬推，而有 PDCA 式反馈和调整窗口。

6. **输出处理结论**
   - 操作: 在“保留、修改、加护栏、先试点、暂停/停止”五类结论中选择，并写明理由。
   - 完成标准: 用户拿到一份目标副作用审计表，包含风险、护栏、试点方式、复查点和未解决问题。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只是要把一个目标写得更具体、更可衡量或更像 OKR。
- 用户需要正式薪酬制度设计、劳动关系处理、法律合规判断或绩效处罚建议。
- 指标问题主要是因果链不成立，应优先用 `kgi-kpi-causal-tree-validity-check`。
- 问题已经是稳定流程反复复发，应转入 `firefighting-to-standard-improvement-loop`。

### 作者在资料中警告的失败模式

- 目标难以制定却硬套目标管理，造成形式化对齐。
- 目标商定成本吞噬执行，会议反复修改口径和责任边界。
- 奖惩客观公正幻觉，忽略资源差异、协作贡献和不可控因素。
- 短期目标吞噬长期发展。
- 个人或部门指标助长本位主义。
- 条件变化后不反馈调整，目标制度变成僵化约束。

### 来源局限

- 来源是作者未标注的培训 PPT，未提供真实绩效制度数据或长期组织研究。
- 资料偏管理方视角，对员工权益、申诉机制和权力不对等展开不足。
- 本 Skill 只能做管理风险审计，不能替代专业组织咨询、薪酬顾问、劳动法或合规判断。

### 复盘方式

- 目标运行 1 个周期后，检查副作用预警信号是否出现：质量下降、协作变差、申诉增多、短期行为上升。
- 对比目标完成率与客户价值、长期能力、跨部门协作和员工信任，不只看完成率。
- 若副作用来自指标因果关系错误，转 `kgi-kpi-causal-tree-validity-check`；若来自流程复发，转 PDCA/SOP 改进。
