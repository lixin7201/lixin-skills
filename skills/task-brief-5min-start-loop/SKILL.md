# 接任务当场确认与 5 分钟进程安排

## R — 原文 (Reading)

> "接到工作任务后，5分钟内马上开始安排进程。"
>
> — 户塚隆将，第四章

## I — 方法论骨架 (Interpretation)

这个方法只管任务进入手里的前 5 分钟。  
先不要装懂，也不要埋头搜索资料；当场确认任务的目的、背景、截止时间、输出形式、判断标准和疑点。  
回到座位后，趁上下文还热，用 5 分钟拆进程、估工期、列缺口、决定第一次回报节点。  
它把任务从"悬空"变成"可控"，降低中途返工和最后一刻才发现理解错的概率。

## A1 — 书中的应用 (Past Application)

### 案例 1: 忙乱时先整理眼前任务
- **问题**: 作者被多项工作压住，越急越失去判断。
- **方法论的使用**: 前辈把眼前该做的事列成一张纸，让作者先停下来整理。
- **结论**: 忙乱时第一步不是继续冲，而是让任务可见、可排、可问。
- **结果**: 作者学会在任务压力下先建立进程，而不是被压力拖走。

### 案例 2: 接任务后当场确认
- **问题**: 任务刚到手时，最容易因怕麻烦而不问清楚。
- **方法论的使用**: 作者强调接到任务当场确认任务信息，并立刻用 5 分钟制订计划。
- **结论**: 当场确认比事后补问成本低。
- **结果**: 疑点提前暴露，返工减少。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 刚收到一个任务，但不知道要交什么、交给谁、何时交。
2. 老板/客户说得很快，用户想先做又担心理解错。
3. 任务很多，用户开始焦虑，不知道先拆哪一步。
4. 要把口头指令转成可执行任务卡。

### 语言信号

- "老板刚让我做一份..."
- "这个任务没说清楚，我要先问什么?"
- "我是不是先开始搜资料?"
- "task brief / clarify assignment"

### 与相邻 skill 的区分

- `planning-and-task-breakdown` 用于完整计划拆解；本 skill 只处理接任务前 5 分钟的澄清和启动。
- `proactive-hypothesis-upward-report` 用于任务进行中向上同步；本 skill 用于任务刚进入时。

## E — 可执行步骤 (Execution)

1. **当场确认六件事**
   - 目的、使用者、截止时间、输出格式、范围边界、成功标准。
   - 完成标准: 能用一句话复述"为谁在何时交付什么，用来决定什么"。

2. **5 分钟启动进程**
   - 写出步骤、预计耗时、已知资料、未知疑点、第一次同步时间。
   - 判停条件: 若目的/输出/截止任一项不明，先回问，不进入执行。
   - 完成标准: 形成一个 5-8 行任务卡。

3. **发出确认**
   - 用短消息向交办者确认理解和下一次同步点。
   - 完成标准: 对方确认或未反对，任务进入执行队列。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 任务已经明确且进入长期执行，需要项目计划、里程碑或风险管理。
- 指令涉及违法、隐私泄露、虚假材料或越权承诺时，先升级合规边界。
- 上级只是在探索想法，尚未形成任务时，先做讨论目标路由。

### 作者在书中警告的失败模式

- 接到任务后先放一边，等真正要做时才发现目的、样例、期限和疑点不清。

### 作者的盲点 / 时代局限

- 本书源于高压精英职场，可能低估远程异步协作、跨时区沟通和劳动边界。
- 不能把"快速启动"变成默认加班或即时响应义务。

### 容易混淆的邻近方法论

- 向上汇报是中期校准；5 分钟启动是入口澄清。
- 全链审计检查整个行动链；本 skill 不承担完整策略判断。
