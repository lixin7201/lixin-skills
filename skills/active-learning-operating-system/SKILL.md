# 主动学习操作系统

## R — 原文 (Reading)

> “看见自己（）”“自学（）”“重构（）”是三个最基本的算法。
>
> — 姜胡说，第一章、第二十三章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

先描述真实输出，识别最低必要知识，做出可运行版本，收集错误，再重构自己的方法和判断边界。

它的独特性在于：把主动学习解释为安装并升级个人操作系统，而不是增加知识量，具有明确的三算法和反馈闭环。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 边学边做出公司网站并完成全网接入
- **问题**: 作者在没有网站建设经验的情况下买书自学，用约一个月做出公司网站；此后继续承担新技术工作，完成单位全部子公司和项目部接入互联网。
- **方法论的使用**: 这是“先完成最小闭环，再在真实任务中升级能力”的早期实例。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 网站约一个月完成；1999—2000年单位全部下属子公司、项目部接入互联网。

### 案例 2: C#学习笔记带来代码外快和讲师工作
- **问题**: 作者自学微软测试版语言Cool（后来的C#），持续把学习笔记公开到论坛。
- **方法论的使用**: 内容先带来编程外快，随后又让一家中科院下属公司邀请他给初学者授课。 案例展示“输入—公开输出—被看见—机会”的完整链路。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 获得代码外快，并从北大旁听转为中科院计算所下属单位的C#培训讲师。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **定义真实输出**
   - 完成标准: 明确要交付的作品、行为或可运行结果

2. **识别最小知识**
   - 完成标准: 只列完成第一版所需的知识缺口和来源
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **边学边做**
   - 完成标准: 在最短周期内交付可运行版本并暴露错误

4. **反馈重构**
   - 完成标准: 根据错误修改方法、边界和下一轮练习，而非只增加阅读量

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单纯查一个事实、只想收藏资料，或需要持证专业人士直接处置的高风险问题。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 用学历、听课或参加培训代替理解、实践和能力形成。 外部教学只能提供输入；学习者若不主动思考和调用，知识不会转化为可运行能力。

### 作者的盲点 / 时代局限

- 主动学习不等于拒绝教学；高风险领域仍需要合格导师、标准和监督。

### 容易混淆的邻近方法论

- `rapid-book-survey` 与 `atomic-output-recomposition`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
