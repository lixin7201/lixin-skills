# 结论-理由-事实接收信息审计

## R — 原文 (Reading)

> 被动地接受大量的复杂信息。这时，就需要用结构化思维的方式来对信息进行高效识别。
>
> — 《有效训练你的结构化思维》Slides 13-18, lines 107-161

> 事实和理由，理由和结论之间要有证明和被证明的逻辑关系。
>
> — 《有效训练你的结构化思维》Slides 17-18, lines 153-161

## I — 方法论骨架 (Interpretation)

这个 skill 处理的是“输入侧”的结构化审计。别人给出一段话时，agent 不急着接受或反驳，而是先把话拆成三层：结论、理由、事实。

结论是对方真正想让你接受的观点；理由是他用来支持结论的解释；事实是可以被观察、记录、数据或原始材料支撑的东西。只有事实支撑理由、理由支撑结论，信息链才算可信。

这个方法的价值不是挑刺，而是把模糊的不信任转成明确追问：哪个结论没有理由，哪个理由没有事实，哪个事实还没核验。

## A1 — 书中的应用 (Past Application)

### 案例 1: 电脑业务汇报

- **问题**: 下属说电脑市场占有率上升但收益降低，因为竞争激烈只能低价竞争，所以利润率下降没有办法。
- **方法论的使用**: 先标出结论“利润率下降没办法”，再标出理由“竞争激烈、只能低价竞争”，最后找事实“市场占有率上升、收益降低”。
- **结论**: 原话里有事实、理由、结论，但仍要检查竞争激烈和低价竞争是否有数据证明，以及是否存在其他原因。
- **结果**: 汇报从“听起来有道理”变成可追问的证据链。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 对方给了一段汇报、解释、客户反馈、销售话术或会议结论，用户感觉不踏实。
2. 用户要判断某个观点是不是由证据支持，而不是只被措辞说服。
3. 用户准备开会追问，但不知道该问事实、理由还是结论。
4. 用户拿到一段复杂信息，需要快速拆出可信部分和假设部分。

### 语言信号

- “他说得对吗？”
- “帮我拆一下这段汇报的逻辑”
- “这里哪些是事实，哪些只是判断？”
- “claim / reason / fact audit”

### 与相邻 skill 的区分

- 与 `primary-source-fact-grounding` 的区别: 本 skill 先拆信息链；如果事实本身来源不清，再转原始资料核验。
- 与 `conclusion-first-pyramid-report` 的区别: 本 skill 审计别人输入；金字塔 skill 组织自己输出。

## E — 可执行步骤 (Execution)

1. **摘出结论**
   - 完成标准: 写出对方最希望用户接受的 1-3 个中心判断；没有明确结论时，用“待澄清结论”标记。

2. **摘出理由**
   - 完成标准: 每个结论下面列出对应理由；没有理由的结论标记为“裸结论”。

3. **摘出事实**
   - 完成标准: 每个理由下面列出可观察、可记录、可核验的事实；主观形容词不能当事实。

4. **检查证明链**
   - 完成标准: 对每条链标注“事实足够 / 事实不足 / 理由不推出结论 / 需要原始资料核验”。
   - 判停条件: 如果关键事实来源不明且影响重大，停止判断，转 `primary-source-fact-grounding`。

5. **输出追问清单**
   - 完成标准: 给出最少 3 条、最多 7 条追问，明确每条追问要补事实、补理由还是重述结论。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户要写一份汇报、方案或演讲结构，应使用表达/金字塔类 skill。
- 用户已经有原始数据和来源核验任务，应直接使用事实接地类 skill。
- 高风险法律、医疗、投资、合规判断不能只靠话术拆解得出结论。

### 作者在书中警告的失败模式

- 把理由当事实，把主观解释当客观证据。
- 只听到结论，没有检查事实和理由之间是否真的能证明。

### 作者的盲点 / 时代局限

- PPT 主要讲信息识别，没有展开不同组织权力关系下“追问成本”的处理；实际使用时要注意场合、关系和留痕。

### 容易混淆的邻近方法论

- 如果任务是“怎么把自己的观点讲清楚”，转 `conclusion-first-pyramid-report` 或表达类 skill。
- 如果任务是“这份资料真假如何”，转 `primary-source-fact-grounding`。

## 相关 skills
