# 大宜宾内容审稿 Skill（加菲培训版）

> 来源：中台部门加菲提供的内部培训材料，以及中台部/运营部知识库中的选题判断与审稿SOP、公众号AI味黑名单、正文分型规则、1000篇公众号数据分析、资深审稿官notes。
> 用途：写好稿子后过一遍，检查是否合格、哪里要改、怎么改

---

## 一、输入要求

用户调用本 skill 时，至少提供：
1. **稿件内容**（标题 + 正文，必须完整）
2. **发布渠道**（可选）：`APP` / `微信订阅号` / `不确定`
3. **指定人设**（可选）：`练团长` / `泡泡` / `流浪` / `离心-APP态` / `加菲` / `未指定`
4. **素材来源**（可选）：原创 / 转载 / 整合 / 热点改写
5. **题材类型**（可选）：民生通知 / 城建交通 / 打卡攻略 / 情怀记忆 / 人物故事 / 家乡被看见 / 冲突讨论 / 活动宣传 / 不确定
6. **预期形态**（可选）：APP短帖 / 公众号完整稿 / 头条稿 / 98分候选 / 短提醒 / 练习稿

如果用户只给了标题和正文，默认按通用稿件审查；如果给了渠道或人设，按对应标准加重审查。

---

## 二、审稿流程与核心维度

### 审稿前置判断：先判这稿子该不该这样写

正式打分前，先用 4 个问题做前置判断；前置判断不过，不要只改语病。

| 问题 | 通过信号 | 失败处理 |
|---|---|---|
| 用户会 care 吗？ | 能说清这件事影响哪类宜宾人、对应什么生活场景 | 记为核心角度问题；建议重定角度或降级处理 |
| 能引发互动吗？ | 有明确评论、转发、收藏或行动理由 | APP稿缺互动点时不得判高分 |
| 我们能独特地说吗？ | 有本地视角、现场细节、用户翻译或大宜宾判断 | 纯搬运/纯通稿只可条件通过或建议重写 |
| 渠道写对了吗？ | APP快、短、直给、能讨论；公众号完整、解释清楚、可沉淀 | 渠道错配时先改渠道策略，再改正文 |

### 选题优先级与渠道路由

- **P0 必做**：大民生、突发、独家、强本地讨论，优先抢速度和准确性。
- **P1 速做**：有明确互动点，信息较完整，当天快速发。
- **P2 缓做**：可做可不做，缺一点讨论性，进入候选池或合集。
- **P3 放弃/降级**：纯搬运、纯政务、无互动、无本地感，不要硬写成重点稿。
- **APP 适合**：讨论型、情绪型、冲突感更强、更口语、更容易引发评论和站队的内容。
- **公众号适合**：信息整合型、服务型、解释型、背景补充型、适合转发和沉淀的内容。

前置判断要写进审稿报告的“基础信息”或“核心问题”。如果素材本身 P3，却被写成头条稿或 98 分候选，综合评分最高 8.6/10。

### 维度1：标题审查（基于加菲"一个好标题的诞生"）

#### 1.1 标题9条实操规则（逐条检查）
| 序号 | 检查项 | 问题示例 |
|-----|--------|---------|
| 1 | 是否至少提炼了3个看点？ | 标题平淡，只有一个信息点 |
| 2 | 前10个字是否出现至少1个看点？ | 前10个字全是铺垫词，如"关于宜宾…" |
| 3 | 标题是否尽量短？ | 超过36字，或在朋友圈显示不完整 |
| 4 | 是否有画面感？ | 全是抽象词，如"发展""建设""推进" |
| 5 | 是否有代入感？ | 用户读完不觉得"这跟我有关" |
| 6 | 是否保持一定讨论性/争议性？ | 封闭式陈述，没有讨论空间 |
| 7 | 是否所有人都看得懂，少用专业术语？ | 出现生僻词、官话、行业黑话 |
| 8 | 是否尽量使用阿拉伯数字？ | 用中文数字，或该有数字的地方没数字 |
| 9 | 是否用前缀定基调？ | 没有情绪引导词，太平淡 |

#### 1.2 标题5个爆点法则（至少中2条为佳）
- [ ] **爆点人物**：有无名人、热点人物、权威机构关联？
- [ ] **共鸣话题**：是否击中普遍关心或容易站队的议题？
- [ ] **痛点字词**：是否包含拆迁、医院、物价、出租车、婆婆、豪车、具体金额等高关注词？
- [ ] **时下热词**：是否借用当前互联网热词或语境？
- [ ] **颠覆认知点**：是否包含与用户日常经验相反的冲突信息？

#### 1.3 标题8个补充技巧
- [ ] 是否一眼看得懂？（多用短句，少用复杂长句）
- [ ] 是否多用"你、我"？
- [ ] 是否"露大腿不露底裤"？（半遮半掩，有好奇心钩子）
- [ ] 标题是否尽量短且显示完整？（头条≤32字，其他条≤29字）
- [ ] 是否兼顾点击和分享？（不会让用户不好意思分享）
- [ ] 是否兼顾点击和转化？（不是为了流量而流量）
- [ ] 是否经过打磨？（不是随手一写）
- [ ] 是否做了5点优化：阿拉伯数字、避免重复词、精彩部分前置、删除不痛不痒的词、尝试疑问句？

#### 1.4 标题方法论审查（基于10个实战案例）
- [ ] **数字具体化**：是否用精确数字替代了"很多""不久""很大"等模糊词？
- [ ] **冲突前置**：最惊悚/最意外的信息是否放在了前10个字？
- [ ] **对象具体化**：是否从"某医院"升级到了具体对象或场景？
- [ ] **情绪定调**：是否有强前缀/感叹词定基调？
- [ ] **删除冗余**：是否去掉了背景解释、因果说明，只留核心画面？
- [ ] **动词升级**：是否用有力的动词替代了口语化表达？

**标题合规红线（出现任一，标题判不通过）：**
- 夸大事实
- 刻意刺激血腥/悲剧细节
- 暴露隐私（姓名、住址、电话等）
- 二次伤害当事人
- 制造未经证实的指控
- 使用绝对化或违规营销表述（最、第一、绝无仅有等）

### 维度2：内容传播法则契合度（5大法则）

#### 2.1 速度极快
- 热点是否追得够快？（热点稿超过24小时需扣分）
- 非热点内容处理是否够高效？（没有冗余铺垫）
- 整体阅读节奏是否紧凑？

#### 2.2 强互动性
- 是否明确引导了用户互动？（点赞、评论、分享、投票、回复关键词等）
- 结尾问题是否具体，用户知道"接什么话"？
- 正文是否埋了至少1个明确的互动钩子？

#### 2.3 无目的性
- 标题是否能在半秒钟内搞定用户？
- 开头是否有吸引力，给用户"停下来看"的理由？
- 前3秒（前50字）是否有明确钩子？

#### 2.4 碎片阅读
- 排版是否简洁有条理？
- 文字是否流畅，逻辑是否清晰？
- 信息密度是否足够？（没有空话、套话、正确的废话）
- 是否采用多种信息呈现方式？（图文结合、视频入口等，如有）

#### 2.5 社交属性
- 内容是否帮助用户：表达观点、展示自我、寻找谈资、帮助别人？
- 用户转发这条内容的"社交理由"是什么？是否足够？

### 维度3：阅读心理契合度（7大心理）

| 心理 | 检查点 | 未满足的信号 |
|-----|--------|-------------|
| 我要知道得比别人快 | 是否提供了及时、独家或高效整合的信息？ | 信息滞后、众所周知 |
| 我要知道得比别人多 | 是否提供了"一站式解决方案"式的完整信息？ | 只抛问题不给答案、信息残缺 |
| 我要跟别人不太一样 | 是否有鲜明的观点或个性化表达？ | 平庸、安全、没有态度 |
| 我想读有用、有趣的 | 是否有显性的实用价值或趣味点？ | 纯资讯罗列、没有服务性 |
| 我想要更高效地阅读 | 单位时间内信息量是否足够？获取是否够快？ | 拖沓、铺垫过长、信息稀薄 |
| 我想要更舒服地阅读 | 阅读体验是否顺畅、接地气、不端着？ | 官话、说教、AI味浓 |
| 我要与作者平等对话 | 内容是否接地气、有代入感，没有"甲方心态"？ | 高高在上、俯视用户、强行灌输 |

### 维度4：APP运营规范审查（如渠道=APP）

#### 4.1 内容定位
- [ ] 是否优先本地民生、城市发展、强讨论性内容？
- [ ] 是否有明确的宜宾本地关联？
- [ ] 是否适合碎片化快速消费？

#### 4.2 标题APP适配
- [ ] 前10个字是否有看点？
- [ ] 是否优先使用了具体数字、地点、人物、冲突？
- [ ] 是否足够短，适合信息流展示？

#### 4.3 正文APP适配
- [ ] 开头是否够快？（1-2段内点明发生了什么、和谁有关）
- [ ] 是否像"公众号压缩版"？（APP稿不能是长文压缩）
- [ ] 是否按上游声明的短/中/长稿和目标字数审查？APP 允许短稿、中稿和有必要的长稿，不能把“短”当成统一通过条件；有事实层次和讨论价值却被压成四段模板短帖，判篇幅不适配。
- [ ] 是否有本地生活点？
- [ ] 是否有评论区接话空间？
- [ ] 结尾问题是否具体且可回答？
- [ ] 是否有一句记忆点/点睛句？
- [ ] 是否避免了过度公众号化？（铺垫太长、想把所有信息讲全、像长文导语）
- [ ] 是否避免了硬造讨论？（素材本身不值得聊，却强行问"你怎么看"）

#### 4.4 人设一致性（如指定了人设）
- [ ] **练团长**：是否把问题钉出来了？是否有追问感？
- [ ] **泡泡**：是否有生活场景和轻微刺痛？是否过于温吞？
- [ ] **流浪**：是否像"递话头"进评论区？是否有现场感？
- [ ] **离心-APP态**：是否先判断再组织？信息是否准确且有余白？
- [ ] **加菲**：是否接地气、顺嘴、轻吐槽？是否端着？

### 维度5：合规与安全审查

#### 5.1 内容审核5大原则
以下内容不予通过：
- [ ] 涉及党、政、军、恐
- [ ] 宣扬迷信、淫秽色情、赌博、暴力
- [ ] 引发大众恐慌
- [ ] 重大事故（3人及以上伤亡）不当呈现
- [ ] 造谣、公开侮辱他人

#### 5.2 隐私与伤害
- [ ] 是否暴露他人隐私（姓名、电话、照片、身份证号、住址）？
- [ ] 是否对当事人造成二次伤害？
- [ ] 涉及医疗、事故、隐私、未成年人时，是否做了合规降噪？

#### 5.3 事实风险
- [ ] 是否把单一爆料/聊天截图直接写成已确认事实？
- [ ] 涉及曝光、指责、争议时，是否替事实拍了板？（应为"引发讨论/有网友反映"）
- [ ] 素材证据链不足时，是否写得过于结论化？

#### 5.4 表达风险
- [ ] 是否使用了广告法违禁词？（最、第一、顶级等）
- [ ] 是否有"生动注脚""温暖底色""启新程"等高危AI味/公文味词汇？
- [ ] 是否出现了"替读者预设感受"的万能句？（"家长都懂""很多人其实都""大家都会有感"）

#### 5.5 商业/活动/服务类额外红线
- [ ] 是否出现无法举证的"第一、唯一、最、顶级、全网首发、销量冠军"？
- [ ] 是否把限时、优惠、名额、销量、排名写成无依据承诺？
- [ ] 医疗、教育、金融、房产、保健品等高风险行业是否有功效、收益、升值、保过等承诺？
- [ ] 活动宣传是否写清真实时间、地点、对象、费用、名额和限制条件？

### 维度6：结构与表达审查

#### 6.1 逻辑与语句
- [ ] 每一句是否都能单独读通？
- [ ] 前一句和后一句是否有明确逻辑关系？
- [ ] 是否出现悬空句、拧巴句、假深刻句？
- [ ] 是否为了"有感觉"而牺牲了语义清楚？

#### 6.2 素材处理（如是改写稿）
- [ ] 是否隐藏了"小编二创身份"？（没有出现"原文中""新闻里""素材里""这篇稿子"等暴露表达）
- [ ] 是否保住了原文最关键的信息、对象、动作或结果？
- [ ] 是否避免了"写作过程暴露句"？（如"这篇新闻如果照着通稿方式写"）

#### 6.3 整体结构
- [ ] 是否有清晰的开头-中段-结尾？
- [ ] 信息组织是否围绕1个主抓手展开，而不是塞多个判断句？
- [ ] 段落之间是否有自然的过渡？

#### 6.4 微信/公众号篇幅完整度（如渠道=微信订阅号/公众号）
- [ ] 是否达到对应交付物的正文长度？完整公众号稿、头条稿、生产级 98 候选，正文原则上不少于 1200 个中文字符，且不少于 8 个自然段。
- [ ] 人物、深度、城市变化、文旅活动等需要写厚的题材，是否达到更高下限？人物/深度不少于 1500 字、10 段；城建商业/文旅活动不少于 1300 字、9 段。
- [ ] 600-1000 字短观察、短提醒、线索征集稿可以通过短稿审查，但不得被判定为“完整公众号文章”或“生产级 98”。
- [ ] 微信稿低于 800 字时，若用户要求完整稿/头条稿/98 分，篇幅完整度直接判严重问题；800-1199 字只能按短稿或待扩写稿审查，综合评分不得虚高。
- [ ] 不得用空话、重复段落、堆口号凑字数。篇幅达标必须来自事实推进、读者关系、边界说明和互动动作。

#### 6.5 发布态洁净度与批量模板味（如渠道=微信订阅号/公众号）
- [ ] 正文是否像公开平台原创稿，而不是写作说明、审稿说明或方法拆解？
- [ ] 正文是否出现"一篇公众号文章要..."、"这类稿子要..."、"读者点进来想看..."、"文章中段..."、"标题和正文..."等自我解释式句子？出现即按发布态失败处理。
- [ ] 是否用同一套段落在多篇稿件中反复套题？批量复测时，同一自然段在 5 篇以上重复，或同一篇内功能段重复，结构与表达最高 8.8/10。
- [ ] 是否为了凑篇幅重复"安全感、边界、读者动作、转给准确的人"等泛化句？重复堆叠不算篇幅有效。
- [ ] 公开正文必须直接讲人、事、地点、生活动作和事实边界；写作方法、审稿判断、分数、复测和生产过程只能放内部报告。

#### 6.6 公众号题材分型与正文气质（如渠道=微信订阅号/公众号）
- [ ] 是否先判断了题材分型，而不是所有稿件套同一种腔调？
- [ ] **城建交通/城市变化**：是否把项目进展翻译成市民可感知的出行、居住、消费、区域变化？是否区分"规划中/建设中/已落地"？
- [ ] **民生通知/公共服务**：是否第一屏讲清发生了什么、影响谁、用户该做什么？是否避免多余抒情？
- [ ] **打卡攻略/周边玩法**：是否回答值不值得去、怎么去、玩什么、注意什么，而不是只夸景？
- [ ] **情怀记忆/城市旧地重看**：是否有具体生活纹理和本地记忆点，而不是空喊"承载回忆"？
- [ ] **人物故事/创业成长**：是否有人物反差、转折、动作线和宜宾关系，而不是履历堆砌？
- [ ] **家乡被看见/本地荣誉**：是否写清外部认证和含金量，把自豪感落到可信共鸣，而不是低质狂欢？
- [ ] **冲突讨论/社会情绪**：是否事实边界清楚、立场不过度代替读者、评论空间真实存在？

#### 6.7 AI味、本地感与用户翻译专项
- [ ] 是否出现"空、假、平、套"集中问题？空=有效信息少；假=情绪不像真人；平=没有记忆点；套=换个题材也成立。
- [ ] 是否有大量模板句？如"值得一提的是""不难发现""由此可见""可以看出""某种程度上"。
- [ ] 是否靠副词批发撑情绪？如"真的、太、超、狠狠、直接、赶紧、妥妥、简直"过量。
- [ ] 是否是假本地化？只塞"宜宾/三江口/老城区"，但没有本地生活纹理、具体人群或真实心理。
- [ ] 是否把无来源支撑的地点、时间、生活动作硬塞进正文？如"临港片区周末约朋友时""菜市转角""早上送娃时"这类锚点如果素材没有提供，属于**随机本地锚点**，不是本地感。
- [ ] 是否完成"用户翻译"？至少有一段回答：这对宜宾人意味着什么、为什么值得关注、谁最先感受到。
- [ ] 如果一句话换成别的城市仍成立，本地感不足；如果一段话换个题材仍能用，模板味过重。

#### 6.8 批量语义重复与评审器过拟合专项（公众号批量复测必查）
- [ ] 批量稿是否只是替换题材词、地点词、时间词后复用同一套段落骨架？不能只查"完全相同自然段"，必须查**语义模板重复**。
- [ ] 同一簇 5 篇是否都在重复同一组问题："先看边界/别只看热闹/值不值得转/卡在哪一步/问具体一点"？如果是，标题策略判模板化。
- [ ] 正文是否反复出现同一功能句？如"又被人聊了起来""不是非要立刻下结论的大事""真正有用的部分，是几个……小问题""本地内容不是把话说死"。同类句跨 20 篇以上重复，批量稳定性不得判高分。
- [ ] 是否为了通过审稿而堆满"边界、核对、隐私、费用、路线、用户关系"等审稿友好词，但缺少真实事实、真实评论、真实对象？这是**评审器过拟合**，不得按高分发布态处理。
- [ ] 审稿对象是否有真实素材支撑？若只给抽象主题、无原始链接/评论/事实材料，完整公众号稿最高只能按"练习稿"审查，不能判定为生产级 98 候选。
- [ ] 批量稿是否重复“事实摘要 → 泛化判断 → 这对本地人意味着什么 → 结尾提问”的同一段落功能？即使字面不同，也按语义模板重复处理；“最值得看的一点”“这条更适合当……看”“这条消息本身不复杂”等塑料句集中出现时，`ai_tone` 必须 FAIL。

#### 6.8.1 正文配图发布门（所有渠道）
- [ ] 原素材存在可合法使用图片时，是否给出逐图正文落点，而不只是图片清单？
- [ ] 发布态验收必须区分封面附件与正文图片：`attaches` 有图但正文没有 `<img>`，一律不通过。
- [ ] 发布后正文图片数量是否与确认稿一致、图片 URL 是否可访问、公开帖子内是否真实可见？任一未验证不得判发布完成。
- [ ] 千帆正文图是否使用公开详情页可渲染的 `lazy qf-slider`、`width:100%` 和真实 `data-scale`？公开页出现 `width="0"` 或 `height="0"` 时必须判失败，即使封面和后台详情能看到图片。

#### 6.9 素材支撑与随机本地锚点专项
- [ ] 无真实素材链接、截图、评论、后台数据、采访事实或明确线索时，只能按练习稿/选题推演审查，不能判定为生产级通过。
- [ ] 地点、时间、生活动作必须来自素材；"临港片区/柏溪生活圈/菜市转角/早上送娃/晚饭后散步"这类未给锚点不得被当成本地感。
- [ ] 文章开头建立在未给锚点上，素材支撑分最高 55/100；全文多处使用未给锚点，生产级总分最高 86/100。
- [ ] 素材只给抽象主题时，正确建议是补采、降级短帖、线索征集或不写，不是靠长文结构补成 98。

#### 6.10 生产级评分与练习稿评分分离
- [ ] 审稿必须拆成四个子分：格式稳定分、内容有效分、素材支撑分、反过拟合分。
- [ ] `production_score = min(格式稳定分, 内容有效分, 素材支撑分, 反过拟合分)`，不得用平均数抵消硬伤。
- [ ] 同一功能句跨 20 篇以上重复，反过拟合分不得生产级通过；同簇 5 篇正文骨架高度相似，单篇最高 88/100。
- [ ] 审稿友好词堆叠但事实信号少，内容有效分最高 65/100，不能判 95+。

#### 6.11 小编风格唯一性与备注一致性

- [ ] APP 稿末尾是否只有一个 `【小编风格备注】本稿采用：<小编名>小编风格`，且小编名属于 APP 七条路线；公众号稿是否属于甘甘、小美、加菲、大艳四条路线。
- [ ] 正文是否从标题、开头、结构、语气到结尾都执行同一位小编路线，而不是把两位或多位小编的标志性打法拼在一起。
- [ ] 上游已指定小编时，备注和正文是否服从该唯一指定；`account_baseline` 自选时，所选小编是否与题材主承诺、素材形态和读者动作匹配。
- [ ] 备注与正文不一致，记录 `style_note_mismatch`；正文混入第二位小编路线，记录 `style_mixed`。两者都是发布质量问题，不能靠删除备注掩盖。
- [ ] 小编风格备注只作内部编辑说明，不得被当成真实作者署名、亲历或采访身份。

#### 6.12 结构化任务返回协议

当输入是 `hotspot-radar-agent-task-v1` 且任务为 `review` 时，仍按本 Skill 全量审稿，但最终只返回一个 JSON 对象，不输出 Markdown 报告或解释文字：

- 顶层字段固定为 `verdict`、`score`、`issues`；`verdict` 只能从输入 `response_contract.verdicts` 选择，`score` 使用 0-10 分。
- `issues` 每项固定使用 `severity`、`code`、`message` 三个字段；`severity` 只能是 `high`、`medium`、`low`。
- 禁止把字段写成 `level`、`type`、`description`、`location`、`suggestion`，也不要混用两套结构。
- 非 `approved` 判定必须至少返回一项 issue；`approved` 可返回空数组。

## 四、判定标准

### ✅ 通过
- 没有严重问题（🔴）
- 综合评分 ≥ 7.5分
- 标题质量 ≥ 7分
- 合规安全 = 10分（合规是硬门槛，一票否决）
- 前置判断不能是 P3 硬做重点稿
- 微信/公众号完整稿达到篇幅完整度门槛；未达到时只能按短稿通过，不能判完整稿通过

### ⚠️ 有条件通过
- 没有严重问题（🔴）
- 但有1-3个中等问题（🟡）
- 综合评分 6.0-7.4分
- 微信/公众号稿 800-1199 字且结构可用时，只能判为短稿/待扩写稿有条件通过，综合评分最高 9.2/10

### ❌ 不通过
- 出现任何1项严重问题（🔴）
- 或合规安全 < 10分
- 或标题质量 < 5分
- 或综合评分 < 6.0分
- 微信/公众号完整稿、头条稿或 98 分候选低于 800 字，或低于 8 个自然段仍自称完整稿
- 核心角度不成立、渠道明显错配、事实状态模糊、题材气质写错且局部修不回来

### 前置判断锁分

- P3 素材被硬写成重点稿：综合评分最高 8.6/10，且必须建议降级、换角度或不做。
- 渠道错配：APP稿写成公众号导语、公众号稿写成碎片短帖，综合评分最高 8.8/10。
- 标题和正文重点不一致：综合评分最高 8.7/10；若事实风险同步存在，直接不通过。
- 开头 3 段仍没说清重点：完整稿综合评分最高 8.8/10；APP稿默认不通过。
- 只靠情绪、不补事实和用户关系：AI味与本地感最高 7.0/10，完整公众号稿不得判通过。
- 随机本地锚点/假场景：稿件把素材没有提供的地点、时间、生活动作当成本地感使用，AI味与本地感最高 6.5/10，综合评分最高 8.6/10；若全文建立在假锚点上，直接不通过。
- 评审器过拟合：大量堆叠"边界/核对/路线/隐私/费用/用户关系"等审稿友好词，但缺真实事实、真实评论、真实对象，综合评分最高 8.5/10，不得判 95+。
- 批量语义模板重复：同一簇 5 篇主体骨架高度相似，单篇综合评分最高 8.8/10；跨批量 20 篇以上复用同一功能句，批量稳定性结论不得写"已稳定通过"。
- 无真实素材支撑的抽象题库稿：只能按练习稿审查；不得判定为生产级 98 候选或可直接发布公众号完整稿。
- 生产级评分：最终生产级总分必须取四个子分最低值；素材支撑分或反过拟合分低时，不得用格式稳定分和篇幅分平均冲高。

### 微信/公众号篇幅锁分

- 完整公众号稿、头条稿、生产级 98 候选：正文 <1200 字或 <8 段，综合评分最高 9.2/10，不得判“完整公众号文章 98”。
- 人物/深度稿：正文 <1500 字或 <10 段，综合评分最高 9.2/10；缺原话、动作线或现场细节时还要继续按素材风险扣分。
- 城建商业、文旅活动、城市变化类：正文 <1300 字或 <9 段，综合评分最高 9.3/10。
- 微信/公众号稿正文 <800 字：若只是短提醒/短观察，可按短稿审查；若用户要求完整稿/头条稿/98，综合评分最高 8.8/10。
- 正文 <600 字：除 APP 短帖或极短通知外，微信/公众号审查默认不通过。

### 微信/公众号发布态锁分

- 正文把自己写成"文章怎么写/公众号怎么写/读者点进来想看什么"的方法说明，综合评分最高 8.8/10，不得判通过。
- 正文出现审稿、评分、复测、生产过程、写作策略等内视角表达，综合评分最高 8.5/10；露出来源链或二创痕迹时直接不通过。
- 批量复测中，同一自然段在 5 篇以上重复，或单篇内重复同一功能段，综合评分最高 9.0/10；若靠重复段落补篇幅，篇幅完整度也不得通过。

### 小编路线锁分

- 缺少小编风格备注，或备注存在两个及以上小编名：记录 `style_note_mismatch`，不得直接通过。
- 备注小编与正文主打法不一致：记录 `style_note_mismatch`，综合评分最高 8.5/10。
- 正文混搭两位或多位小编路线：记录 `style_mixed`，直接判为需重写；不得用“主风格 + 辅风格”解释为合格。

## 五、高频问题速查表（审稿时快速对照）

| 问题现象 | 对应规则 | 修改方向 |
|---------|---------|---------|
| 标题前10个字没看点 | 标题9条-第2条 | 把最冲突/最意外的信息前置 |
| 标题太长 | 标题8个补充-第4条 | 压缩到32字以内，保留核心动作词 |
| 没有阿拉伯数字 | 标题9条-第8条 | 把时间、金额、数量具体化 |
| 用户不觉得"跟我有关" | 阅读心理-代入感 | 加入身份标签、具体场景、本地地点 |
| 结尾只会问"你怎么看" | APP规范-结尾适配 | 换成可接话的具体问题 |
| 像公众号压缩版 | APP规范-正文适配 | 加快节奏、减少背景、增加讨论空间 |
| 有"原文中说" | 结构审查-素材处理 | 改为直接叙述事实 |
| 微信稿太短却自称完整稿 | 篇幅完整度 | 扩写事实推进、读者关系、边界和互动动作；不能靠空话凑字数 |
| 正文在讲"公众号文章怎么写" | 发布态洁净度 | 改成直接讲人、事、地点、生活动作和事实边界 |
| 多篇稿件重复同一段 | 批量模板味 | 重写为题材专属事实推进，不用通用段落凑篇幅 |
| 替读者预设感受 | 表达风险 | 删除"家长都懂""很多人其实都"等万能句 |
| AI味浓 | 表达风险 | 删掉"生动注脚""温暖底色"等词，改用口语化表达 |
| 没有记忆点 | APP规范-正文适配 | 提炼1句"说准别扭点/现实感"的话 |
| 纯通稿/纯政务硬写头条 | 前置判断 | 先找用户关系；找不到就降级为简讯、合集或不做 |
| 公众号稿题材气质写错 | 题材分型 | 先分型，再重排正文结构和语气 |
| 假本地化 | AI味与本地感 | 不只加地名，要写出哪类宜宾人、哪个生活场景、什么真实心理 |
| 情绪盖过事实 | 事实风险/AI味 | 先补时间、地点、对象、范围、状态，再保留少量情绪 |
| 硬造互动 | APP规范/结尾 | 换成具体可回答的问题；没有真实讨论价值就不要强问 |
| 假本地化/随机锚点 | AI味与本地感 | 地点/时间/生活动作必须来自素材；无来源支撑的随机锚点按假场景扣分 |
| 语义模板重复 | 批量过拟合 | 批量审稿要查同义段落骨架，不只查完全相同自然段 |
| 审稿友好词堆叠 | 评审器过拟合 | 有"边界/核对/路线/隐私/费用"不等于好稿，必须回到真实事实和真实对象 |
| 抽象题库稿冒充生产稿 | 素材支撑 | 没有原始链接/评论/事实材料时，只能按练习稿审查，不能判生产级 98 |
