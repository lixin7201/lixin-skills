# 横向分组与逻辑顺序检查

## R — 原文 (Reading)

> 表述必须具有明确的归纳或演绎关系，但不可同时既具有归纳关系，又具有演绎关系。
>
> — 芭芭拉·明托，《金字塔原理》第2章

## I — 方法论骨架 (Interpretation)

横向检查处理的是同一层要点之间的关系。
同组要点不能只是“都重要”，必须同类，并且能用归纳或演绎之一回答上层疑问。
归纳是多个独立要点共享共同性，向上推出概括；演绎是前提、评论、因此结论形成链式推导。
同组要点还要有顺序，常见为时间、结构、程度或演绎顺序。
如果一组里混入原因、措施、感受、案例和结论，先拆组，再写上层概括句。

## A1 — 书中的应用 (Past Application)

### 案例 1: 购物清单超过记忆上限
- **问题**: 9 样购物物品按口头顺序出现，读者难以记住。
- **方法论的使用**: 作者把零散项目按食品类别或超市区域分组。
- **结论**: 分组能降低记忆负担，并帮助上层概念提示下层细节。
- **结果**: 读者不再记 9 个散点，而是记少数同类组。

### 案例 2: 男女同工同酬开头
- **问题**: 五个思想之间没有清晰逻辑关系，读者需要自己找联系。
- **方法论的使用**: 用“是否同组、是否回答同一疑问、是否能概括”检查段落。
- **结论**: 看似自上而下的文字也可能横向关系失效。
- **结果**: 改稿要先处理思想关系，而不是润色句子。

### 案例 3: TTW 印刷厂备忘录
- **问题**: 成本、效率、工会、流失等材料交织，结论和行动建议混在一起。
- **方法论的使用**: 先列要点，再识别行动性思想，归类并提炼上层结论。
- **结论**: 杂乱材料可以通过自下而上分组重建结构。
- **结果**: 备忘录从材料堆叠变成可读的分析。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户列了很多 bullet，但自己也觉得“不够 MECE / 不像一组”。
2. 一页复盘里同时出现原因、措施、感受和结论。
3. 报告大纲每层要点看似整齐，但上层标题只能写“几个问题/几项建议”。
4. 用户要判断一组论证是归纳、演绎，还是应该拆开。

### 语言信号

- “这几个点怎么分组”
- “帮我看是不是 MECE”
- “这些理由顺序对吗”
- “这个大纲横向逻辑不清”
- “induction / deduction / logic order”

### 与相邻 skill 的区分

- 与 `conclusion-first-pyramid-report` 的区别: 结论先行先确定顶端答案；本 skill 检查同一层要点之间是否成立。
- 与 `problem-definition-r1-r2-diagnostic-tree` 的区别: 本 skill 处理表达结构中的分组；R1/R2 处理现实问题的诊断边界。
- 与 `pyramid-slide-one-point-check` 的区别: 本 skill 可用于任何大纲或段落；单页检查只落到幻灯片页面。

## E — 可执行步骤 (Execution)

1. **原子化要点**
   - 把每个 bullet 改写成一个完整思想句，避免只保留名词标题。
   - 完成标准: 每条都有主语、谓语和明确判断或行动。

2. **标注要点类型**
   - 给每条标注原因、证据、步骤、问题、建议、案例、结果或背景。
   - 完成标准: 同组内没有明显混合类型；混合类型先拆组。

3. **选择横向关系**
   - 如果第二点评论第一点并推出第三点，标为演绎；如果各点独立但有共同性，标为归纳。
   - 完成标准: 每组只能清楚地归入演绎或归纳之一。
   - 判停条件: 两者都不成立时，不强行排序，回到重分组。

4. **确定逻辑顺序**
   - 归纳组按时间、结构或程度排序；演绎组按推理链排序。
   - 完成标准: 能用一句话解释为什么这个顺序优于其他顺序。

5. **重写上层概括句**
   - 行动性思想写直接结果，描述性思想写共同含义。
   - 完成标准: 上层句不是“3 个原因/几点建议”，而是有信息量的判断。

6. **复核遗漏与重复**
   - 检查同组是否有重复、缺项、异类项和维度混用。
   - 完成标准: 每条下层都支撑同一个上层概括。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户还没确定读者问题或顶端结论，需要先用结论先行或 SCQA。
- 材料真实性、因果关系或业务目标尚未验证，不能用结构检查替代事实验证。
- 资料库、素材库、头脑风暴清单只是在收集阶段，暂不需要严格同组。

### 作者在书中警告的失败模式

- 异类事项硬凑成一组。
- 用“缺乏思想”的句子掩盖思考不完整。
- 不预告逻辑关系，让读者按自己的背景误解。

### 作者的盲点 / 时代局限

- MECE 和逻辑顺序容易被误用为形式洁癖；真实工作里要服务决策和理解，不是追求分类漂亮。
- 对情绪表达、探索式写作和创意内容，过早分组可能压扁新想法。

### 复盘方式

- 让别人只看每组上层概括，预测下层会有哪些内容；预测失败说明概括无效。
- 对每组写一句“这些要点的关系是……”；写不出来就重分组。
