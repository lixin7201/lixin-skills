# 写作 DNA

## 适用范围

基于 writing-train 24 篇文章的原型观察。没有运行 blind A/B，不能认证“原汁原味”或高保真。

## 选题与标题

常见结构：

- 大额结果 + 具体项目/平台 + 揭秘；
- 反常识判断 + “真正决定变量”；
- 个人经历 + 强转折；
- 教程/攻略 + 明确收益或效率承诺。

安全处理：收益数字只有在用户提供可核验材料时使用；否则改成机制、冲突或风险，不制造夸张承诺。

## 开头

常见动作：

1. 直接抛异常现象或个人场景；
2. 迅速立态度；
3. 建立“我见过表面和底牌”的观察位置；
4. 引出真正要讲的商业逻辑。

生成时不得虚构人物第一人称。可改为“先看一个反常识事实”“这项目最容易看错的不是……”等非冒充开头。

## 推进

- 具体名词密度高：平台、产品、费用、收入、动作、时间；
- 案例先行，再抽象为方法；
- 通过反问推动读者自检；
- 用“不是 A，而是 B”纠正直觉；
- 在关键处用短句加重；
- 长文常有编号、小标题、连载和回扣；
- 口语与技术/英文名词混用。

## 表达力度

可保留：直给、锋利、带判断、偶尔自嘲、粗粝。

需要降噪：连续自我背书、压倒式确定性、贬低读者、把大数字当证明、重复“真话/悟道/邪修”。

## 素材优先级

具体交易/使用场景 > 真实数据 > 项目机制 > 个人关系/身份 > 空泛观点。

任何人物经历只能转述并标作者自述；生成稿不得借用为“我”的经历。

## 结构模板（可变形）

标题 → 异常场景 → 一句判断 → 机制拆解 → 隐藏成本/底牌 → 反例或失败方式 → 合规动作 → 收束判断

不要每篇固定八段。短稿可只用：冲突 → 关键因果 → 下一步。

## 像与不像

像：

- 先砸穿表面叙事；
- 具体案例与商业变量一起出现；
- 结论有力度，随后能解释为什么；
- 技术最终回到流量、用户、交付和钱。

不像：

- “在当今快速发展的时代”；
- 每段都是三点式万能框架；
- 只喊认知、执行力、长期主义，没有具体机制；
- 为了像而堆“兄弟们、邪修、悟道、真话”；
- 冒充人物经历或复制独有原句。

## 写后检查

删除署名冒充、虚构收益、空泛升华、过程泄漏和模板复读；保留关键因果、具体场景、信息密度与必要粗粝。
