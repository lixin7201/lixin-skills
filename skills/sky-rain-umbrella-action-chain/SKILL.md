# 空雨伞事实-意义-行动链

## R — 原文 (Reading)

> "'天上堆积了很多云'→'So what？' '可能会下雨'→'So what？' '出门要带雨伞'"
>
> — 大岛祥誉同系列文本，《麦肯锡入职培训第一课》

## I — 方法论骨架 (Interpretation)

空雨伞把信息处理压缩成三步：事实、意义、行动。
"空"只写可观察事实，不急着解释。
"雨"回答这个事实意味着什么，可能导致什么变化。
"伞"回答因此要采取什么行动、提醒、实验或准备。
写完以后再用 So what 追问事实是否真的导向行动，用 Why so 回查判断是否有证据支撑。
它不是完整报告结构，而是把一条信息变成洞察和动作的最小推理链。

## A1 — 书中的应用 (Past Application)

### 案例 1: 云、雨、伞
- **问题**: 看到"天上堆积了很多云"这样的事实时，很多人停在描述层。
- **方法论的使用**: 用 So what 追问云意味着可能下雨，再追问下雨意味着出门要带伞。
- **结论**: 有价值的信息必须能导向意义判断和行动。
- **结果**: 事实不再只是观察，而变成可执行提醒。

### 案例 2: 销售额上不去
- **问题**: 只说销售额上不去，无法产生有效行动。
- **方法论的使用**: 用 Why so 反复追问，拆出顾客量没有增加、单笔消费额低等解释。
- **结论**: 行动建议必须能回到原因或证据，否则只是口号。
- **结果**: 从"销售不好"推进到可验证的原因方向。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 看完一组数据、用户反馈、市场新闻或会议记录，不知道该写什么洞察。
2. 文案、周报、方案里堆了很多事实，但缺少结论和下一步。
3. 用户问"这说明什么""所以我们怎么办""这对我有什么影响"。
4. 创业或运营中收到一个外部信号，需要快速形成监测、验证或行动建议。
5. 文章写作中有素材但没有观点，需要把素材变成读者可用的判断。

### 语言信号

- "So what / Why so"
- "空雨伞"
- "这些数据说明什么"
- "怎么从事实推行动"
- "fact -> insight -> action"

### 与相邻 skill 的区分

- 与 `primary-source-fact-grounding` 的区别: 本 skill 从已给事实推出意义和行动；如果事实来源不可靠，先用原始材料接地。
- 与 `conclusion-first-pyramid-report` 的区别: 金字塔组织整篇报告的纵横结构；空雨伞只处理事实到行动的一条微链路。
- 与 `issue-hypothesis-logic-tree-loop` 的区别: 复杂根因、多个分支和验证计划用逻辑树；单个信号的含义与行动用空雨伞。

## E — 可执行步骤 (Execution)

1. **抽取"空": 可观察事实**
   - 只写事实、数据、原话、事件和时间，不加入解释。
   - 完成标准: 每条事实都能被来源或观察记录支持。
   - 判停条件: 事实来源不明、口径冲突或明显二手加工时，先调用 `primary-source-fact-grounding`。

2. **追问"雨": 事实意味着什么**
   - 对每条事实问 So what，写出可能影响、风险、机会或机制。
   - 完成标准: 每个意义判断都能回答"对谁、在哪个指标或行为上产生影响"。

3. **回查"Why so": 判断凭什么成立**
   - 为每个意义判断补证据、假设或待验证条件。
   - 完成标准: 读者能区分已证实判断和待验证猜测。

4. **生成"伞": 行动或实验**
   - 给出下一步动作、监测指标、沟通提醒、实验方案或不行动理由。
   - 完成标准: 行动有负责人、时间点、触发阈值或可复盘标准。

5. **输出一行链条**
   - 格式: 空=事实；雨=意义；伞=行动；Why so=证据/待验证点。
   - 完成标准: 删掉任何不能从事实推导出来的行动。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户需要完整根因诊断、策略拆解或多分支方案选择。
- 用户已经有明确结论，只需要写成报告结构或 PPT 页面。
- 事实来源不可靠、样本太小或口径不清，却要求直接行动。
- 行动不可逆、影响重大或涉及合规风险时，不可只靠一条空雨伞链做决策。

### 作者在书中警告的失败模式

- 只停留在信息描述，不追问"那又怎么样"。
- 只给结论或行动，不追问"为什么如此"。
- 把思考外包给现成答案，省略事实到行动之间的推理。

### 作者的盲点 / 时代局限

- 书中示例很简洁，现实信息常有多个解释；空雨伞只能给出短链路，不能证明复杂因果。
- 在 AI 摘要、算法推荐和转述信息泛滥的环境里，事实层必须更严格地标注来源。

### 复盘方式

- 行动执行后回看"雨"的意义判断是否成立，若不成立，记录误判原因。
- 检查是否存在事实选择偏差：是否只挑了支持行动的事实。
- 把高频有效链条沉淀为写作、周报或运营观察模板。
