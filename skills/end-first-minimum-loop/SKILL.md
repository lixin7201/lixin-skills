# 以终为始的最小闭环

## R — 原文 (Reading)

> 不是从起点开始，往目标规划；而是倒过来，从终点往回看，要达成终点必须满足什么条件。
>
> — 姜胡说，第十二章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

先定义可报销成功的终点与60分标准，只做一条端到端路径，用真实用户完成一次后再扩字段和异常分支。

它的独特性在于：将以终为始、60/80/120标准、骨架顺序和最小完整交付压成一套执行算法。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 作者逆向设计驾考方法并一次高分通过
- **问题**: 作者从“拿到驾照”反推考试要求，刷题寻找规则、阅读成功经验、在现场只练关键差距，而不是把驾校全部内容等同于目标。
- **方法论的使用**: 从该真实过程还原输入条件、关键动作与反馈，而不是只摘取结果。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 用较少精力一次通过驾考且成绩优异。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **定义终局样本**
   - 完成标准: 用一个具体可见的交付物描述完成，而非抽象愿望

2. **倒推必要链路**
   - 完成标准: 只保留产生该结果不可缺的输入、动作和反馈
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **完成最小循环**
   - 完成标准: 在可逆范围内跑通输入—处理—输出—反馈

4. **按瓶颈扩展**
   - 完成标准: 只扩充当前失败点所需能力，形成下一版本

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 目标尚未确认、不可逆且高风险的正式发布，或只需要优化已有稳定流程。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 在没有真实反馈前持续打磨，迟迟不交付第一个可运行版本。 完美标准隐藏未知需求，也常被用来回避暴露不足和接受评价。

### 作者的盲点 / 时代局限

- 最小闭环不能成为低质量借口；涉及安全、法律与信誉时最低标准不可裁剪。

### 容易混淆的邻近方法论

- `rapid-book-survey` 与 `nearby-problem-income-loop`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
