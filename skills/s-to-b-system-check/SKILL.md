# S 到 B 系统化检查

## R — 原文 (Reading)

> 成功的B所开发的系统没有他们的参与也能够正常运转。
>
> — 〔美〕罗伯特·清崎；〔美〕莎伦·莱希特等, 《富爸爸财务自由之路》第4章

## I — 方法论骨架 (Interpretation)

S 型业务依赖个人专业、控制和亲自交付；B 型业务依赖系统、团队、流程和指标。
这个方法不问“你是不是老板”，而问“你不在时系统是否还能产出结果”。
系统化不是一口气做大，而是把获取客户、交付、质量、财务和训练拆成可复制部件。
适合自由职业者、咨询师、创作者、小店主、课程主理人和早期创业者。

## A1 — 书中的应用 (Past Application)

### 案例 1: 漫画书阅览室的微型系统
- **问题**: 两个孩子没有资本，也不能无限卖自己的时间。
- **方法论的使用**: 他们找到旧漫画书来源、收费规则和管理员，让业务在自己不在场时运行。
- **结论**: 哪怕是小生意，也可以测试系统所有权而不是亲自劳动。
- **结果**: 阅览室运行约三个月，产生非亲自劳动收入。
### 案例 2: 企业系统三路径
- **问题**: 多数人想创业却只想到自己亲自做一个更忙的工作。
- **方法论的使用**: 作者把系统路径拆成自建、特许经营、网络营销三类，要求比较系统质量。
- **结论**: B 的核心是系统，不是头衔。
- **结果**: 这成为审查商业机会和创业路径的框架。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户已经有业务，但本人一停业务就停。
2. 用户想招人、写流程、产品化服务或建立团队。
3. 用户想判断一个商业模式是不是可复制系统。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

 1. **画业务链路**
   - 操作: 列出获客、销售、交付、复购、财务、质量控制、人员训练。
   - 完成标准: 链路完整，没有只写产品。
   - 判停条件: 若缺少关键事实，先向用户索取或标注假设，不继续给强结论。
 2. **标本人依赖**
   - 操作: 标出必须由本人完成的环节、原因和替代可能。
   - 完成标准: 本人瓶颈被显性化。
 3. **设计最小系统**
   - 操作: 为一个瓶颈写 SOP、模板、检查表或训练流程，并找一次替代执行。
   - 完成标准: 有一个环节能被别人或工具稳定复现。
 4. **看指标**
   - 操作: 跟踪交付质量、客户满意、毛利、错误率和本人时间释放。
   - 完成标准: 系统化不是更忙，必须释放时间或提高稳定性。
   - 判停条件: 若出现法律、税务、医疗、证券投资或债务危机，停止给具体方案并建议专业支持。

### 完成标准

- 已给出一个明确分类、路径、排序或下一步实验，而不是泛泛建议。
- 已写明关键事实、假设、风险、停止条件和复盘指标。
- 若涉及钱、债务、税务、法律、证券或房地产，已提醒需要按当前地区和真实数据复核。

### 复盘方式

- 记录本次判断所依据的事实与假设。
- 在 7-30 天后检查行动是否发生、指标是否改善、风险是否扩大。
- 若结果偏离预期，把偏离原因写成下一次可检查规则。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户还没有任何业务或验证，只是在问要不要创业。
- 用户的目标是成为高价专家而不是系统所有者；可先尊重 S 型策略。

### 作者在书中警告的失败模式

- 以为注册公司、雇人、租办公室就是 B，结果固定成本升高但系统没有形成。
- 过早追求规模，把本人都没跑通的混乱流程外包给团队。

### 作者的盲点 / 时代局限

- 作者偏好 B/I 路径，但高质量 S 型职业也可以是合理选择。
- 系统化需要管理、现金流和市场前提，不适合所有阶段。

### 容易混淆的邻近方法论

- 与 `cashflow-quadrant-income-map` 的区别: 本 skill 假设已经发现 S/B 问题，专门检查系统化条件。
- 与 `business-education-due-diligence` 的区别: 本 skill 审计自己的业务；后者审计外部商业教育或加盟系统。
