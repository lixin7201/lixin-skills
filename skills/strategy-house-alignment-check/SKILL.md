# 战略屋目标-战场-能力对齐检查

## R — 原文 (Reading)

> 战略屋模型是一个可视化框架，用于构建和展示企业的战略规划，从使命愿景到具体的战术执行层面，确保战略的一致性和可执行性。
>
> — 《分章节P3-01 战略屋和品牌屋》Slide 9

> 通过这个模型，团队可以更好地对齐目标、资源和行动，从而提高执行效率和效果。
>
> — 《分章节P3-01 战略屋和品牌屋》Slide 10

## I — 方法论骨架 (Interpretation)

战略屋不是一张“战略展示图”，而是一张错位检查图。它把愿景、经营目标、赛道、品牌、品类、产业链环节、产品、营销、渠道、研发、供应链和组织放到同一张结构里，逼团队回答：我们到底要赢在哪里，凭什么赢，哪些能力必须跟上。

对个人品牌、小团队或早期创业来说，不需要照搬大企业模板。可压缩成四层：目标是什么，主战场是谁/哪里，制胜方式是什么，保障机制是什么。只要其中一层缺证据或资源，后续内容、渠道和产品动作就会漂。

这个 skill 的输出不是宏大战略口号，而是一份“对齐/错位清单”：哪些目标没有战场，哪些战场没有能力，哪些动作消耗资源但不支撑目标。

## A1 — 书中的应用 (Past Application)

### 案例 1: B2B 品牌的战略屋

- **问题**: 市场部要让品牌、内容、广告、网站、活动、人才和协作共同支撑长期品牌目标。
- **方法论的使用**: PPT 把使命、愿景、2024 指标、2026/2028 品牌目标、主要战场、营销能力、线下活动能力、赋能机制和人才机制放在同一张战略屋里。
- **结论**: “成为 TOB 市场部最认可的品牌”必须落到内容营销、网站、广告、活动、方法论输出和人才机制。
- **结果**: 战略不再只是品牌愿景，而变成可检查的能力建设路线。

### 案例 2: 全域消费者运营体系

- **问题**: 品牌想同时运营会员、门店、社交媒体、电商、私域、公域和 KOC。
- **方法论的使用**: PPT 用战略屋把 CRM 中央引擎、会员体系、品牌馆、生活馆、服务、门店和数字化社交媒体串起来。
- **结论**: 全域运营必须依赖数据收集、会员小程序、企业微信、素材库和消费者数据库等保障。
- **结果**: 如果没有数据治理、内容供给和服务承接，全域只是铺开触点。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 公司、项目、账号、产品或个人 IP 有很多动作，但没人能说清主目标和主战场。
2. 团队同时做品牌、内容、投放、渠道、产品和社群，资源被拉散。
3. 用户想制定年度战略、增长方向、品牌战略或业务打法，但担心只有 PPT 没落地。
4. 目标很大，资源、组织能力、供应链、内容能力或交付能力明显跟不上。

### 语言信号

- “我们战略是不是散了？”
- “目标、产品、渠道对不上”
- “帮我梳理战略屋”
- “strategy alignment / how to win / operating model”

### 与相邻 skill 的区分

- 与 `brand-house-positioning-benefit-rtb-audit` 的区别: 本 skill 先检查战略层的目标、战场和能力；品牌屋 skill 检查定位、利益点和 RTB。
- 与 `platform-playbook-currentness-audit` 的区别: 本 skill 不核验某个平台打法是否过期；它判断平台动作是否服务战略。
- 与 `brand-health-penetration-loyalty-diagnosis` 的区别: 本 skill 做前置对齐；品牌健康 skill 用真实指标诊断结果状态。

## E — 可执行步骤 (Execution)

1. **写清战略顶层**
   - 完成标准: 用一句话写出愿景/经营目标、目标周期和一个可衡量结果。
   - 判停条件: 如果目标无法量化或没有期限，只能做愿景澄清，不能进入执行建议。

2. **定义主战场**
   - 完成标准: 写清目标人群、场景/地区/品类、竞争对象和你选择不做的范围。

3. **说明制胜方式**
   - 完成标准: 列出 1-3 个可控变量，如产品体验、内容资产、渠道效率、服务承接、供应链、组织协作。

4. **盘点保障机制**
   - 完成标准: 对每个制胜变量列出资源、团队、流程、数据、预算、合作方和交付能力。

5. **找最大错位**
   - 完成标准: 标出目标-战场-动作-能力之间最大的 1-3 个断点，并说明如果不修会怎样。

6. **给出最小对齐动作**
   - 完成标准: 输出一个本周可做的证据补充、资源调整、动作停止或机制建设任务。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只要写一句品牌定位或卖点，应转 `brand-house-positioning-benefit-rtb-audit`。
- 用户只问某个平台新规、广告产品或平台打法是否还能用，应转 `platform-playbook-currentness-audit`。
- 用户没有目标、资源、市场或产品信息，只想让你编一套战略。

### 作者在资料中的失败模式提示

- 战略屋填写完整不等于执行一致；目标、资源和行动必须互相支撑。
- 全域消费者运营若没有数据、会员、内容、服务和组织承接，会变成触点堆砌。

### 作者的盲点 / 时代局限

- PPT 偏企业市场部和品牌规划视角，对个人 IP、小团队、早期创业的资源限制提示不足。
- 涉及 CDP、企业微信、小程序和消费者数据库时，必须另行核验当前平台规则、数据授权和隐私合规。

### 容易混淆的邻近方法论

- 战略屋不是商业计划书，也不是年度 OKR；它只检查战略逻辑和能力承接。
- 不要把“全域铺开”当作战略成熟，小团队应先做单渠道、单人群、单能力的最小闭环。
