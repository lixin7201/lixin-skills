# 情感长短文合并验证（2026-08-26）

## 实施规格

目标：让 `app-skill` 在情感婚恋路由内支持第一人称虚拟短帖与故事长文，同时保持其他十类文稿 DNA 和九条小编 DNA 的原行为边界。

成功标准：

- 未指定形态默认 180–500 字短帖；明确长文才走 700–1600 字路线。
- 虚拟情感稿内部记录 `scenario_origin=virtual`；公开标题和正文不显示固定虚构标签，并锁定同一第一人称。
- 非情感任务不读取情感专属参考，不获得虚构金额、家庭叙述或长文结构。
- 现有十类非情感类型 DNA 与九条小编 DNA 不被修改。
- 高风险情感内容只生成 `HUMAN_REVIEW_ONLY` 候选，不自动发布。
- 公开仓库不包含购买包正文、源路径、运行日志或私有 holdout 原文。

## 最小实现

1. 主 Skill 只增加条件路由、优先级和虚拟情感输出边界。
2. 以 `情感婚恋互动DNA.md` 为唯一类型入口，同名 `.md` 只作兼容指针。
3. 内容机制、短帖、长文、原创安全拆成四份按需参考；短长形态二选一加载。
4. 增加确定性隔离校验和 11 条情感/非情感回归合同。

## 影响矩阵

| 层级 | 改动 | 预期影响 |

| 发布链路 | 不修改 | Skill 只生成候选，高风险仍需人工门 |

## 验证计划

- 静态：运行 `python3 scripts/validate_emotion_integration.py`。
- 差异：确认非情感类型、小编 DNA、账号总 DNA 与改前逐文件一致。
- Skill：运行官方快速校验及 OpenClaw 可发现性检查。
- 行为：分别做情感短帖、情感长文、非情感招聘/民生 no-publish 冒烟。

## 验证结果

状态：`INTEGRATION PASS / LONGFORM CANDIDATE`。

- 确定性校验：`PASS`；38 条测试合同，6 个情感运行文件，检查 10 类非情感 DNA 与 9 条小编 DNA。
- 改前改后逐文件比较：10 类非情感 DNA、9 条小编 DNA、5 个账号全局文件，共 24 个文件无变化。
- 主 Skill 增量：2275 字节，只增加触发、隔离、优先级和输出边界；情感专属参考按路由条件加载。
- Frontmatter：Ruby 标准 YAML 解析通过；官方 `quick_validate.py` 因本机没有其可选 `PyYAML` 依赖未执行完成，未为此安装新依赖。
- OpenClaw 可发现性：`Ready`、`Visible to model: yes`、`Available as command: yes`。
- 情感短帖 no-publish：约 300 字、5 段、第一人称、公开固定标签 0、流浪啊单一路线；工具失败 0，无发布工具。
- 情感长文 no-publish：约 1000 字、12 段、第一人称、2–3 次因果推进、公开固定标签 0、流浪啊单一路线；工具失败 0，无发布工具。
- 非情感招聘 no-publish：保持大宜宾-梦竹路线，没有虚构情感标识、第一人称家庭故事或长文结构；工具失败 0，无发布工具。
- 公开安全扫描：新增运行参考不含本机用户名、购买包路径、DOCX、原始语料、运行日志或私有 holdout 正文。

结论：隔离合并已通过静态与真实运行验证。现有其他写稿 DNA 没有被改写，真实招聘样本未发生串台。情感长文已可调用，但尚未完成完整冻结 holdout 盲 A/B，因此质量等级仍标记 candidate，不宣称稳定爆款已被证明。

## 公开固定标签合同修正

用户明确要求公开文章不出现 `【情感讨论·虚构情境】`。合同现改为：

- 公开标题和正文禁止出现该固定标签；测试 `t38` 将其列为明确禁止输出。
- 虚构来源只保留在内部运营字段 `scenario_origin=virtual`。
- 仍禁止声称真实网友投稿、真人真事、当事人自述或真实宜宾家庭。
- 高风险候选的 `HUMAN_REVIEW_ONLY` 人工门保持不变。
- 改前验证按预期失败于 `fixed virtual label leaked into main skill`；改后源仓库与 OpenClaw 运行版均通过 38 条合同。
- fresh no-publish：短帖、长文公开固定标签均为 0；非情感招聘稿未发生串台；实际发布 0。
