# 问题归属—投入分流

## R — 原文 (Reading)

> 有些问题，并不是你自己的问题。
>
> — 李笑来，第15、20、25章

---

## I — 方法论骨架 (Interpretation)

问题出现不等于你必须亲自解决，也不等于可以一推了之。先区分永存、次要、暂态、自造、他人、公共和专门问题，再判断谁拥有结果责任、谁有权限、谁掌握证据。

路由动作至少有五种：自己解决、协助而不接管、归还责任、转交专业节点、留痕升级。重要性和紧急性影响时序，但安全、合规和权利问题会产生报告义务，即使你不是最终所有者。

方法的完成标准不是“问题消失”，而是责任、下一动作、期限和升级条件清晰，且没有制造新的无主问题。

## A1 — 书中的应用 (Past Application)

### 案例：把电脑质量争议推进到可决策层

- **问题**：门店一线人员只能处理维修预约，无法决定质量争议和退换责任。
- **方法论的使用**：作者区分问题与人的关系，逐级要求找到能决策的责任层，同时说明提高音量并非针对个人。
- **结论**：解决复杂问题要把它路由到有责任和权限的节点，而不是与无权者争胜。
- **结果**：商店同意按原价退货，作者最终接受换新并放弃价差。
- **证据位置**：candidates/cases.md c27，第15章

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 同事或客户把问题交给你，但你没有合同、预算或决策权限。
2. 跨团队故障影响重大，需要确定谁主责、谁协助、何时升级。
3. 公共问题不能由个人根除，但可能存在报告、倡议或有限改善责任。

### 语言信号

- “这事不是我权限但会影响项目”
- “我该接手还是升级”
- “这个问题到底归谁”

## E — 可执行步骤 (Execution)

1. **分类问题性质**
   - 动作：判断它是永存、次要、暂态、自造、他人、公共还是专门问题，并记录证据。
   - 完成标准：有一个主类别和必要的次类别，未把情绪标签当成性质。

2. **建立责任—权限—能力矩阵**
   - 动作：列出结果所有者、执行者、决策者、专业节点和受影响者，标记权限与能力缺口。
   - 完成标准：每个关键动作都能指向有权限的人；无主项被显式暴露。

3. **选择路由动作**
   - 动作：在自解、协助、归还、转交、升级中选择，写清自己承担什么、不承担什么。
   - 完成标准：下一动作、责任人、截止时间和回执方式明确。

4. **设置升级与退出条件**
   - 动作：对安全、合规、权利、重大损失和反复无响应设置留痕与逐级升级；普通低价值问题设停止投入阈值。
   - 完成标准：至少一个升级条件和一个停止条件可观察。

### 整体验收与停止

- **完成标准**：问题类型、责任权限矩阵、路由动作、期限和升级条件均有记录，受影响者知道下一节点。
- **停止条件**：自己无授权且合适节点已确认接收时停止代办；出现安全、合规或不可逆损害时停止普通分流并立即升级。
- **复盘方式**：到期检查问题是否到达正确节点、是否产生回执与结果；误路由记录其原因并更新责任图。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不用“这不是我的问题”逃避法定报告、岗位责任、照护义务或安全风险。
- 不替他人无限接管本应由其学习和承担的普通责任。

### 作者在书中警告的失败模式

- 把无力感转成对某个能人的责任投射，或和没有决策权的一线人员反复争吵。

### 作者的盲点 / 时代局限

- 原书个人责任叙事较强，可能低估制度、权力不对等、健康和资源约束；组织路由需以真实职责与政策为准。

### 容易混淆的邻近方法论

- 与 `discussion-goal-routing` 的区别：本 Skill路由问题责任和投入；后者判断对话目标以及继续、退出或升级互动。
