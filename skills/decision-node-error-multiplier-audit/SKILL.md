# 决策节点错误乘数审计

## R — 原文 (Reading)

> 他们只因为多了一招一式
>
> — 李笑来，第5章 为什么很少有人使用定投策略

---

## I — 方法论骨架 (Interpretation)

一个方案的脆弱性不仅取决于单步质量，还取决于必须连续正确多少次。即便每一步看似可靠，多个节点相乘后，完整成功率会快速下降。

先画出所有会改变结果的决策节点，区分必要判断与人为增加的动作。对必要节点加证据、检查表和防错；对非必要节点删除、批处理、自动化或预承诺。

简化的目标不是少思考，而是把有限判断力留给真正改变结果的节点，并保留安全、合规和退出门。

## A1 — 书中的应用 (Past Application)

### 案例：主动基金六十八倍收益仍多次濒临归零

- **问题**：作者管理的早期基金在约五年中实现高倍增长，但过程中多次接近归零，促使他反思主动管理的风险与幸存偏差。
- **方法论的使用**：作者把该经历用于检查收益路径审计、主动管理风险边界，而不是只展示结果。
- **结论**：案例能说明方法如何进入真实行动，但不能从一个成功样本推出普遍因果。
- **结果**：名义结果约68倍，但作者随后转向更重视被动策略；高收益不能抹去期间的毁灭性风险。
- **证据位置**：`candidates/cases.md` c08，第6章（PDF p63—67）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 策略需要连续多次择时或审批才能成功
2. 团队给流程不断增加可选动作
3. 单步看似正确但整链经常失败

### 语言信号

- “每一步胜率都不低为什么总失败”
- “这个流程决策点太多”
- “能不能少做几个判断”
- “decision node risk”

### 与相邻 skill 的区分

- 与 `whole-action-chain-validity-audit` 的区别：本 Skill 量化并减少失误节点；后者检查必要动作是否齐全和衔接有效。
- 与 `investment-decision-firewall` 的区别：本 Skill适用于跨域流程与策略；投资防火墙专门拦截高风险投资偏差。

## E — 可执行步骤 (Execution)

1. **枚举决策节点**
   - 动作：画出从启动到结果的所有判断、批准、切换和退出节点。
   - 完成标准：每个节点有输入、责任人和错误后果。

2. **估算联合脆弱性**
   - 动作：用历史数据或保守区间估每个节点正确率，计算或定性判断连续正确的联合难度。
   - 完成标准：找出贡献最大风险的前三个节点，不伪造精确概率。

3. **删除与预承诺**
   - 动作：对节点选择删除、默认规则、自动化、批处理、检查表或保留临场判断。
   - 完成标准：每个非必要节点有处置，必要安全门被明确保留。

4. **小样本复跑**
   - 动作：用简化链跑一个周期，比较错误数、等待和结果质量。
   - 完成标准：有前后对照及恢复被误删节点的条件。

### 整体验收与停止

- **完成标准**：决策链、联合脆弱性、节点处置和复跑证据齐全，关键风险节点减少或被防错。
- **停止条件**：简化将删除安全、法律、财务控制或单点故障保护时停止，转治理评审。
- **复盘方式**：每轮记录真实错误发生在哪个节点；连续两轮无价值但仍耗注意力的节点进入删除评审。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不得删除必要安全合规和授权检查
- 没有数据时只用区间和敏感性分析，不伪造概率

### 作者在书中警告的失败模式

- 不断增加招式和临场判断，忽视“每一步都要对”带来的乘法脆弱性。

### 作者的盲点 / 时代局限

- 原书以投资选择解释动作数量，没有给出严格概率模型；复杂系统中节点可能相关，不能简单假设独立。

### 容易混淆的邻近方法论

- 与 `whole-action-chain-validity-audit` 的区别：本 Skill 量化并减少失误节点；后者检查必要动作是否齐全和衔接有效。
- 与 `investment-decision-firewall` 的区别：本 Skill适用于跨域流程与策略；投资防火墙专门拦截高风险投资偏差。
