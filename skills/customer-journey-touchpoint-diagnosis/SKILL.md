# 消费者旅程触点诊断

## R — 原文 (Reading)

> 将用户从认知企业的产品和服务，到最终购买流程的可视化表现。
>
> — 《分章节P1-04 市场营销战略》Slide 14, lines 211-219

> A认知、A吸引、A问询、A行动、A拥护。
>
> — 《分章节P1-04 市场营销战略》Slide 14, lines 220-242

## I — 方法论骨架 (Interpretation)

消费者旅程诊断把“转化不好”从一个笼统问题拆成连续触点。用户不会突然购买，通常会经历看见、被吸引、主动询问、采取行动和愿意推荐。

每个阶段都有不同的任务：认知阶段解决“知道你是谁”，吸引阶段解决“为什么与你有关”，问询阶段解决“我还担心什么”，行动阶段解决“如何低阻力完成”，拥护阶段解决“为什么愿意复购或推荐”。

这个方法的关键是站在用户角度观察行为、想法、情绪和痛点，再决定下一步动作，而不是先改标题、降价或加投放。

## A1 — 书中的应用 (Past Application)

### 案例 1: 购买流程可视化

- **问题**: 企业不知道用户从认识产品到购买之间经历了哪些关键接触点。
- **方法论的使用**: 先设定用户画像，再分析购买流程，最后整理每个阶段应提供的信息和存在课题。
- **结论**: 每个阶段都需要不同信息和动作。
- **结果**: 运营动作从单点优化变为旅程诊断。

### 案例 2: 人群差异化运营

- **问题**: 不同用户群体在认知、兴趣、承接、首购、复购阶段需求不同。
- **方法论的使用**: PPT 将站外曝光、内容种草、私域沟通、直播权益、客服、榜单推荐等触点放入人群链路。
- **结论**: 触点要随人群和阶段变化。
- **结果**: 避免用同一套话术触达所有用户。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 课程、咨询、门店、电商、社群、SaaS 或内容产品转化下降，但不知道卡在哪里。
2. 用户反馈分散，有客服记录、访谈、数据或社群留言，需要串成旅程图。
3. 团队争论该改标题、价格、投放、客服还是交付。
4. 用户想优化复购、推荐或私域承接，但还没定位掉点。

### 语言信号

- “报名率低，不知道问题在哪”
- “帮我画用户旅程”
- “哪个触点掉了？”
- “customer journey / touchpoint / funnel drop”

### 与相邻 skill 的区分

- 与 `platform-playbook-currentness-audit` 的区别: 本 skill 诊断用户旅程掉点；平台打法 skill 审计具体平台玩法是否过期、可迁移。
- 与 `private-domain-fit-boundary-audit` 的区别: 本 skill 判断旅程和触点；私域 skill 判断是否适合反复触达和怎么守边界。

## E — 可执行步骤 (Execution)

1. **定义目标用户与目标动作**
   - 完成标准: 写清一个用户群体、一个目标动作和当前异常指标。

2. **画 5A 旅程**
   - 完成标准: 列出认知、吸引、问询、行动、拥护各阶段的用户行为、触点和情绪。

3. **填入证据**
   - 完成标准: 每个判断至少标注一个来源: 转化数据、客服记录、访谈、用户留言、可用性测试或现场观察。
   - 判停条件: 如果只有团队臆测，没有任何用户证据，先做最小访谈或数据核验。

4. **定位掉点和痛点**
   - 完成标准: 找出 1-3 个最大掉点，并说明用户在该阶段缺什么信息、信任、动力或操作便利。

5. **生成触点改进动作**
   - 完成标准: 每个掉点对应一个改进动作、一个验证指标和一个观察周期。

6. **复盘是否迁移**
   - 完成标准: 改动后对比目标指标和用户反馈；若掉点转移，重画旅程。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 没有用户行为证据，只想凭想象画画像。
- 产品价值本身未验证，应先做用户访谈或市场反馈。
- 用户要求通过恐惧、羞耻或过度打扰推动转化。

### 作者在书中警告的失败模式

- 只设画像，不看真实购买流程。
- 只看某个触点，不整理每阶段应提供的信息和课题。

### 作者的盲点 / 时代局限

- PPT 对隐私授权、数据口径和跨渠道归因讲得不足；使用时必须标出证据来源和不确定性。

### 容易混淆的邻近方法论

- 漏斗分析偏指标变化；旅程诊断要补用户想法、情绪和信息需求。
- 用户画像不是旅程，画像必须在旅程中被行为证据校正。
