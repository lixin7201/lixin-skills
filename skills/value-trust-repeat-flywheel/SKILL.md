# 价值—信任—复购飞轮

## R — 原文 (Reading)

> 尽早去实现你的闭环，为用户创造价值。不断地为用户提供价值，从而获得更多的用户和拥趸。
>
> — 姜胡说，第十六章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

超额解决当前问题、公开可验证结果、持续提供相关价值，让信任和转介绍自然降低下一次交易成本。

它的独特性在于：把利他、价值交付、信任、复购和社会网络明确写成长期现金流飞轮。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 油田培训建立信任并带来数据迁移项目
- **问题**: 作者给胜利油田技术人员上定制课程，连续一周在正式课后继续交流到门卫催场。
- **方法论的使用**: 高投入的交付建立了信任，半年后对方邀请他组建四人团队承接数据迁移项目。 项目最终亏损，也暴露出只估能力、不计房租差旅和协作成本的管理缺口。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 获得第一个正式组建团队的项目，但因缺乏成本与分配经验而亏损。

### 案例 2: 公开工作日志持续带来项目与咨询
- **问题**: 作者创办软件“包工队”后，把工作过程、经验和反思持续发到网上。
- **方法论的使用**: 公开输出既展示能力，也让潜在客户在需要时能找到他，逐渐形成项目和咨询的稳定来源。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 许多业务由日志内容带来，并逐渐获得企业分享和咨询邀请。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **定义可感知价值**
   - 完成标准: 客户能明确说出结果、节省或风险降低

2. **稳定超额交付**
   - 完成标准: 承诺可兑现，关键节点主动沟通，不靠一次惊喜
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **沉淀信任证据**
   - 完成标准: 记录结果、反馈、案例与边界，透明处理失败

4. **设计自然复购**
   - 完成标准: 后续服务源于持续问题和新价值，并跟踪复购与转介绍

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 产品本身无效、想用话术掩盖价值不足，或把关系经营等同频繁打扰。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 只提高小时单价，没有沉淀可复制产品、系统、用户或生产性资产。 个人时间存在硬上限，停止工作收入即停止，长期无法形成规模与复利。

### 作者的盲点 / 时代局限

- 作者案例以个人品牌和知识服务为主；低频耐用品的复购周期与机制不同。

### 容易混淆的邻近方法论

- `users-before-product` 与 `self-investment-flywheel`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
