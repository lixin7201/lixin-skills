# 内容库最小结构建设

## R — 原文 (Reading)

> 产品信息：包装/图片/价格/评价/认证/背书等；用户痛点；产品卖点；适用人群；使用场景。
>
> — 《分章节P3-05 新媒体运营模型》Slide 12

> 客服话术、直播话术、评价回复话术、投诉处理话术、视频拍摄话术、KOL合作流程和话术。
>
> — 《分章节P3-05 新媒体运营模型》Slide 12

## I — 方法论骨架 (Interpretation)

内容库不是把素材丢进文件夹，而是把内容生产所需的“人、货、场、证据、话术、边界”结构化。它让团队每次创作都能从已验证的产品信息、用户痛点、卖点、使用场景、素材、客服反馈和禁用表达中取材。

最小内容库不追求大而全。先建能反复调用的几个字段：产品事实、用户痛点、核心卖点、适用人群、场景、证明材料、常用话术、素材来源、禁用边界和更新时间。

这个 skill 的目标是把内容生产从“临时灵感”变成“可复用资产”，同时避免未经授权收集用户信息、堆砌标签和复制过期平台话术。

## A1 — 书中的应用 (Past Application)

### 案例 1: 产品与用户内容库

- **问题**: 新媒体内容需要持续产出，但产品信息、用户痛点、卖点和场景分散。
- **方法论的使用**: PPT 将产品信息、用户痛点、产品卖点、适用人群、使用场景、健康知识放进内容库。
- **结论**: 内容生产应围绕人、货、场和证据组织。
- **结果**: 选题、脚本、客服和直播不再每次从零开始。

### 案例 2: 话术和素材标签

- **问题**: 客服、直播、评价回复、投诉处理、视频拍摄和 KOL 合作话术不统一。
- **方法论的使用**: PPT 要求建立话术库、素材库、资源库，并示例用视频类型、风格、镜头、开箱方式、字幕、音乐、场景和角色做标签。
- **结论**: 内容资产要能检索和复用。
- **结果**: 内容库服务持续生产和标签转化，而不是一次性素材堆积。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 内容账号、品牌、课程或产品每次发内容都临时想，产出不稳定。
2. 团队有大量素材、评论、客服记录、卖点、案例，但无法复用。
3. 多人协作时客服、直播、短视频、销售和文章话术不一致。
4. 用户要做内容库、素材库、选题库、KOL 库或 FAQ 库的最小结构。

### 语言信号

- “帮我建内容库”
- “素材太散，怎么整理？”
- “账号选题总从零开始”
- “content library / asset library / swipe file”

### 与相邻 skill 的区分

- 与 `evergreen-content-fertility-filter` 的区别: 本 skill 建内容资产结构；evergreen skill 判断单条内容是否有长期肥力。
- 与 `new-media-channel-fit-stop-rule` 的区别: 本 skill 解决内容供给；渠道 skill 解决投放/发布到哪里以及何时停止。
- 与 `brand-house-positioning-benefit-rtb-audit` 的区别: 内容库字段要继承定位、利益点和 RTB，不能脱离品牌证据。

## E — 可执行步骤 (Execution)

1. **确定内容库服务对象**
   - 完成标准: 写清内容库服务的品牌/产品/账号、主要用户、主渠道和本月目标。

2. **建 8 个最小字段**
   - 完成标准: 建立产品事实、用户痛点、核心卖点、适用人群、使用场景、证明材料、常用话术、禁用表达。

3. **给每条素材打证据标签**
   - 完成标准: 每条素材标注来源、更新时间、证据等级、适用场景、可用渠道和是否需授权。
   - 判停条件: 涉及真实用户、截图、隐私、医疗/金融/教育结果或合作方资料时，未授权不得入库或发布。

4. **补一个复用模板**
   - 完成标准: 至少生成 1 个短视频脚本模板、文章选题模板、客服回复模板或直播话术模板。

5. **建立维护节奏**
   - 完成标准: 设定每周新增、每月清理、过期标注和禁用表达复查机制。

6. **连接输出任务**
   - 完成标准: 从内容库中生成 3 个可执行选题，并标明所用字段。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只需要写一篇文章或一条短视频文案，不需要沉淀库。
- 没有产品事实、用户痛点或证据，只想编素材。
- 想把未授权用户信息、聊天记录、隐私标签或竞品素材直接入库发布。

### 作者在资料中的失败模式提示

- 内容库要全面覆盖人、货、场，并进行有效标签转化；不能只是素材堆积。
- 内容概念、用户圈层和渠道选择必须回到用户真实需求和品牌定位。

### 作者的盲点 / 时代局限

- PPT 对版权、隐私授权、数据保留期限和平台内容合规提示不足；实际使用必须补这些字段。
- 平台热门内容标签会过期，内容库要标更新时间和适用渠道。

### 容易混淆的邻近方法论

- 内容库不是选题灵感清单，而是证据、素材、话术和边界的复用系统。
- KOL/达人库不是联系人表，必须标合作授权、适用人群、历史效果和风险记录。
