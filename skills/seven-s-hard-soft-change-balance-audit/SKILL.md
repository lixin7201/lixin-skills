# 7S 组织软硬件平衡审计

## R — 原文 (Reading)

> 企业在发展过程中必须全面地考虑各方面的情况，包括结构、制度、风格、员工、技能、战略、共同的价值观。
>
> — 《分章节P1-06 组织团队管理》Slide 14

> 其中硬件有战略、结构和制度3项，软件有风格、技能、员工和共享价值观4项。
>
> — 《分章节P1-06 组织团队管理》Slide 14

> 只对硬件要素改善并不能使企业整体得到改善，如果不对构成企业基础的软件要素进行彻底改革就无法实现企业变革。
>
> — 《分章节P1-06 组织团队管理》Slide 15

## I — 方法论骨架 (Interpretation)

7S 的核心不是“列出七个词”，而是检查组织变革有没有只改硬件、不改软件。战略、组织结构、制度流程属于硬件 3S，比较容易写进 PPT 和制度；风格、技能、员工、共同价值观属于软件 4S，通常更慢、更隐性，也更容易被忽略。

当战略落地失败、部门协作差、制度推不动、人才跟不上时，不要急着归因到“执行力差”。先把七个要素各自的现状、证据和错位关系摆出来，看是战略不清、结构冲突、制度阻塞、管理风格不匹配、能力不足、人才结构缺口，还是价值观没有共识。

这个 skill 的产物是一份“组织错位台账”和“最小干预点”，不是完整组织咨询报告。它帮助 agent 先降低误诊风险，再决定是否转战略、沟通、授权、培训或制度优化。

## A1 — 资料中的应用 (Past Application)

### 示例 1: 部门间缺乏合作

- **问题**: PPT 示例中组织结构现状是部门间缺乏合作，领地意识强。
- **方法论的使用**: 将问题放入 7S 的结构维度，再和共同价值观、系统、风格联动检查。
- **结论**: 改善方案不是只改汇报线，而是加强部门之间交流，促进组织内部合作。
- **结果**: 问题从“某部门不配合”变成“结构和协作机制错位”。

### 示例 2: 战略和文化不匹配

- **问题**: PPT 示例同时列出事业战略方向不明确、组织文化保守、共享经营理念不足。
- **方法论的使用**: 将战略、文化、共享价值观分开检查，避免只写战略口号。
- **结论**: 要明确战略，也要通过对话、研修和文化建设让经营理念被共享。
- **结果**: 变革从硬件制度推进，扩展到软件共识和能力建设。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 公司战略、组织架构或制度调整后，团队行为没有变化。
2. 跨部门协作差，大家互相指责，但不知道是结构、制度、能力还是文化问题。
3. 团队扩张后流程变复杂、管理风格失灵、人才能力跟不上。
4. 用户想做组织诊断，但需要避免空泛咨询话术和越权改造。

### 语言信号

- “战略定了但组织推不动”
- “部门墙很重 / 各自为政”
- “是不是组织结构、制度、文化不匹配？”
- “7S audit / hard-soft alignment / organization change”

### 与相邻 skill 的区分

- 与 `strategy-house-alignment-check` 的区别: 战略屋检查目标、战场、能力和保障机制是否一致；本 skill 检查组织内部七要素的软硬错位。
- 与 `delegation-readiness-leadership-style-check` 的区别: 单个下属或任务授权问题转授权 skill；跨团队、跨制度、跨文化问题才用本 skill。
- 与 `communication-understanding-execution-loop` 的区别: 单次沟通理解断裂转沟通 skill；制度、结构、风格和价值观共同失配时用本 skill。
- 与 `strategy-model-evidence-gate-router` 的关系: 战略方向不清时先选战略模型和证据；战略已定但组织承接失败时用 7S。

## E — 可执行步骤 (Execution)

1. **界定变革症状和范围**
   - 完成标准: 写清具体症状、涉及团队、时间范围、业务影响和用户拥有的权限。
   - 判停条件: 如果用户没有任何组织影响权限，只输出观察/沟通/取证建议，不给组织改造命令。

2. **画出 7S 现状表**
   - 完成标准: 分别填写战略、结构、制度、风格、员工、技能、共同价值观的现状和证据来源。

3. **区分硬件问题和软件问题**
   - 完成标准: 标出硬件 3S 已经改了什么、软件 4S 是否跟上。
   - 判停条件: 如果只有主观抱怨没有访谈、数据、制度或行为证据，先转取证。

4. **找错位链条**
   - 完成标准: 写出 1-3 条“因为 A 没跟上，所以 B 推不动，造成 C 结果”的错位链。

5. **选择最小干预点**
   - 完成标准: 给出一个低风险、可验证的组织动作，例如对齐会议、流程试点、角色澄清、培训、制度小改或价值观沟通。

6. **设置复盘和升级条件**
   - 完成标准: 写清验证周期、观察指标、反馈渠道，以及何时升级到管理层、HR、法务或外部专业支持。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只是要写战略规划、选战略模型，应转 `strategy-model-evidence-gate-router` 或 `strategy-house-alignment-check`。
- 用户只是在布置一个任务、辅导一个人或判断授权方式，应转 `delegation-readiness-leadership-style-check`。
- 用户只是一次沟通没说清楚，应转 `communication-understanding-execution-loop`。
- 涉及裁员、劳动纠纷、歧视、骚扰、心理安全或合规风险时，不能用 7S 简化处理。

### 资料中的失败模式提示

- PPT 明确提示“只对硬件要素改善”不能让企业整体改善；这是本 skill 的主要反例。
- PPT 示例中的部门墙、战略不明、内部网络失效、人才缺乏、文化保守、理念未共享，都说明组织问题不能单点归因。

### 作者的盲点 / 资料局限

- PPT 是模型速览，没有提供真实组织变革的访谈方法、权力结构和利益冲突处理。
- 7S 容易被滥用成高层单向诊断；实际使用必须保留员工反馈、申诉和心理安全边界。

### 容易混淆的邻近方法论

- 7S 不是万能组织诊断报告；它只适合先查软硬要素错位。
- 7S 不是绩效追责工具；不能把组织系统问题简化成某个员工执行力差。

## 相关 skills

- contrasts-with: `strategy-house-alignment-check`。战略屋看外部战场和内部能力承接，7S 看组织七要素软硬平衡。
- contrasts-with: `delegation-readiness-leadership-style-check`。个人任务授权不升级为组织诊断。
- composes-with: `communication-understanding-execution-loop`。发现沟通机制错位后，可用沟通 skill 做单次闭环。
- composes-with: `strategy-model-evidence-gate-router`。战略方向不清时先补战略证据，再审计组织承接。
