# TH 三类问题故事路由

## R — 原文 (Reading)

> "根据问题类型不同，构成演示流程的重要课题也不同。"
>
> — 高杉尚孝，第二章

## I — 方法论骨架 (Interpretation)

同一个提案不能永远按同一种故事讲。  
作者把演示中的问题分为三类: 已经损坏要恢复原状、风险尚未发生要预防潜在问题、现状未坏但要追求理想。  
不同类型对应不同故事主轴: 原因和修复、诱因和预案、目标差距和策略。  
如果问题类型与听众认知错位，说服会变成夸张或跑题。  
这个 skill 用于选择演示故事，不替代问题诊断本身。

## A1 — 书中的应用 (Past Application)

### 案例 1: 小田岛误判问题类型
- **问题**: 小田岛把股票回购建议包装成严重问题修复。
- **方法论的使用**: 作者指出对方并没有把现状看作恢复原状型问题。
- **结论**: 问题类型与听众认知不一致，会触发反弹。
- **结果**: Good Example 改为更贴近对方认知的预防/改善框架。

### 案例 2: 大型巨额提案适合预防型
- **问题**: 昂贵系统或大型投入难以只靠理想收益说服。
- **方法论的使用**: 作者建议大型巨额情况可采用预防潜在问题型故事结构。
- **结论**: 高成本决策往往要先讲风险诱因、预防措施和应急方案。
- **结果**: 听众更容易理解投入的紧急性和合理性。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 推动安全、合规、技术、流程或组织投入，不知讲风险还是收益。
2. 听众不承认问题严重，用户却准备了危机叙事。
3. 提案主轴混乱，既讲修复、又讲预防、又讲理想。
4. 已定义希望听众行动，但不知道故事顺序。

### 语言信号

- "这个提案该讲风险还是收益?"
- "对方不觉得这是问题"
- "恢复原状/预防潜在/追求理想是哪类?"
- "TH problem type / story routing"

### 与相邻 skill 的区分

- `presentation-action-change-brief` 先定义听众 A/B 和行动；本 skill 再选故事主轴。
- `problem-definition-r1-r2-diagnostic-tree` 用于诊断真实问题和根因；本 skill 用于演示中如何讲这个问题。
- `scqa-reader-question-introduction` 处理序言的 S-C-Q-A；本 skill 处理整场故事类型。

## E — 可执行步骤 (Execution)

1. **判定问题状态**
   - 已损坏? 未发生但风险大? 现状可接受但想更好?
   - 完成标准: 三类只能选一个主类，其他作为辅助。

2. **校准听众认知**
   - 写出听众是否承认问题、承认程度、最关心成本/风险/收益哪一项。
   - 判停条件: 若听众不承认问题存在，先做认知对齐，不直接上危机叙事。
   - 完成标准: 主问题类型与听众当前认知相容。

3. **生成故事骨架**
   - 恢复原状型: 现状 -> 原因 -> 根本措施 -> 防再发。
   - 预防潜在型: 糟糕未来 -> 诱因 -> 预防策略 -> 应急方案。
   - 追求理想型: 理想 -> 差距 -> 策略 -> 行动计划。
   - 完成标准: 每一页或段落能归入骨架节点。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 真实问题和根因尚未定义，需要先做问题诊断。
- 用户只有序言开头问题，优先 SCQA。
- 为了说服故意夸大风险、隐藏成本或压制反对意见时，停止。

### 作者在书中警告的失败模式

- 把对方不认可的问题说成紧急灾难，激发反感和防御。

### 作者的盲点 / 时代局限

- 三类问题不能覆盖所有探索、共创、教育和复杂政治场景。
- 商务演示中的故事路由不证明结论正确，证据不足仍须标注假设。

### 容易混淆的邻近方法论

- TH 路由选故事，金字塔检查逻辑层级。
- 预防型不是恐吓；必须有诱因、概率、损失和预案证据。
