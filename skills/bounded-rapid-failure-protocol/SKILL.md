# 有界快速失败协议

## R — 原文 (Reading)

> “炸了以后反思、学习、修正，重复冒险。”
>
> — 沃尔特·艾萨克森，第95章“星舰发射”

## I — 方法论骨架 (Interpretation)

快速失败的目标不是追求失败，而是用最小、可逆、可观察的代价换取会改变下一步决策的信息。试验前必须写明未知问题、失败最大损失、最低成功标准、要回收的数据、停止阈值和回退方案。试验后根据证据修改设计；若没有得到新信息或不执行修正，失败只是浪费。

## A1 — 书中的应用 (Past Application)

### 案例 1：猎鹰 1 号连续试射

- **问题**：小团队无法在纸面上消除所有火箭未知风险。
- **方法论的使用**：每次发射回收遥测和残骸信息，定位燃料晃动、级间分离等问题后修改。
- **结论**：真实飞行数据比长期模拟等待更快暴露系统问题。
- **结果**：前三次失败后，第四次成功入轨。

### 案例 2：星舰首次综合飞行

- **问题**：一次入轨概率低，但继续等待也无法获得完整飞行数据。
- **方法论的使用**：事前把起飞、远离人群并回收大量数据定义为最低成功。
- **结论**：即使飞行器最终爆炸，试验仍可产生有效学习。
- **结果**：获得发动机、发射台和飞行问题数据；同时导焰系统不足造成额外损害，构成边界反例。

## A2 — 触发场景 (Future Trigger)

1. 新产品、流程、模型或技术路线存在关键未知，仅靠讨论无法消除。
2. 团队想做全量上线，但可以先用沙箱、样机、灰度或小流量试验。
3. 一次失败可接受，但必须知道最多损失多少、何时停止。
4. 需要区分“业务结果失败”和“学习目标成功”。

### 语言信号

- “怎么快速试错但别把事情搞砸？”
- “这个实验失败到什么程度还算有价值？”
- “先做小范围试验还是继续分析？”
- “Design a bounded experiment / safe-to-fail test。”

### 与相邻 Skill 的区分

- 与 `end-first-minimum-loop` 的区别：后者倒推最小完整交付；本 Skill 处理高不确定试验的风险、数据和停止协议。
- 与 `surge-mode-governor` 的区别：本 Skill 约束单个试验；后者约束短期组织运行模式。
- 与 `open-loop-feedback-recovery` 的区别：本 Skill 假设团队愿意被证据改变；若反馈已被拒绝，应先恢复开环。

## E — 可执行步骤 (Execution)

1. **写出唯一未知问题**
   - 形式为“如果做 X，Y 是否在条件 Z 下成立？”
   - 完成标准：试验结果能改变一个具体决定。

2. **划定风险边界**
   - 列出资金、时间、数据、用户、安全、法律和声誉的最大允许损失。
   - 完成标准：每类损失都有数值或明确阈值，且负责人同意。
   - 判停条件：存在人命、不可逆健康、违法、无法恢复的数据或无法隔离的公共风险时，不进入快速失败。

3. **定义最低成功与停止条件**
   - 区分业务成功、技术成功和学习成功。
   - 写明触发自动停止、人工停止和回退的指标。
   - 完成标准：在结果出现前冻结验收标准。

4. **设计最小可逆试验**
   - 优先沙箱、仿真、样机、影子流量、灰度、小区域或可回滚版本。
   - 完成标准：失败不会突破第2步边界，数据足以回答第1步。

5. **执行并完整回收证据**
   - 记录预期、实际、异常、未观测项和外部影响。
   - 停止条件：任一风险阈值触发，立即停止并回退，不以“再坚持一下”覆盖协议。

6. **做出下一轮决定**
   - 选择继续、修改、扩大、缩小或终止，并说明证据。
   - 完成标准：至少有一个设计或决策因结果而改变；否则判为无效试验。

## 复盘方式

- 检查验收标准是否在结果出来后被改写。
- 计算每单位损失换来的决策信息，连续两轮没有新增信息即停止。
- 记录外部影响是否超出边界；若超出，下轮先加强隔离而不是提高容忍度。

## B — 边界 (Boundary)

- 不用于人身安全、不可逆医疗、违法、未经同意的人体/用户实验。
- 核心数据迁移必须有备份、回滚和一致性验证。
- 第23章防晃隔板和第95章导焰系统显示：低估安全后果不是快速失败，而是风险转嫁。
- 公开平台、隐私和信任的损失难以回滚，不应照搬火箭原型逻辑。
- 失败后不复盘、不修正或只庆祝“学到了”，一律不算通过。
