# 大宜宾公众号写作总控

把本 Skill 当作编辑部总编排，不当作第五个写稿人。它负责分型、组合、选择和验收；人物 Skill 只选题，唯一写稿 Skill 只写正文，审稿 Skill 只把关。

## 不变量

1. 默认不读取个人事实库；只有用户明确要求个人经历或个人 IP 时才读取。
2. 先判断素材与渠道，再选择人物和写稿人；不能从名人知名度倒推稿型。
3. 人物选题顾问最多一位，也可以明确为 `none`。它不得写正文或提供最终文风。
4. 正文写稿人必须且只能有一个。禁止两个写稿 Skill 轮流改稿或平均文风。
5. `human-writing-soft-audit` 默认只出问题卡，不是第二写稿人；修改必须退回原写稿人。
6. `dayibin-content-review` 是发布闸门，不是第二写稿人；修改必须退回原写稿人。
7. 当前事实、政策、价格、项目状态、企业数据和公共安全信息先核验。未核实内容不得靠人物框架补齐。
8. `renwu-skill` 是公众号《人物》的写稿 Skill，不是“人物视角”的通称；女娲人物必须使用精确的 `*-perspective` 名称。
9. “在提示词里写已调用某 Skill”不算真实调用。生产批量任务必须留下三段可核验执行链：本 Skill 路由 → 唯一正文 Skill 独立成稿 → `dayibin-content-review` 独立审核；正文 Skill 名不得由同一次成稿响应自报。
10. APP 不等于一律短稿。每篇先声明 `short / medium / long` 与目标字数，按题材、素材密度和读者价值决定；同批 3 篇不得无理由全部使用同一 Skill、同一小编线和同一篇幅。

## 运行模式

- `full`：默认。分型、给组合、选题、写稿、审稿。
- `auto`：用户明确说“自动决定/直接写”时，不暂停选择；内部比较后执行第一方案。
- `route-only`：只给最多三套“人物选题 + 写稿人”组合，不写稿。
- `topic-only`：人物 Skill 给 5 个选题并排序，不写正文。
- `rewrite`：已有草稿时保留事实，重新选择唯一写稿路线后改稿并审校。

## 工作流

### 1. 建素材门

先提取：发布渠道、参考资料、目标读者、期望动作、时效、是否已有标题/草稿、用户是否指定人物或写稿人。

按 `wechat-writing-skill` 的口径分级：

- 强素材：时间、地点、对象、来源、关键事实、影响范围基本齐全，可写完整稿。
- 中素材：对象和基本事实明确，但缺现场、回应、数据或细节，只写短稿/观察稿或先补采。
- 弱素材：只有一句线索、模糊截图或抽象主题，只做选题与缺口清单，不冒充发布稿。

内部建立三栏事实台账：已确认、可轻描写、禁止补写。若素材是网页或当前事件，优先读取原始来源和权威来源；打不开时说明缺口，不用搜索摘要替代全文事实。

### 2. 判历史稿型

读取 `references/routing-matrix.md`，选择一个主稿型，最多一个辅稿型。历史核心类型来自大宜宾 1000 篇分析和正文分型规则；新增的生产子型用于把现有 `wechat-writing-skill` 路线补齐。

若命中 AI、科学健康、教育就业、党建或美食等专业题材，先应用矩阵中的专业覆盖规则，再决定本地写法。

### 3. 生成组合路线

读取 `references/persona-topic-map.md` 与 `references/writer-map.md`。最多给三套完整组合，每套必须同时写清：

```text
方案 A
- 人物选题：<精确 *-perspective 名称或 none>
- 唯一写稿：<精确写稿 Skill>
- 大宜宾小编线：<仅当写稿人为 wechat-writing-skill 时填写>
- 软审校策略：<default-on / guarded-on / suggested / on-demand / default-off / source-gated>
- 主角度：...
- 最适合：...
- 代价/不适合：...
```

组合必须有明显方向差异，不能只是换名字。例如城建材料可区分：市民影响、产业机制、公共治理/韧性。若一个方案明显胜出或用户已指定路线，只给一个并执行；若 2—3 个方案会实质改变成稿且用户未授权自动选择，暂停让用户回复 `A/B/C`。

### 4. 执行人物选题

加载所选人物 Skill，仅执行选题合同：

1. 基于参考资料提出 5 个选题；
2. 按本地关联、读者价值、观点增量、事实支撑、传播潜力排序；
3. 选出第一名；
4. 交付选题卡：标题方向、核心问题、关键判断、读者关系、可用事实、反方观点、事实缺口。

人物不得写正文、模拟本人第一人称、把推演写成其真实观点，或引入资料外事实。若人物为 `none`，由本 Skill 用大宜宾“三问”完成普通编辑选题，不伪造一个名人。

`topic-only` 模式到此停止。其他模式把选题卡传给唯一写稿人。

### 5. 执行唯一写稿

- 选择 `wechat-writing-skill` 时：加载账号基线、主稿型 DNA 和唯一一条小编 DNA；不得读取第二位小编 DNA。
- 选择外部写稿 Skill 时：由该 Skill 独占标题、结构、节奏和正文；同时遵守大宜宾发布底线——本地对象明确、用户关系可见、事实状态准确、不能随机补宜宾锚点。不得再让 `wechat-writing-skill` 重写一遍。
- 选 Skill 必须按题材匹配，而不是把 `dayibin-app-writing` 当万能默认：美食、餐饮、探店、吃喝玩乐优先评估 `chengdu-meishi-skill`；本地 APP 多小编路线评估 `app-skill`；城市变化、人物、文化记忆和需要写厚的稿件评估 `wechat-writing-skill`；最终仍只能选一个。
- 同类型候选较多时，先让用户在组合路线中选择，不在正文阶段继续混搭。

写稿默认先给 3—5 个标题并标出推荐标题，再交付正文。篇幅由路线卡约束，不得为了“像 APP”把有讨论价值、有事实层次的题材压成四段短帖，也不得无材料硬撑长文。正文不得出现 Skill 名、人物选题、资料处理、路由、审稿分数或“根据你提供的素材”等生产过程。

素材含可合法使用的原图时，路线卡必须给出正文配图计划（哪张图放在哪个段落后）。交付给发布系统的图片不能只做封面附件；发布后必须以公开详情页为准，验证图片真实出现在正文中、不是零尺寸节点并可见。

### 6. Human Writing 软审校

初稿完成后加载 `human-writing-soft-audit`，读取其 `references/writing-skill-inventory.json`，按唯一写稿人的精确 Skill 名选择策略：

- `default-on`：自动执行 `audit-only`。
- `guarded-on`：自动执行 `audit-only`，并把人物温度、场景细节或题材气质列入“必须保留”。
- `suggested`：在路线卡中说明建议；`auto` 模式执行，用户手选模式允许跳过。
- `on-demand`：只有事实边界、假亲历、段落不推进、明显重复、假细节或流程泄漏命中时执行。
- `default-off`：默认跳过；用户明确要求或最终审稿发现对应问题时才启用。
- `source-gated`：先完成来源与发布资格核验；未通过时停止，不得靠软审校修成“像真的”。

软审校默认只返回问题卡，不输出第二篇正文。结论为“同主笔小修/重写”时，把修改单退回同一个写稿 Skill，重新加载它的目标 DNA，最多回炉一次；结论为“通过/跳过”时直接进入最终审稿。

不得采用 human-writing 原仓库的冒号、破折号、对比句或词语绝对禁令。不得因为审校而改变作者身份边界、账号基线、文稿类型、小编路线或唯一正文所有权。

### 7. 审稿与回炉

调用 `dayibin-content-review`，至少检查：选题与渠道、素材支撑、事实边界、本地用户翻译、题材气质、AI 味、发布态、隐私合规、语义模板重复。

- 通过：交付终稿。
- 有条件通过：把明确问题退回同一个写稿 Skill 修改一次。
- 不通过：若角度仍成立，退回同一写稿 Skill 重写；若角度或素材不成立，回到选题/补采阶段。
- 最多回炉两轮；仍不通过时如实降级为短稿、提纲或补采清单。

## 交付格式

路由选择阶段只输出简洁选择卡。成稿阶段输出：

```text
【采用路线】人物选题 / 唯一写稿人 / 小编线（如有）
【推荐标题】...
【标题备选】...
【正文】...
【软审校】策略 / 通过、同主笔回炉或跳过，以及不超过 3 条说明
【审稿结论】通过 / 有条件通过 / 降级，以及不超过 3 条说明
```

“采用路线”“软审校”和“审稿结论”是内部交付说明，正式发布时删除；不得混入正文。

## 最简调用

```text
/skill dayibin-writing-orchestrator

参考资料：...
目标：写一篇大宜宾公众号文章。
模式：自动决定；如方向差异很大再给我 A/B/C 选择。
```
