# 伦理化的感知—行动设计

## R — 原文 (Reading)

> 影响用户的感知，最终是为了影响用户的感受。感受才是形成认知、采取行动的主因。
>
> — 姜胡说，第十五章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

分别检查是否想做、是否容易做、是否在正确时刻收到提示，并调整感知与摩擦；不得用欺骗或恐惧替代真实价值。

它的独特性在于：把平台语言、感知链和行为三条件串联，并用“只营销自己愿意买的东西”设伦理边界。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 支付宝用一句忘发了让广告评论超过正文点赞
- **问题**: 支付宝在促销通知中加入“对，是昨天……我昨天忘记发了嘛”，用不完美的口语表达拉近距离。
- **方法论的使用**: 读者不但不反感广告，反而主动参与调侃。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 评论区互动活跃，其中一条评论点赞数超过正文。

### 案例 2: 吴哥窟女孩用三种语言让游客理解上学诉求
- **问题**: 当地女孩为了让不同国家游客理解自己想上学的诉求，主动学习三种语言。
- **方法论的使用**: 信息有价值还不够，必须用对方能够接收的语言表达。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 跨越语言障碍，使游客能够直接理解其诉求。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **确认用户自有目标**
   - 完成标准: 目标由用户认可，且收益与风险被清楚说明

2. **定位感知断点**
   - 完成标准: 识别用户没看到、没理解、没记住或行动成本过高的环节
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **设计可撤销助推**
   - 完成标准: 使用提醒、默认、反馈或简化步骤，并保留退出和选择权

4. **审计长期后果**
   - 完成标准: 检测误导、依赖、弱势群体伤害和利益冲突，必要时停止

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 利用成瘾、隐瞒代价、制造虚假稀缺，或绕过用户知情同意的增长设计。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 表达围绕自己的兴趣、术语和证明欲，不处理受众的真实问题。 信息未获得注意和理解就无法产生价值，再正确的结论也不会被使用。

### 作者的盲点 / 时代局限

- 何为用户利益存在价值判断；必须让受影响群体参与评估，不能由设计者单方面定义。

### 容易混淆的邻近方法论

- `value-trust-repeat-flywheel` 与 `needs-wants-scene-research`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
