# 正确复述—反馈闭环

## R — 原文 (Reading)

> 尝试着通过反向复述（您的意思是不是“……”）确定提问者的真正问题，而后再认真回答。
>
> — 李笑来，第10、29、34节

---

## I — 方法论骨架 (Interpretation)

反馈闭环的第一步不是解释自己，而是建立共同的问题模型。用自己的话复述对方的事实、担忧、影响和请求，并让对方明确确认或修正。

确认后再回答：能回答的给证据，不能回答的当场记录，不确定的说明核实方式和时间。回应结束后再次请对方指出遗漏，避免“我答了”与“问题解决了”混为一谈。

该方法比泛泛倾听多三个验收点：复述被确认、未答项被记录、后续反馈有时间和责任人。

## A1 — 书中的应用 (Past Application)

### 案例：用 Evernote 随身记录听众反馈

- **问题**：演讲现场的提问、沉默和意外反应容易在会后丢失，讲者也容易把它们解释成听众问题。
- **方法论的使用**：作者持续记录听众提问和反应，把未答和表达缺口带回材料修订。
- **结论**：反馈只有被确认、留痕并进入下一版，才构成闭环。
- **结果**：作者称智能手机与 Evernote 让记录更方便；原文未提供改进率数据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评审或客户只说“不可靠”“不好用”，需要澄清具体风险和请求。
2. 对话张力上升，回答者担心把疑惑误判为质疑或攻击。
3. 当前无法完整回答，需要留痕、核实并按时反馈。

### 语言信号

- “他说不可靠但没说哪里”
- “我怕把疑惑当攻击”
- “先确认他真正问什么”
- “restate and confirm”

### 与相邻 skill 的区分

- 与 `misunderstanding-map-preflight` 的区别：本 Skill处理一次已经发生的反馈；后者在发布前汇总多个样本的误解模式。
- 与 `discussion-goal-routing` 的区别：本 Skill在目标仍是理解时澄清问题；后者先判断互动是在查明事实、争胜、修复关系还是责任升级。

## E — 可执行步骤 (Execution)

1. **暂停自辩并提取四要素**
   - 动作：从对方表述中提取事实、担忧、影响和请求；缺失部分用开放问题补齐。
   - 完成标准：四要素均有原话依据或明确标为未知。

2. **复述并获得确认**
   - 动作：用“我的理解是……我漏了什么”复述，不加入动机推测和反驳。
   - 完成标准：对方明确确认或给出修正；未确认前不进入解决方案。

3. **分类回应与未答项**
   - 动作：将问题分为可立即回答、需证据、需授权、超范围四类，分别答复、记录、升级或拒绝。
   - 完成标准：每项有状态、责任人和所需证据，不确定性被明示。

4. **约定反馈并闭环**
   - 动作：给出反馈时间、渠道和验收问题，回应后再次让对方确认是否覆盖核心担忧。
   - 完成标准：到期完成反馈或提前说明延期；对方确认已答或剩余分歧被准确记录。

### 整体验收与停止

- **完成标准**：问题模型被双方确认，所有未答项有状态与时间，最终答复可追溯且没有把异议抹平。
- **停止条件**：出现辱骂、威胁、操控、法律/安全紧急事项或对方拒绝基本沟通规则时，停止普通闭环并转安全或升级流程。
- **复盘方式**：记录首次复述偏差、遗漏项和反馈是否按时；重复偏差更新提问模板或进入误解地图。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不用确认式复述拖延紧急处置或迫使受害者反复解释伤害。
- 不把对方确认“你听懂了”当作其同意结论。

### 作者在书中警告的失败模式

- 把疑惑当质疑并急于自辩，回答建立在错误问题模型上；未答项也不记录。

### 作者的盲点 / 时代局限

- 原书场景以演讲问答为主，权力不对等、创伤、敌意和合规调查需采用更严格程序。

### 容易混淆的邻近方法论

- 与 `misunderstanding-map-preflight` 的区别：本 Skill处理一次已经发生的反馈；后者在发布前汇总多个样本的误解模式。
- 与 `discussion-goal-routing` 的区别：本 Skill在目标仍是理解时澄清问题；后者先判断互动是在查明事实、争胜、修复关系还是责任升级。
