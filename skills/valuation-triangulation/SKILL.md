# 资产底线与现金流上限的多法估值

## R — 原文 (Reading)

> 不能指望用一个公式、一套算法，就把估值、买入、卖出搞定了。影响估值的因素很多，当我们使用某一套具体的算法时，其实是冻结了一部分变量。越简单的算法冻结的变量越多，它是有很多前提的。
>
> — 姜胡说，第二十章、第二十一章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

先用资产检查下行底线，再用可持续自由现金流估算盈利价值，并用同业倍数作旁证；无法形成区间就停止。

它的独特性在于：不把某个公式当答案，而是强调资产底线、盈利上限、算法适配和停止条件。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

- **结果**: 形成普通人也能操作的企业价值直觉模型。

- **方法论的使用**: 从该真实过程还原输入条件、关键动作与反馈，而不是只摘取结果。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **清洗输入**
   - 完成标准: 统一口径核对资产、负债、自由现金流、股本和异常项目

2. **估资产底线**
   - 完成标准: 按可变现性和负债保守折扣，说明不适用的无形资产
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **估现金流上限**
   - 完成标准: 用情景而非单点增长率计算，并做折现率/增长敏感性

4. **三角校验**
   - 完成标准: 与可比、历史或替代成本对照，输出区间、分歧来源和推翻条件

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 业务与数据尚未看懂、高度早期且无可解释现金流，或要求一个确定目标价。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 依据利润增长判断企业赚钱，不检查收入是否收现和维持经营所需支出。 应收、存货和会计确认可美化利润，企业却可能没有可支配现金甚至持续融资。

### 作者的盲点 / 时代局限

- 所有估值模型都会放大输入假设；区间不是保证，更不是买卖建议。

### 容易混淆的邻近方法论

- `risk-budgeted-asset-allocation` 与 `investment-decision-firewall`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
