# 结论先行金字塔汇报

## R — 原文 (Reading)

> 清晰的顺序，就是先提出总结性思想，再提出被总结的具体思想。先总结后具体的表达顺序，你必须牢记。
>
> — 芭芭拉·明托，《金字塔原理》第1章

## I — 方法论骨架 (Interpretation)

这个 skill 把“我有很多材料”改成“读者先得到一个可判断的答案”。
金字塔汇报不是把摘要放到开头，而是先确认读者真正需要回答的问题，再把顶端结论放在第一屏。
顶端结论下面只放少数关键句要点，每个要点都必须同类、能支撑上层，并能继续展开证据。
表达顺序服务读者理解，不必复制作者思考过程。
如果还没有结论，就不要硬写结论先行；应先自下而上整理材料或补证据。

## A1 — 书中的应用 (Past Application)

### 案例 1: 会议改期电话信息
- **问题**: 原信息按来电顺序罗列人员冲突和会议室情况，读者要自己推断请求。
- **方法论的使用**: 明托把请求放在开头：“今天的会议可以改在星期四上午11点开吗？”后面再给人员和会议室理由。
- **结论**: 先给行动建议，再列支持条件。
- **结果**: 简单事务通知也能降低读者推理负担。

### 案例 2: 饮料公司大客户记账建议
- **问题**: 财务主管原备忘录只描述发现，没有回答管理者关心的“建议是否可行”。
- **方法论的使用**: 先写答案“可行”，再用信息充分、现金流增加、工作量减少三个同类理由支撑。
- **结论**: 自上而下构思能防止文章只回答问题的一部分。
- **结果**: 备忘录从材料说明变成管理决策建议。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 要给老板、客户、团队写 1 页汇报、邮件、请示、周报或项目说明。
2. 材料已经有了，但开头像流水账，读者会问“所以你要我判断什么”。
3. 汇报时间很短，需要在 30 秒到 2 分钟内先交代判断。
4. 用户要求“帮我改得更有逻辑”“先说重点”“提炼 executive summary”。

### 语言信号

- “帮我把这段汇报改成先说结论”
- “老板只给我两分钟，我该怎么讲”
- “这堆材料怎么组织成报告”
- “top line / executive summary / so what”

### 与相邻 skill 的区分

- 与 `scqa-reader-question-introduction` 的区别: 本 skill 重写全文或汇报的顶端答案和支撑结构；SCQA 只处理开头如何引出读者问题。
- 与 `horizontal-grouping-logic-check` 的区别: 本 skill 先确定顶层结论；横向检查用于审查同一层要点是否同类、有序。
- 与 `problem-definition-r1-r2-diagnostic-tree` 的区别: 本 skill 解决表达结构；R1/R2 skill 先界定问题和诊断路径。
- 与 `pyramid-slide-one-point-check` 的区别: 本 skill 面向整份汇报或邮件；单页检查只处理一页 PPT 或一张图表。

## E — 可执行步骤 (Execution)

1. **定位读者问题**
   - 写出读者是谁、他现在必须判断什么、他最可能问“为什么/如何/凭什么”中的哪一个。
   - 完成标准: 形成一句明确的问题句，如“是否应该延期上线”。
   - 判停条件: 如果问题句写不出来，转用 SCQA 或 R1/R2 先界定问题。

2. **写顶端结论**
   - 用一句完整判断直接回答读者问题，包含建议、结论或请求。
   - 完成标准: 读者只看第一句话就知道你要他同意、批准、警惕或采取什么行动。
   - 判停条件: 如果没有证据支撑结论，标注“暂定结论”，先补证据，不要伪装确定。

3. **组织关键句要点**
   - 只保留 2-4 个一级要点；每个要点都必须同类，并能回答顶端结论引发的疑问。
   - 完成标准: 每个要点都能用“因为/具体做法/证据是”连接到顶端结论。

4. **展开证据并检查金字塔**
   - 每个一级要点下放事实、案例、数据或行动；逐层检查“上层概括下层、同组同类、逻辑递进”。
   - 完成标准: 没有游离材料，标题不再是“几个问题/若干建议”这种空壳。

5. **输出可交付版本**
   - 产出“结论句 + 关键句要点 + 必要证据 + 请求/下一步”。
   - 完成标准: 一个没看过原材料的人能在 1 分钟内复述结论和主要理由。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户还在开放探索、收集材料或头脑风暴，不能强行提前确定答案。
- 目标是叙事、小说、品牌情绪传播或保留悬念，而不是让读者迅速判断。
- 用户只要求查事实、翻译、润色措辞，不涉及结构重建。

### 作者在书中警告的失败模式

- 未组织信息，让读者自己拼答案。
- 异类事项硬凑成一组，上层概括只能变得空泛。
- 幻想一坐下就能写出金字塔，把模板当成思考替代品。

### 作者的盲点 / 时代局限

- 该方法来自咨询报告和传统商业写作，对短视频、社交传播和互动式产品文案需要改造。
- 它能让已有思想变清晰，但不能自动产生正确洞察；错误结论被结构化后会更有说服力。

### 复盘方式

- 找一个真实读者只看开头，让他复述“你要我判断什么”；复述偏差即为顶端结论失败。
- 检查每个一级要点是否同类、有顺序、能支撑顶端结论；不能支撑的删掉或移到附录。
