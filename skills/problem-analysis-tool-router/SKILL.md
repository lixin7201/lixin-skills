## I — 方法论骨架 (Interpretation)

问题分析最大的风险不是不会用工具，而是把所有问题都塞进最熟悉的工具。这个 skill 是入口路由器：先判断问题类型，再选择一个主方法，最后设定证据门和下一步交接。

事实到行动的问题适合空雨伞；复杂议题拆解适合逻辑树或假设树；现状与目标差距适合差距分析；流程瓶颈适合流程图；反复异常和根因适合鱼骨图；任务不清适合 5W2H；复盘和教练问题可考虑 ORID/GROW。

第十四批资料把问题扩大到“模型大全”和“100个工具”场景：P1/P2/P3、战略组织、营销服务、人资、质量生产、财务管理、项目物流、决策思维等目录都能提供工具名，但目录本身不等于方法选择。路由时先判问题域，再只选一个主模型和一个可选校验模型；证据不足时先列证据门，不把工具堆成报告。

第十五批根因工具资料补上一个更硬的入口门：如果问题还没有写成“现状、目标/标准、差距、对象、范围、证据来源”，就不要进入 5Why、鱼骨图或 8D。5Why 适合深挖单条或多条因果链；鱼骨图适合团队展开候选原因并验证主要因；8D/PDCA 适合已经需要临时遏制、永久纠正和防再发的稳定流程问题；麦肯锡七步适合复杂议题的假设和逻辑树迭代。

它的产出不是完整分析报告，而是“该先用哪个方法、为什么不用其他方法、下一步产出是什么”。

## A1 — 书中的应用 (Past Application)

### 案例 1: 多模型问题分析工具箱

- **问题**: PPT 同时列出空雨伞、战略树、议题树、目标多杈树、七步法、差距分析、ORID/GROW、鱼骨图和 5M1E，容易导致初学者混用。
- **方法论的使用**: 将每个工具按问题意图分类，而不是按模型名称逐个套用。
- **结论**: 先判定问题类型，再调用对应方法。
- **结果**: 避免用鱼骨图解决目标不清，用逻辑树解决流程瓶颈，或用 5W2H 冒充根因分析。

### 案例 2: 100 个工具带来的选择负担

- **问题**: 《100个思维工具详解》把工具分为战略组织、营销服务、人资、质量生产、财务管理、项目物流、决策思维等篇章，用户容易提出“把 100 个模型都用上”的宽泛请求。
- **方法论的使用**: 先把真实任务归入一个主域，例如战略判断、根因分析、流程改善、项目分工、个人选择或风险决策，再选择一个主模型。
- **结论**: 工具大全只能做 catalog，不能替代问题定义、证据检查和专业边界判断。
- **结果**: 输出“首选工具 + 证据缺口 + 不选哪些工具”的路由结论，而不是 100 个工具列表。

### 案例 3: 根因工具混用

- **问题**: 第十五批旧 PPT 同时出现 5Why、鱼骨图、WHY-WHY、8D、碎石法和麦肯锡七步，容易把“问为什么”“画鱼骨”“写 8D 报告”混成同一件事。
- **方法论的使用**: 先判断问题是否已经完成差距式陈述，再区分是因果链深挖、团队候选原因展开、永久纠正闭环，还是复杂议题假设验证。
- **结论**: 根因工具不是按名字选择，而是按当前卡在哪个环节选择。
- **结果**: 未界定问题先转 R1/R2；反复异常转鱼骨/5Why；已经止血但复发转 8D/PDCA；多分支经营议题转假设逻辑树。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户说“问题很多”，但不确定要先拆原因、拆流程、拆目标还是拆行动。
2. 用户手里有一堆模型名，想知道当前场景先用哪个。
3. 用户的问题横跨工作执行、创业增长、学习复盘或个人行为，需要先分诊。
4. 用户已经开始分析，但模型和问题类型不匹配。
5. 用户要求“用 100 个思维模型/管理工具分析”，但没有给出具体问题域、证据和停止边界。
6. 用户把 5Why、鱼骨图、8D、碎石法、麦肯锡七步混在一起，不知道先用哪个。

### 语言信号

- “这个问题该用什么模型？”
- “帮我选一个分析方法”
- “逻辑树、鱼骨图、5W2H 哪个适合？”
- “problem-solving method / tool router”
- “100 个思维模型该怎么选？”
- “tool/model router / management tools”
- “5Why、鱼骨图、8D、碎石法、麦肯锡七步哪个先用？”

### 与相邻 skill 的区分

- 与 `issue-hypothesis-logic-tree-loop` 的区别: 本 skill 决定是否该用逻辑树；逻辑树 skill 负责具体拆解和验证。
- 与 `fishbone-major-cause-verification-workshop` 的区别: 本 skill 先判断是否真是根因问题；鱼骨 skill 负责团队根因会。
- 与 `problem-definition-r1-r2-diagnostic-tree` 的区别: 本 skill 负责选择工具；如果问题陈述还夹带原因、方案或主观词，先转问题定义 skill。
- 与 `strategy-model-evidence-gate-router` 的区别: 本 skill 先判断是不是战略/市场/产品组合问题；一旦进入战略模型选择和战略证据门，转战略路由 skill。
- 与 `skill-router` 的区别: `skill-router` 选择本机已安装的 Skill；本 skill 选择现实问题可用的思维/管理模型。

## E — 可执行步骤 (Execution)

1. **定义问题意图**
   - 完成标准: 将用户问题归入一个主类型: 事实到行动、战略定位、议题拆解、目标分解、差距、流程瓶颈、根因、任务澄清、复盘/教练、项目分工、风险决策、个人行动。
   - 判停条件: 用户只是问“本机该用哪个 Skill/角色”，转 `skill-router`；用户只是问概念定义，先回答定义或查术语。

2. **检查差距式问题陈述**
   - 完成标准: 问题至少包含对象、范围、当前状态、目标/标准、差距和证据来源。
   - 判停条件: 如果问题陈述里已经夹带原因、解决方案、人格判断或主观词，先转 `problem-definition-r1-r2-diagnostic-tree`。

3. **识别问题域和证据门**
   - 完成标准: 归入学习/工作/创业/写作/决策/个人行为中的一个主域，并列出至少 2 个使用工具前必须知道的事实。
   - 判停条件: 如果事实完全为空，只输出最小澄清问题和可选起步模板，不运行模型。

4. **选择一个主方法**
   - 完成标准: 给出一个首选方法和一句选择理由；若只能二选一，说明判据。
   - 约束: 只允许一个主模型和一个可选校验模型；不得把模型大全当作报告结构。5Why 用于因果链深挖，鱼骨图用于候选原因展开，8D/PDCA 用于纠正和防再发，麦肯锡七步用于假设逻辑树。

5. **排除误用方法**
   - 完成标准: 至少列出 1 个看似相关但暂不该用的方法，以及不用的原因。

6. **设置证据门和停止条件**
   - 完成标准: 说明使用该方法前必须补齐的事实、数据、观察或角色输入。
   - 判停条件: 高风险法律、医疗、投资、心理危机、劳动合规、数据隐私、财务审计或安全事故场景，停止模型路由，只给取证清单和专业流程建议。

7. **交接到下游 skill 或动作**
   - 完成标准: 给出下一步调用的 skill 或一页纸分析产物格式。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户已经明确指定要运行某个 skill 或方法。
- 用户要的是“本地有哪些 Skill/我该调用哪个 Skill”，应先用 `skill-router`。
- 用户只问某个模型定义，不需要分析任务。
- 问题缺少任何事实描述，先要求补充背景。
- 高风险专业建议场景不能通过通用模型路由解决。
- 战略模型之间的选择已经明确属于 PEST/SWOT/五力/BCG/GE/安索夫/价值链，应转 `strategy-model-evidence-gate-router`。

### 作者在书中警告的失败模式

- 只会模型名，不看问题类型。
- 把非根因问题强行做鱼骨图，把事实行动问题强行做复杂树。
- 把“100 个工具”当成逐项套用清单，导致分析很长但没有决策。
- 问题尚未定义就开始问 5 个为什么，导致每层原因都建立在错误入口上。
- 把临时止血当作 8D 完成，忽略永久纠正和防再发。

### 作者的盲点 / 时代局限

- PPT 主要是模型总览，案例深度不足；路由结论必须保持可撤回，后续分析中发现问题类型变化要重新路由。
- 《100个思维工具详解》包含大量二手案例和高专业度工具，人资、财务、合规、安全等场景不能由通用工具书直接输出结论。

### 容易混淆的邻近方法论

- `sky-rain-umbrella-action-chain`: 用于事实-解释-行动链，不负责选择工具。
- `problem-definition-r1-r2-diagnostic-tree`: 用于现状/理想差距定义，不覆盖所有问题类型。
- `fishbone-major-cause-verification-workshop`: 用于已确认要做根因会和主要因验证的场景。
- `firefighting-to-standard-improvement-loop`: 用于已有临时措施后，要做永久纠正、标准化和复发监测的场景。
- `strategy-model-evidence-gate-router`: 用于战略/市场/产品组合模型选择，不负责所有现实问题分诊。
- `skill-router`: 用于本地 Skill 选择，不负责管理工具或思维模型本身的适用判断。
