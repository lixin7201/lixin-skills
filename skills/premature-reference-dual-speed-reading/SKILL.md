# 过早引用双速阅读协议

## R — 原文 (Reading)

> 所以，到了第二遍第三遍就必须施展“只字不差地阅读”这项专门的技能了
>
> — 李笑来，准备、过早引用、BNF与下一步章节

---

## I — 方法论骨架 (Interpretation)

非线性知识不可能总按依赖顺序讲完。初读时追求全部理解，会因过早引用卡死；永远只看大意，则会漏掉否定词、边界和规则，学成自洽的错误版本。

双速协议把两种速度分工：第一遍以脱盲和全局地图为目标，允许未知占位；第二、三遍只对关键定义、规则、符号和边界逐字核对。读者必须自己整理依赖图，并在后续知识出现时修订。

最终通过解释依赖、完成最小实现或测试来验收，而不是以“看完”作为完成。

## A1 — 书中的应用 (Past Application)

### 案例：自制容器概念图后多轮修正

- **问题**：作者粗读 Python 官方材料时跳过 Bytes、遗漏 Frozen Set 并弄反 Ordered 等关系。
- **方法论的使用**：他先容忍粗地图不完整，再阅读语言参考、逐项核对并亲手修订概念图。
- **结论**：粗读负责形成导航，精读和自制地图负责暴露与修正关键错误。
- **结果**：图表经多轮改进更准确，错误本身成为记忆和理解证据。
- **证据位置**：candidates/cases.md c15，过早引用章节

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 技术书或规范前文持续引用后文才定义的概念，第一章就卡住。

## E — 可执行步骤 (Execution)

1. **定义首轮脱盲目标**
   - 动作：写出本轮只需回答的结构、核心对象、依赖和使用场景，设时间盒并允许未知占位。
   - 完成标准：有一页粗目录/问题清单，未知项被标记而未阻断全局扫描。

2. **标记过早引用与图例**
   - 动作：记录未知术语的首次出现、后续定义位置，以及文档符号、语法和导航规则。
   - 完成标准：关键未知可沿依赖边查找，至少能解码一条正式定义。

3. **关键定义逐字精读**
   - 动作：对会改变实现、安全、判断或边界的条目逐词核对“是什么、不是什么、条件、例外”。
   - 完成标准：每个关键定义有原文定位、自己的准确改写和至少一个反例。

4. **自制地图并实现验证**
   - 动作：亲手画依赖图或清单，用最小实现、测试或口头讲解暴露错误并版本化修订。
   - 完成标准：能解释依赖关系且最小验证通过；未通过项回到对应定义而非重读全书。

### 整体验收与停止

- **完成标准**：粗地图、过早引用表、关键定义卡和至少一次实现/测试证据齐全。
- **停止条件**：材料属于法律合同、安全操作、药物剂量等首轮必须精确的内容时停用粗读；来源不可信或版本不明时先做来源审计。
- **复盘方式**：比较初始地图与最终地图，记录漏掉的否定词、边界和依赖；把高频错误加入下一份材料的精读触发清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 法律合同、安全规程、药物剂量、不可逆操作不能首轮“合理忽略”关键细节。
- 不把多轮阅读变成无限准备；必须进入解释、实现或测试。

### 作者在书中警告的失败模式

- 第一遍试图全部搞懂而放弃，或始终像读小说一样粗看，再用别人整理的图替代自己的纠错过程。

### 作者的盲点 / 时代局限

- 书中以编程为主要载体，不是所有技能的最佳入口；工具版本、代码版式和图片必须回到当前官方文档或视觉源核验。

### 容易混淆的邻近方法论

- 与 `decentralized-teacher-source-ladder` 的区别：本 Skill处理一份非线性材料怎么读；后者处理没有单一老师时如何升级来源、求助和裁决冲突。
- 与 `evergreen-content-fertility-filter` 的区别：本 Skill提高理解准确性；后者决定内容是否值得长期读写与产出。
