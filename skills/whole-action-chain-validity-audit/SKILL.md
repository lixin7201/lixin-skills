# 完整动作链有效性审计

## R — 原文 (Reading)

> 无论什么，要么不做，只要决定做，就要做全套。
>
> — 李笑来，第9章 镜像世界另外一侧的众生相

---

## I — 方法论骨架 (Interpretation)

单点正确不等于策略有效。一个结果往往需要识别、进入、执行、监控、退出、交付和复盘等多段动作；任何必要环节缺失，成功都可能只是偶然或不可复现。

先从目标结果反推必要链条，为每段写输入、触发、责任、产出、衔接和失败处理。然后用正常、失败和极端情境走查，确认不是只展示最漂亮的一段。

完整不等于复杂。该方法负责补齐必要环节；非必要判断应由决策节点错误乘数审计删减。

## A1 — 书中的应用 (Past Application)

### 案例：主动基金六十八倍收益仍多次濒临归零

- **问题**：作者管理的早期基金在约五年中实现高倍增长，但过程中多次接近归零，促使他反思主动管理的风险与幸存偏差。
- **方法论的使用**：作者把该经历用于检查收益路径审计、主动管理风险边界，而不是只展示结果。
- **结论**：案例能说明方法如何进入真实行动，但不能从一个成功样本推出普遍因果。
- **结果**：名义结果约68倍，但作者随后转向更重视被动策略；高收益不能抹去期间的毁灭性风险。
- **证据位置**：`candidates/cases.md` c08，第6章（PDF p63—67）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一次成功被用来证明整体方法
2. 商业或投资方案只有进入没有退出交付
3. 跨团队流程在衔接处失效

### 语言信号

- “做对一次算策略有效吗”
- “这套方案是不是少了环节”
- “只讲买入不讲退出”
- “whole action chain”

## E — 可执行步骤 (Execution)

1. **从结果反推链条**
   - 动作：列出识别、进入、执行、监控、交付/退出和复盘等必要环节。
   - 完成标准：每环有输入、产出和必要性理由。

2. **明确触发与衔接**
   - 动作：为每环写触发条件、责任人、时间、下游接收和失败处理。
   - 完成标准：无无主环节或隐含跳跃。

3. **三情境走查**
   - 动作：用正常、失败和极端情境逐段模拟，检查是否只在理想路径成立。
   - 完成标准：每个关键失败都有停止、恢复或升级路径。

4. **复跑并判定整体**
   - 动作：跑一个最小完整周期，区分单点成功与整链可复现。
   - 完成标准：有全链证据和待修环节，不用结果掩盖过程缺口。

### 整体验收与停止

- **完成标准**：必要链条、触发、责任、衔接、失败处理和最小复跑证据齐全。
- **停止条件**：关键环节无合法负责人、失败损失不可控或只能靠隐藏风险才能闭环时停止。
- **复盘方式**：每轮记录断点发生在哪一环，补齐必要环节后再用决策节点审计删冗余。

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- 不要以“做全套”为名增加无价值审批
- 单点探索尚未承诺整体结果时可先用最小实验

### 作者在书中警告的失败模式

- 只展示一次正确买卖或单环节亮点，忽略进入、退出、容量、交付和失败恢复。

### 作者的盲点 / 时代局限

- 原书的“要么不做要么做全套”措辞过绝对；探索阶段允许最小但完整的试验，而非一开始建设全规模系统。

### 容易混淆的邻近方法论

- 与 `decision-node-error-multiplier-audit` 的区别：本 Skill 补齐必要动作和衔接；后者删除或防错非必要决策节点。
- 与 `platform-commerce-closure-audit` 的区别：本 Skill 是跨领域动作链；后者专门审计平台商业交易闭环。
