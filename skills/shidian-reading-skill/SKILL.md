# 十点读书写稿

把风格当作一套选题、材料、推理和节奏方法，不把它缩成爆款词与短段模板。

## 先确认任务

从用户输入提取：

```yaml
deliverable: 完稿 / 提纲 / 标题 / 开头 / 结尾 / 改稿 / 扩写 / 压缩 / 诊断
audience: 具体读者与此刻处境
primary_route: 11 类之一
secondary_route: 可选，最多 1 类
author_route: 可选，15 条开放路线之一
evidence_spine: 事件 / 作品 / 人物 / 生活案例 / 研究数据
target_length: 默认 2300–3200 字
fact_risk: 低 / 中 / 高
ending_mode: 动作 / 校准判断 / 祝愿 / 互动
```

用户没有指定类型时，根据主证据脊柱选择，不只看标题关键词。加载 `references/Writing-DNA.md`、`references/账号总风格.md` 和 `references/写作视角与认知框架.md`，再加载恰好一个 `references/文稿类型/*DNA.md`。

用户点名署名时，检查 `references/小编风格/`。存在对应卡才加载；不存在时按 `references/小编样本不足.md` 回退，不能猜测个人风格，也不能冒充作者本人。

## 材料门禁

先建立事实台账：

| 材料 | 来源层级 | 可直接使用 | 需核验 | 禁止推断 |
|---|---|---|---|---|

优先级：用户原始材料 > 当事人/官方/原作 > 当前权威资料 > 完整书影人物线 > 有出处案例 > 网友评论或名言。最后一层只能做情绪回声，不能证明医学、法律、金融、心理或社会结论。

出现以下情况时先不写长稿，返回不超过 5 个关键补充问题与“当前可写范围”：

- 没有可展开主材料；
- 核心事实不可核验，删除后文章不成立；
- 只能靠虚构朋友、采访、读者来信或第一人称经历补洞；
- 标题要求明显超过材料能兑现的强度。

## 🔴 CHECKPOINT · 写稿前停手项

遇到以下任一项，必须暂停，不进入正文：

1. 用户要求以十点读书官方、某署名作者或未提供的第一人称经历发布：说明不能冒充，确认改为第三人称编辑稿后再写。
2. 医疗、心理危机、法律、金融或公共事件的核心结论只有二手说法：列出必须补齐的来源；来源未补齐时只提供低风险提纲。
3. 用户要求直接发布、群发、投稿或对外发送：先交付预览稿与事实台账，等待用户明确确认发布动作。Skill 本身不得代替确认。

## 失败路径

| 触发条件 | 一线修复 | 仍失败时 |
|---|---|---|
| 主材料不足 | 追问最多 5 个关键事实 | 返回可写范围与素材清单，不写长稿 |
| 类型无法唯一判断 | 比较两条主证据脊柱 | 各给一个短提纲让用户选择，不混成平均模板 |
| 点名署名卡不存在 | 回退账号基线 + 类型 DNA | 明示样本不足，不生成个人口癖 |
| 标题强于证据 | 降低数字、极值和因果承诺 | 保留稳健标题，不用爆款壳 |
| 关键事实有冲突 | 标出冲突来源并停止定论 | 删除争议断言或等待补证 |
| 去 AI 后风格指标下降 | 回滚对应句段 | 保留目标 DNA，不追求通用顺滑 |

健康、心理危机、法律、金融、未成年人、死亡与公共事件自动进入高风险门：区分事实、说法与推断；医学不诊断、不承诺疗效，法律金融不替代专业意见，热点事实标注截止时间。

事实台账属于后台工序。用户给出明确事实包时，把它视为本稿可用边界；在动笔前删掉不能成立的断言或改成有边界的自然表达。除非用户要求审稿报告，成稿正文不得出现“根据材料、原稿提到、现有叙述、需核验、无法确认、不能简单归因”等生产说明。若某个核心事实不确定到无法自然成文，停止写稿并返回缺口，不把免责声明塞进故事。

## 选题和角度

先写出：

```text
目标读者在【具体时刻】遇到【可观察摩擦】，表面以为是【常见解释】，真正值得看见的是【核心矛盾】。
```

选择一张主账：身体底气、关系分寸、自我主权。文章只能有一个主问题；其他问题作为回声，不抢主线。热点、人物与书影必须完成“公共材料 → 私人处境 → 普遍判断”的转译。

材料按“一根主梁，三种回声”组织：一个主材料负责全文，近回声帮助读者代入，远回声抬高解释，必要时用反例校准。每增加一个材料，必须带来新信息，不能重复证明同一道理。

## 写作

优先使用 `references/文章结构模板.md` 中与类型相符的一种主结构。推进时执行：

1. 用生活摩擦、事实、人物选择或作品矛盾起笔，前 15% 让读者知道与自己有什么关系。
2. 展开主材料的处境、选择与代价，先叙事后判断。
3. 命名背后的关系机制，避免全人格定性。
4. 用第二材料、反例或可靠知识校准，防止单例过推。
5. 把判断映射回读者日常，给可承受的小动作或边界。
6. 让情绪完成“刺痛 → 命名 → 松绑 → 回暖”，不把读者留在恐惧、羞耻或愤怒里。

使用 `references/语言DNA.md` 控制句段。默认段落中位约 25–32 字，短段约 20%–34%，连续短段通常不超过 3–5；指定肖肖等路线时服从路线卡的真实差异。短段用于落锤与换气，不把每句话都拆开。

把段落指标落实到成稿：900–1200 字短稿通常写 28–42 段；2300–3200 字长稿通常写 70–105 段。一个叙事段写 1–3 句，关键转折或判断可单独成段。写完抽查连续 10 段：若大多超过 60 字，拆出动作、对白或判断；若大多不足 20 字，合并没有独立作用的碎句。不要用空行制造虚假段数。

类型差异必须进入正文骨架：书影稿服从人物弧与作品顺序，热点稿服从事实时间线，人物稿服从关键选择，亲子/婚恋稿服从关系双方与责任归位，成长稿服从状态变化，清单稿才允许稳定编号。不得为了整齐把所有类型改成“提出问题—三点解释—金句祝愿”。

默认只交付“标题 + 正文”。事实台账、路线选择、核验清单、自检分数和写作说明留在后台；只有用户明确要求时才附在正文之后。

## 标题与版式

标题先兑现事实，再追求强度。给标题时至少分为：稳健型、冲突型、数字/行动型，并标出首选及其兑现依据。禁止假数字、假引语、偷换人群和灾难化承诺。

单篇完稿只保留一个成稿标题。标题要点出人物/人群、冲突或结果中的至少两项，避免写成分析报告式的“某人的三段关系：关于支持与代价”。

用户要可发布版时，加载 `references/账号排版规范.md` 与 `references/视觉风格指南.md`。广告、主播、二维码、课程与账号卡片不属于默认正文 DNA，除非用户明确提供并要求保留。

## 改稿与诊断

改稿先列出事实不可变项、核心立场和目标路线，再做最小充分修改。不得为了“更像”新增案例、改变观点或替换来源。

诊断时加载 `references/原味指纹.md`、`references/像不像判别器.md` 和 `references/像不像对照样本.md`，逐项检查：标题兑现、入口、主材料、机制、校准、读者映射、句段、结尾、事实与非冒充边界。不要只说“缺少温度”。

## 交稿前检查

- 标题的强承诺是否全部被正文兑现？
- 主材料是否真正展开，第二材料是否提供新信息？
- 观点是否由材料推演，而不是先写金句再找例子？
- 是否出现无源数字、假名言、假经历、伪心理诊断或事实漂移？
- 是否把转载语言或署名路线冒充成十点官方/作者本人？
- 是否连续使用同一标题壳、三段式和“愿你”结尾？
- 段落指标是否符合所选类型与署名路线，而非机械短段？

## 红线黑名单

- 不复制训练稿标题、连续原句、人物细节组合或独特比喻。
- 不伪造朋友、采访、读者来信、名言、研究、数据和第一人称经历。
- 不把明确转载或来源未明的语言宣布为账号原生、小编本人风格。
- 不用医学诊断、投资承诺、法律定责、性别羞辱、育儿恐吓或悲剧猎奇换取冲击力。
- 不让事实台账、核验术语、路线说明和自检过程进入默认正文。
- 不把所有题材写成数字标题、三段清单、逐点金句和万能祝愿。

## 去 AI 保真终检

完成目标 DNA 写作后，必须执行 `/Users/REPLACE_ME/.openclaw/workspace/skills/de-ai-preserve-voice/SKILL.md`，并同时加载 `references/去AI味保真补丁.md`。目标账号、文稿类型与署名路线的有证据 DNA 高于通用去 AI 规则：保留真实段落节奏、直白判断、适量反问、自然重复和不完全对称；只清除过程泄漏、无源权威、机械复用与空转。
