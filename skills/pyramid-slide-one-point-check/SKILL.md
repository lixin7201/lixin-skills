# 单页单论点演示检查

## R — 原文 (Reading)

> 每次只演示和说明一个论点。论点应使用完整的陈述句，而不是标题性语言。
>
> — 芭芭拉·明托，《金字塔原理》第11章

## I — 方法论骨架 (Interpretation)

PPT 页面不是资料容器，而是一次只传递一个完整判断的视觉证据单元。
页面标题应回答“这页想让听众相信什么”，而不是只写主题词。
图表页尤其要先确定图表回答的问题，再把答案写成标题，图表本身只负责支撑这个答案。
一页如果说不清一个思想，就拆成多页；一页如果塞了多个互不相关论点，就会让听众自己找重点。

## A1 — 书中的应用 (Past Application)

### 案例 1: 文字幻灯片标题
- **问题**: “销售前景”这种标题只是主题，听众不知道作者判断。
- **方法论的使用**: 明托示范用“销售前景看好”这类完整陈述句替代标题性语言。
- **结论**: 页面标题要传递论点，而不是标注内容类别。
- **结果**: 听众在进入细节前就知道这页要说明什么。

### 案例 2: 图表标题
- **问题**: “各地区利润份额”只告诉读者图表主题，观众需要自己找结论。
- **方法论的使用**: 明托要求确定图表要回答的问题，把答案作为标题，例如“西部地区约占利润的一半”。
- **结论**: 图表标题应直接传递信息，减少不同观众的误读。
- **结果**: 注意力集中到作者希望强调的数据方面。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户上传或描述一页 PPT，想知道标题、图表和正文是否清楚。
2. 页面标题是“收入趋势”“用户分析”“问题与建议”等主题词。
3. 一页同时放多个判断、多个图表或多个行动，听众需要自己找重点。
4. 用户要求“帮我把图表标题写成结论”“这页 PPT 怎么改更像咨询报告”。

### 语言信号

- “这页 PPT 标题怎么写”
- “图表标题能不能更有观点”
- “一页是不是信息太多”
- “one point per slide / chart title / slide title”

### 与相邻 skill 的区分

- 与 `conclusion-first-pyramid-report` 的区别: 本 skill 只检查单页或单图；结论先行处理整份汇报。
- 与 `horizontal-grouping-logic-check` 的区别: 本 skill 先要求一页一个完整论点；页内多个支撑点再用横向检查。
- 与 `scqa-reader-question-introduction` 的区别: 本 skill 检查页面表达；SCQA 检查报告开头。

## E — 可执行步骤 (Execution)

1. **提取页面主张**
   - 用一句话回答“这页希望听众相信什么”。
   - 完成标准: 句子包含判断或发现，不只是主题名词。
   - 判停条件: 如果一页有两个以上主张，拆页或选主张。

2. **重写标题为完整论点**
   - 把标题改成完整陈述句或含动词的短语。
   - 完成标准: 听众只看标题就知道作者结论。

3. **检查证据匹配**
   - 图表、文字、数字只保留能支撑该论点的内容。
   - 完成标准: 页内每个元素都能回答“它如何支撑标题”。
   - 判停条件: 证据不能支撑标题时，先改标题或换证据。

4. **控制复杂度**
   - 文字页控制在少数关键句；复杂图表只保留必要视觉关系。
   - 完成标准: 页面不依赖演讲者解释才能看出主要信息。

5. **输出改页建议**
   - 给出新标题、应保留内容、应删除内容、是否拆页、讲述顺序。
   - 完成标准: 页面成为“一个论点 + 支撑证据”的单元。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户需要改整份报告结构，而不是单页或单图。
- 页面是附录、数据表、工作底稿，目标是供人查阅而非演示传递一个论点。
- 图表本身数据有误或口径不清，应先做数据验证。

### 作者在书中警告的失败模式

- 一页塞多个论点，听众无法判断重点。
- 图表标题只写主题词，迫使观众自己找结论。
- 用复杂或看不清的页面逃避说明复杂性。

### 作者的盲点 / 时代局限

- 原书主要针对传统现场演示；现代交互式仪表盘、长截图和协作文档需要区分“演示页”和“探索页”。
- 单页清晰不能替代整份汇报的正确结构和证据质量。

### 复盘方式

- 遮住正文只看标题，让他人说出这页结论；说不出就重写标题。
- 遮住标题只看图表，检查观众是否会得出同一结论；分歧大说明证据或标题不匹配。
