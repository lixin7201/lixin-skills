# 自我管理方法路由器

## R — 原文 (Reading)

> GTD时间管理核心步骤: 收集、处理、组织、回顾、执行。
>
> — 《分章节P2-07 自我管理》Slide 12, lines 151-174

> 情绪反应并不是直接由外部事件引起的，而是由个体对事件的认知评价和信念所决定。
>
> — 《分章节P2-07 自我管理》Slide 15, lines 227-230

## I — 方法论骨架 (Interpretation)

“自我管理差”通常不是一个问题，而是一组不同问题的混合标签。清单乱、拖延、目标含糊、专注差、学习不能迁移、情绪解释卡住、长期项目没复利，分别需要不同方法。

这个 skill 是分诊入口。它先把症状归类，再把用户转到最合适的下游方法：清单和下一步行动转 GTD；注意力断裂转专注-休息循环；目标不清转 SMART/OKR；学习不会用转 RIA/费曼；情绪解释转 ABC 且先排除真实风险；长期积累转飞轮；新项目不确定转立项可行性。

它不重复安装单模型，而是防止用户用一个模型解决所有自我管理问题。

## A1 — 书中的应用 (Past Application)

### 案例 1: GTD 管理任务

- **问题**: 待办和信息堆在脑子里，执行混乱。
- **方法论的使用**: PPT 要求收集、处理、组织、回顾、执行，把任务从大脑移出并分类。
- **结论**: 清单混乱先做外部化和下一步动作。
- **结果**: 任务管理问题不被误判为意志力问题。

### 案例 2: 费曼学习法

- **问题**: 学了知识但理解不深、不能应用。
- **方法论的使用**: PPT 要求明确主题、语言简化、以教代学、评价反思。
- **结论**: 学习问题要转成讲解、反馈和应用，而不是只增加阅读量。
- **结果**: 学习成效可通过别人是否听懂和自己能否使用来检验。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 用户把多个症状合并成“我自我管理很差”。
2. 用户不知道该用 GTD、番茄、OKR、SMART、费曼、RIA、ABC 还是飞轮。
3. 用户同时有清单、专注、目标、学习、情绪和长期投入问题。
4. 用户正在把组织过载或资源不足归因为个人效率差，需要纠偏。

### 语言信号

- “我自我管理太差了”
- “拖延、清单乱、目标也乱，该从哪开始？”
- “学了很多但没用起来”
- “self-management / productivity router”

### 与相邻 skill 的区分

- 与 `inbox-to-next-action-triage` 的区别: 本 skill 先判断是否是任务清单问题；若是再转 GTD/下一步行动。
- 与 `focus-rest-energy-cycle` 的区别: 本 skill 分流专注问题；该 skill 具体处理注意力与休息节奏。

## E — 可执行步骤 (Execution)

1. **收集症状**
   - 完成标准: 列出用户当前 3-7 个具体表现，不能只写“效率低”。

2. **排除外部和高风险因素**
   - 完成标准: 检查组织资源、照护责任、健康、心理、法律、劳动合规和不可拒绝任务。
   - 判停条件: 出现高风险健康/心理/法律/劳动场景，停止自我管理归因，建议专业支持或制度处理。

3. **分流到问题类型**
   - 完成标准: 标注主要类型: 任务收集、优先级、专注能量、目标对齐、学习迁移、情绪解释、长期复利、项目可行性。

4. **选择下游方法**
   - 完成标准: 只选一个首发方法，并说明为什么其他方法暂缓。

5. **定义最小动作**
   - 完成标准: 给出今天或本周可完成的一个最小动作、完成标准和停止条件。

6. **复盘路由**
   - 完成标准: 一周后检查症状是否变化；若主问题变化，重新路由。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户已经明确要求运行某个单一 skill 或方法。
- 问题根源是工作量不合理、资源不足、健康风险或不可控照护责任。
- 情绪或心理风险较高，不能用效率模型替代专业支持。

### 作者在书中警告的失败模式

- 把所有问题都塞进时间管理。
- 把学习理解停留在阅读，不进入应用和反馈。
- 把情绪问题直接归因于事件，忽略信念解释，但也不能否认真实风险。

### 作者的盲点 / 时代局限

- PPT 是模型合集，容易诱导“模型越多越好”；正式使用要坚持单一首发方法和可观察复盘。

### 容易混淆的邻近方法论

- 番茄解决短时专注，不解决目标方向。
- OKR 解决目标对齐，不解决任务收集。
- ABC 处理解释信念，不替代现实问题解决。
