# 痛苦清单与防卫子句

## R — 原文 (Reading)

> 我只想知道将来我会死在什么地方，这样我就不去那儿了。
>
> — 姜胡说，第二十二章

---

## I — 方法论骨架 (Interpretation)

这个方法处理的核心不是“知道更多”，而是把一个模糊问题变成可观察、可验证的行动结构。

把历史后果写进痛苦清单，设置时间和情绪检查点，命中条件就延迟发送并进入复核流程。

它的独特性在于：把失败清单转成程序式 guard clause，比普通提醒更具体且能事前判停。

使用时先确认输入和边界，再运行最小步骤；没有证据的地方要标为假设。

输出必须包含下一步、完成标准和停止条件，不能停在口号或概念解释。

## A1 — 书中的应用 (Past Application)

### 案例 1: 拉米特雇人阻断上脸书使效率翻四倍
- **问题**: 拉米特·塞西公开雇用一名监督者，在自己上脸书分心时提醒甚至扇耳光。
- **方法论的使用**: 方法把“不要分心”从意愿改成外部检查点，用即时后果打断自动行为。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 拉米特称工作效率提高到原来的四倍。

### 案例 2: 卡拉奇洗手清单显著降低儿童疾病
- **问题**: 研究者没有依赖抽象卫生教育，而是明确列出六种必须用香皂洗手的场景，并提供香皂，让关键行为在日常环境中可执行、可检查。
- **方法论的使用**: 从该真实过程还原输入条件、关键动作与反馈，而不是只摘取结果。
- **结论**: 该案例为方法提供了真实场景证据，同时保留其条件限制。
- **结果**: 一年后腹泻、肺炎和脓疱疹分别下降52%、48%和35%。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **记录痛苦事件**
   - 完成标准: 写清触发、行为、后果和当时忽略的信号

2. **提炼可观测条件**
   - 完成标准: 把模糊教训改写成行动前能判断的 if 条件
   - 判停条件: 若关键输入无法取得或风险超过授权范围，停止推进并转为补证/求助。

3. **绑定拦截动作**
   - 完成标准: 命中条件即暂停、复核、降级或寻求第二人确认

4. **复盘误报漏报**
   - 完成标准: 真实运行后修改规则；保留版本和例外理由

### 整体验收与停止

- **完成标准**: 四步均有可检查产物；事实、假设与建议分开；用户能直接执行下一步。
- **停止条件**: 输入不足、越过专业/安全/资金授权边界、用户拒绝关键验证，或继续行动将不可逆时，停止并明确缺口。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 首次出现且原因未知的问题、需要开放探索的创作，或规则会阻断紧急救援。
- 只有主题词相似、但没有 A2 所列任务与触发信号时，不要激活。

### 作者在书中警告的失败模式

- 把错误归咎于偶然或外部，未识别反复造成损失的个人缺陷。 缺陷没有被命名和设置检查点，就会在相似触发条件下自动重演。

### 作者的盲点 / 时代局限

- 过去的教训可能过拟合旧环境；防卫子句必须可撤销并定期清理。

### 容易混淆的邻近方法论

- `thought-observer-pause` 与 `investment-decision-firewall`：先比较目标产物、输入证据和停止条件，再决定调用哪个。
